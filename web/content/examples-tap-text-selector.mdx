# tap-text-selector

v0.2 closing-checkpoint smoke. Single `app.tap({text: 'General'})` against a pre-launched Settings root. The point: you don't write your own `app.launch` here.

```ts
import { test } from '../src/sdk/index.js'

test('settings: tap General navigates to sub-page', async ({ app }) => {
  // The C2 SmixRunner XCUITest auto-launches com.apple.Preferences before
  // serving requests, so an SDK-side launch would only fight the XCUITest
  // session attachment (fresh:true terminates the app the runner is bound
  // to). C6 keeps the example minimal: tap "General" against the already-
  // running Settings root, verified by the shell wrapper's double-sided
  // probe after this test exits.
  await app.tap({ text: 'General' })
})
```

## Reading guide

**No explicit `app.launch`.** SmixRunner — the XCUITest session bound to the simulator — boots `com.apple.Preferences` before serving requests. If the test wrote `app.launch('com.apple.Preferences', { fresh: true })`, it would *terminate* the Preferences instance the runner is attached to, dropping the test session.

**The smoke shape.** The test exits as soon as the tap returns; the shell wrapper (`scripts/smix-c2-...`) does a double-sided probe after the test exits to confirm the sub-page actually rendered. The example is intentionally one line, so any failure points squarely at the tap path.
