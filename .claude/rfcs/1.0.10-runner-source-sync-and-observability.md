## Meta-root-cause (Phase A — CONFIRMED with hard evidence)

`smix-cli` upgrades never reached insight's Swift runner. Their
`~/.local/share/smix/runner/SmixRunnerUITests/SmixRunnerUITests.swift`
is byte-frozen at a pre-v1.0.3 revision — zero references to
`sessionHandlers`, `/session/open`, `/session/list`, `/diagnostic/dump`,
or `SessionHandlers`. Six CLI patch releases (v1.0.4–v1.0.9) shipped
CLI-side observability + wire additions, but the on-disk runner sources
that xcodebuild compiles never changed. Every request that depends on a
route added since v1.0.3 (starting with `/session/open`) hits a
FlyingFox router that has never registered it → deterministic 404 → CLI
falls back to legacy path → clearAppData bails with "no session id".

The chronic 404 across 6 releases is not a route-registration race, not
a session-table init race, not a persistence bug. It is a **distribution
gap**: `cargo install smix` ships only the Rust binary. The Swift runner
project cascade (SMIX_RUNNER_PROJECT env → `~/.local/share/smix/runner/`
→ dev-repo `swift-bridge/`) has no mechanism to keep the installed
sources synced with the installed CLI binary. Consumers acquire runner
sources out-of-band, once, and never again.

Evidence:
```
$ wc -l ~/.local/share/smix/runner/SmixRunnerUITests/SmixRunnerUITests.swift \
        swift-bridge/SmixRunnerUITests/SmixRunnerUITests.swift
    2212 ~/.local/share/smix/runner/…                    # frozen pre-v1.0.3
    2669 swift-bridge/…                                   # v1.0.9 HEAD
$ grep -c 'session/open\|SessionHandlers\|v1\.0\.' \
       ~/.local/share/smix/runner/SmixRunnerUITests/SmixRunnerUITests.swift
0
```

Secondary root cause: `GET /health` route calls `HealthRoute.response()`
(legacy `{"ok":true}` since v0.x) — the `runnerVersion` field CHANGELOG
v1.0.2 claimed is never emitted, so version-mismatch has never been
detectable client-side.

## Charter items

### D1 — Package Swift runner sources with the CLI crate

- New crate `smix-runner-sources` (path-only initially, published to
  crates.io if consumer scenarios need it):
  - `data/swift-runner-sources.tar.gz` — checked-in tarball of
    `swift-bridge/{SmixRunner,SmixRunnerUITests,Sources,Tests,
    Package.swift,project.yml,SmixRunner.xcodeproj/}`
  - EXCLUDES `SmixCoreFFI.xcframework/` (13.3 MB binary) — fetched at
    extract time from a pinned GitHub Release URL, hash-verified
  - `pub const SOURCES_TAR_GZ: &[u8] = include_bytes!("…")`
  - `pub fn extract_to(dst: &Path, force: bool) -> Result<ExtractReport>`
  - `pub const SOURCES_VERSION: &str = env!("CARGO_PKG_VERSION")` —
    bumped in lockstep with workspace version
- Pre-publish hook script `scripts/release/build-runner-tarball.sh`
  regenerates the tarball; refuses to publish if git working tree in
  `swift-bridge/` differs from tarball contents

### D2 — Auto-sync installed runner on `smix runner up`

- Rewrite `installed_runner_project()` cascade:
  1. Read `~/.local/share/smix/runner/.smix-runner-version`
  2. If missing OR ≠ current CLI version → auto-extract
     `smix_runner_sources::SOURCES_TAR_GZ` after backing up existing
     tree to `~/.local/share/smix/runner.bak-<ts>/`
  3. Write `.smix-runner-version` = current CLI version
  4. Emit info banner: `smix-runner: sources synced from CLI (v1.0.X)`
- No user migration needed on upgrade; happy path is transparent
- New CLI verb `smix runner install [--force] [--path <dir>]` for
  advanced users who want to pin

### D3 — Real `/health` responseDetail wiring

- Add `HealthRoute.responseDetail(runnerVersion:uptimeMs:)` returning
  `{"ok":true,"runnerVersion":"1.0.10","uptimeMs":N,"schema":1}`
- Wire runForever to call `responseDetail` with a build-time-generated
  `SmixRunnerVersion.string` constant
- Version constant generated by `smix runner install` / auto-sync via a
  synthesized `Sources/SmixRunnerCore/Generated/SmixRunnerVersion.swift`

### D4 — Client-side version-mismatch gate

- `smix-runner-client`: after `/health` returns 200, parse
  `runnerVersion` field
- If mismatch with CLI version → emit `RunnerVersionMismatch` event on
  liveness channel + return actionable error from `runner up` startup
- Test: mock server returning stale version → client refuses boot with
  actionable message

### D5 — Observability counters (Phase C in insight's ask)

`AppAliveCache` gains counter fields (all `UInt64`):
- `markDeadTotal`, `markAliveTotal`
- `reprobeAttemptedTotal`, `reprobeInvalidatedEarly`, `reprobeExhaustedWindow`, `reprobeSucceeded`
- `hitTotal`, `missTotal` (for isSuppressed lookups)

`sessionHandlers.diagnostic` returns extended DiagnosticSnapshot:
- `aliveCache: AliveCacheCounters`
- `sessions: SessionCounters { openTotal, closeTotal, listTotal, terminateTotal, launchTotal, relaunchTotal }`

Wire schema is `#[non_exhaustive]` + `#[serde(default)]` on every new
field so consumers on older SDKs see zeros not decode errors.

### D6 — Ring buffer persistence

- `subprocess_ring` writes-through to
  `~/Documents/smix-diagnostic-ring.json` on every push (best-effort,
  atomic `.tmp` + rename)
- Piggybacks on the v1.0.5 session-persistence pattern
- Runner cycles no longer wipe post-mortem state

### D7 — Corpus release gate (Phase D in insight's ask)

- Scaffold `scripts/release/corpus-gate.sh`:
  - `SMIX_CORPUS_DIR` env → directory of `.yaml` files
  - Boots configured sim + runs each yaml + refuses ship on any FAIL
- Accept insight corpus PR at
  `crates/smix-cli/tests/fixtures/insight-bootstrap-corpus/` when they
  open it; wire same script
- No ship without corpus green

### D8 — Tests (per user directive: "做好测试")

- `smix-runner-sources` — extract round-trip test (temp dir, verify file
  hashes match)
- `runner.rs` — version-mismatch cascade unit test (mock stale
  `.smix-runner-version` file → asserts auto-extract fires)
- `smix-runner-client` — mock server returning stale runnerVersion →
  asserts client emits RunnerVersionMismatch
- Swift `HealthRoute.responseDetail` — JSON shape test with fixed
  version + uptime
- `AppAliveCache` — counter increments per markDead / re-probe path;
  counter values survive supervisor cycle via ring persistence
- Integration: end-to-end `smix runner up` → asserts installed sources
  match CLI version after first boot on a clean machine
- Manual: run insight's bootstrap corpus locally before shipping

## Sequence

Deliberately in ONE release, no interim ships:

1. D1 + D2 + D8 (source sync + tests) — the meta-root-cause
2. D3 + D4 (version gate wire-in) — user-visible feedback loop
3. D5 + D6 (counters + persistence) — observability closure
4. D7 (corpus gate) — infrastructure debt paid down
5. Manual repro of insight's `bun test:e2e` against v1.0.10 CLI + fresh
   sync → assert `/session/open` returns 200, `clearAppData` succeeds,
   no ReportCrash `.ips`, `re-probe hit` counter increments

Ship only when steps 1–5 all observed on real sim.
