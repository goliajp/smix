# RFC — smix 1.0.6 supervise-sidecar + runner-down cascade + rust 1.97 baseline

Status: DRAFT — planned charter
Date: 2026-07-11
Triggers:
- v1.0.5 shipping doc for insight (`docs/ai-guide/insight-v1.0.5-shipping.md`) — item "Deferred to v1.0.6+" listed sidecar auto-supervise
- rust-version workspace bump to 1.97 (via Cargo.toml modification)
- v1.0.5 shipped D2 supervisor as a standalone verb only — insight-side integration requires them to spawn + tear down the sidecar themselves. Ergonomics improvement is a small, well-scoped charter.

## Framing

v1.0.5 shipped the supervisor daemon (§D2) as a standalone `smix runner supervise` verb. Consumers wanting automatic recovery had to spawn the sidecar themselves and manage its lifecycle. That's an operationally-fine shape but adds boilerplate to every gate driver.

v1.0.6 folds sidecar management into the runner lifecycle so consumers who want automatic recovery just add `--supervise` to their existing `smix runner up` invocation.

## Decisions

### D1 — `smix runner up --supervise` spawns detached supervisor

After `up` succeeds (`/health` returns 200), spawn a detached `smix runner supervise` process. Record its PID in `.smix/runner/state.json` under a new `supervisorPid` field so `runner down` can tear it down.

Behavior:

- `smix runner up sim-insight --bundle com.focusai.app.mobile --supervise` — brings the runner up as before, then spawns supervisor and returns.
- Supervisor inherits stdout/stderr redirected to `.smix/runner/supervise-<UDID>.log`.
- Supervisor runs with its own process group so a `SIGINT` to the CLI doesn't tear it down accidentally.
- If supervisor exit mid-run (5-in-10-min circuit breaker fires, or process killed), `runner down` still works — the missing PID entry is silently ignored.
- Idempotent — if `state.json` already records a running supervisor, don't spawn a duplicate.

### D2 — `smix runner down` cascades supervisor teardown

`smix runner down` currently kills xcodebuild + optionally sweeps unrecorded sessions. v1.0.6 adds a first step: if `state.json` records a supervisorPid + the process still matches (`ps -p` command name check), SIGTERM it, wait 5 s, escalate to SIGKILL if needed.

Rationale: `runner up --supervise` and `runner down` should be a symmetric pair. Users who forget an orphaned supervisor after `runner down` currently keep it running until they realize + kill by hand.

### D3 — rust-version 1.97 baseline

Workspace `rust-version = "1.97"` (already applied via user edit). Enables:

- Stabilized `if let` chains in the 1.97 stable line — clean up a handful of nested `if let Some(x) = ... { if let Some(y) = ... { ... } }` sites in `smix-cli`, `smix-adapter-maestro`, `smix-runner-client`.
- New std::process APIs — none critical, but codegen improvements benefit the release binary.

Not part of D1/D2 code paths, but a workspace hygiene improvement that lands as a companion cleanup pass. Not a breaking change for consumers because published rust-version is a *minimum* — anyone building smix from source still needs 1.97+, anyone consuming via `cargo install` gets a pre-built binary.

### D4 — CHANGELOG discipline: sub-headings by ecosystem impact

Small doc-hygiene change to CHANGELOG format going forward: each version's entries grouped under `### Runner-side (Swift)`, `### CLI (Rust)`, `### SDK — all four`, `### Documentation`, `### Deferred`. Makes it obvious at a glance which surface changed. Retroactive edit of v1.0.4 + v1.0.5 optional; v1.0.6 leads with the new pattern.

## Wire + ABI

- No wire additions.
- No SDK ABI additions.
- CLI additions: `--supervise` flag on `smix runner up`; `state.json` schema extended with optional `supervisorPid: u32`.
- `state.json` reads that predate v1.0.6 (missing `supervisorPid`) continue to work via `#[serde(default)]`.

## Non-goals

- `smix runner supervise` as its own CLI verb stays. v1.0.6 doesn't remove or deprecate it — the sidecar mode is a convenience shortcut, not a replacement.
- Auto-restart of the supervisor itself when it exits from the 5-in-10-min circuit breaker. That would defeat the escalation semantic; the circuit breaker exists precisely so a monitoring layer can take over.
- Sidecar mode for Android runners. Android's UiAutomator runner has a different failure profile; if/when we add supervise for it, that'll be its own decision.

## Rollout

Standard 4-ecosystem publish. Same DAG as v1.0.5. `scripts/release/ship.sh 1.0.6` is now the canonical entry (with smoke gate). If the smoke gate hasn't fired against a real sim yet, first invocation will trigger it — bake that time into the ship timeline.

**Timeline estimate**: 1 day. D1 + D2 are one 200-line change; D3 is opportunistic cleanup; D4 is a CHANGELOG format sync.
