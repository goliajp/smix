### Cluster A — `resetAppData` verb (URL-scheme JS-wipe)

- **New yaml verb** — distinct from `clearAppData` per Q2 answer:
  ```yaml
  - resetAppData:
      via: url-scheme
      url: 'insight://dev-mutate?action=reset'
      waitFor:
        logLinePattern: '\[insight-dev\] reset-complete token=([a-f0-9-]+)'
        timeoutMs: 5000
  - launchApp:
      launchArgs: ['-EXInternalMetroPort', '8081']
      waitForForegroundMs: 15000
  ```
- Insight side sends `mmkv.clearAll()` (synchronous, single-digit ms) then `console.log('[insight-dev] reset-complete token=<uuid>')` — token disambiguates concurrent runs.
- **smix side:** CLI issues `simctl openurl <UDID> <url>`, tails the metro log (Cluster B foundation) for the pattern, returns success on first match or Err on timeout. When `--metro-log` unset, best-effort fire-URL + sleep configurable ms (default 500) — per insight Q1 tail.
- **Wire:** no new HTTP endpoint. Reset is host-side (simctl openurl + metro log tail).
- **SDK:** `App::reset_app_data(url, wait_for: WaitFor, timeout_ms) -> Result<ResetAppDataOutcome>`; `WaitFor::LogLinePattern(regex)` / `WaitFor::Sleep(ms)` / `WaitFor::None`.
- **`Step::ResetAppData { via, url, wait_for, timeout_ms }`** in adapter-maestro; parser accepts short-form (`- resetAppData: 'insight://…'`) and map-form.
- **Counter:** `resetAppDataTotal` in `SessionLifecycleCounters`. `resetAppDataTimedOut` for pattern-miss cases.
- **`clearAppData` kept** per Q3 (a). No rename, no deprecation. Verb-selection-guide RFC (D6) documents when to pick each.

### Cluster B — external metro log gate

- **CLI:** `smix run --metro-log <path>` + `--metro-log-tail-lines <N>` (default 200 per Q6). Path stable/no-rotation per Q5 → O_APPEND + tail-from-EOF, no inotify.
- **Accumulator:** ring buffer (128 or `N`-configurable) in the process. Reads from log file at run start (EOF-first) and every stanza; folds into a shared struct.
- **Diagnostic dump:** `runner.metroLogTail: string[]` in JSON; `smix diagnostic dump` (non-JSON) renders a new "=== metro log tail (last N of M) ===" section.
- **No coupling to Metro internals** — pure file tail; consumer controls the writer.

### Cluster C — `launchAppReachedInteractive` + reason disambiguation

- **Wire (`SessionAppLifecycleRequest` extension):**
  ```rust
  #[serde(default)]
  pub wait_for_interactive_ms: Option<u64>,  // when set, orthogonal to wait_for_foreground_ms
  ```
- **Response (`SessionAppLifecycleResponse` extension):**
  ```rust
  #[serde(default)]
  pub reached_interactive: bool,
  #[serde(default)]
  pub interactive_named_ids: Vec<String>,   // ax-ids observed at fire moment (debug aid)
  ```
- **Runner-side:** after `.runningForeground`, poll `/tree` at 500 ms cadence. Read the response tree, filter descendants for `accessibilityIdentifier` non-empty AND not in ignore-list. Fire when count ≥ `minIdentifierCount`; timeout = `wait_for_interactive_ms`.
- **Config `.smix/config.yaml`** — new schema:
  ```yaml
  interactiveProbe:
    minIdentifierCount: 3
    ignore:
      - SplashScreenLogo
      - com.focusai.app.mobile
  ```
  Bundled defaults ship these two per Q7. Consumer can override; smix reads the file at CLI startup + attaches to the runner via env var (`SMIX_INTERACTIVE_PROBE_JSON`).
- **Counters:** `launchAppReachedInteractive` + `launchAppTimedOutBeforeInteractive` in `SessionLifecycleCounters`.
- **Failure mode:** Q8 answer (a) — `launchApp` returns success even on interactive timeout; counter delta is the signal.
- **`app-unavailable` reason enum:**
  ```rust
  pub enum AppUnavailableReason {
      CrashedDuringInit,
      AliveButTreeEmpty,
      AliveButTreeStale,
      DriverDisconnected,
      Unknown,  // fallback
  }
  ```
  + first-class `hint: String` field on the wire response. Runner-side detection:
    - `crashed-during-init` — `entry.app.state == .notRunning` + `.ips` file appeared within last 30 s (scan `~/Library/Logs/DiagnosticReports/`)
    - `alive-but-tree-empty` — `.state == .runningForeground` + tree probe returns 0 named nodes (not in ignore)
    - `alive-but-tree-stale` — tree content hash matches previous session's snapshot
    - `driver-disconnected` — XCUITest driver query throws / times out
- **Wire change** on `/tree` error envelope: rename `reason: Option<String>` → carry `AppUnavailableReason` + `hint`. Backward-compat: pre-v1.0.14 clients ignore new field, `reason` string still emitted.

### §6 retry-attribution

- **CLI:** `smix run --retry <N>` default 1 (unchanged pre-v1.0.14 behaviour).
- **Runtime:** each flow tracks its attempts as `Vec<AttemptRecord>`:
  ```rust
  pub struct AttemptRecord {
      pub attempt_index: u32,
      pub status: AttemptStatus,       // ok / timeout / error / crashed
      pub error_class: Option<String>, // "TIMEOUT" / "DRIVER_ERROR" / …
      pub ips_generated: Option<String>, // path if new .ips within window
      pub wall_ms: u64,
  }
  ```
- **Diagnostic dump:** `runner.recentFlows: Vec<{flow_name, attempts: [...]}>`.
- **Wire:** no HTTP endpoint change (attribution is CLI-side aggregation).
