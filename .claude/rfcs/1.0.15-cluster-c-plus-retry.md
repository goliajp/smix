### Config file — `.smix/config.yaml`

```yaml
interactiveProbe:
  minIdentifierCount: 3
  ignore:
    - SplashScreenLogo
    - com.focusai.app.mobile
```

Bundled defaults (when file absent): those two ignore entries + minIdentifierCount 3. Per insight Q7 answer.

Consumer overrides via `.smix/config.yaml` at repo root (adjacent to `.smix/sims.json`).

CLI forwards to runner via `TEST_RUNNER_SMIX_INTERACTIVE_PROBE_JSON` env — same TEST_RUNNER_ prefix pattern used for SMIX_RUNNER_VERSION etc. JSON-encoded so Swift can decode without a yaml parser.

### Swift-side runner (SmixRunnerUITests.swift launchApp handler)

After existing `.runningForeground` polling completes (v1.0.11 §D3), if `req.waitForInteractiveMs > 0`:
1. Poll `entry.app.descendants(matching: .any)` at 500 ms cadence.
2. Snapshot descendants; extract `accessibilityIdentifier` for each.
3. Count non-empty ax-ids that are NOT in the ignore-list.
4. If count ≥ minIdentifierCount, set `reachedInteractive = true`, collect up to 8 sample ids into `interactiveNamedIds`, break.
5. On timeout, `reachedInteractive = false`, counter `launchAppTimedOutBeforeInteractive` +1.
6. On success, counter `launchAppReachedInteractive` +1.

`launchApp` returns success in both cases per Q8 answer (a).

### SDK layer

`App::clear_app_data_with_launch` gains a `wait_for_interactive_ms: Option<u64>` parameter (additive). Default via the yaml layer: consumer specifies in `launchApp: { waitForInteractiveMs: 30000 }`; for the internal path inside `clear_app_data_with_launch`, we can default to 30 s if `waitForForegroundMs` was set — conservative but avoids surprise.

### yaml layer

`launchApp: { waitForInteractiveMs: 30000 }` — parses to `LaunchAppOptions.wait_for_interactive_ms: Option<u64>`. `Step::ResetAppData` unaffected.

## D2 — AppUnavailableReason + hint field

### Wire additions

New in `smix-runner-wire`:
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
#[non_exhaustive]
pub enum AppUnavailableReason {
    CrashedDuringInit,
    AliveButTreeEmpty,
    AliveButTreeStale,
    DriverDisconnected,
    Unknown,
}

#[derive(Clone, Debug, Serialize, Deserialize, Default)]
#[serde(rename_all = "camelCase")]
#[non_exhaustive]
pub struct AppUnavailableEnvelope {
    #[serde(default = "unknown_reason")]
    pub reason: AppUnavailableReason,
    #[serde(default)]
    pub hint: String,
    // ... existing "app unavailable" wire shape …
}
```

### Runner-side detection (Swift)

Called from `/tree` handler when the current tree query returns empty / error:

- **`crashed-during-init`** — `entry.app.state == .notRunning` AND we can find a `.ips` file for the bundle-id in `~/Library/Logs/DiagnosticReports/` with mtime within last 30 s. Hint: `"Process exited during initialization — look at ~/Library/Logs/DiagnosticReports/ for the .ips."`
- **`alive-but-tree-empty`** — `.state == .runningForeground` + `entry.app.descendants(matching: .any).count == 0` OR all descendants have empty ax-ids. Hint: `"Process foreground but no named a11y descendants — likely splash-screen ceremony still running, or your app's accessibility tree lacks accessibilityIdentifier coverage."`
- **`alive-but-tree-stale`** — same descendants as previous session's snapshot (hash comparison via `SmixRunnerServer.currentTreeSnapshotHash`). Hint: `"Tree hash matches a previous session — driver may be returning cached content. Try /session/renew-activation."`
- **`driver-disconnected`** — XCUITest query throws / times out inside the trampoline. Hint: `"XCUITest driver query failed — try smix runner cycle."`
- **`unknown`** — fallback for the "we know something's wrong but not why" case.

### /tree wire

Response envelope on failure gains the enum + hint. Backward-compat: pre-v1.0.15 clients get `reason: "unknown"` default (via `#[serde(default)]` with a helper function returning `AppUnavailableReason::Unknown`).

## D3 — `smix run --retry N` + attempt attribution

### CLI

`smix run --retry <N>` — default 1 (unchanged pre-v1.0.15 behaviour). Applies per-flow (not per-step, not per-batch).

### Runtime (smix-adapter-maestro)

The flow runner wraps each flow's step-list execution:
```rust
for attempt in 0..=max_retries {
    match run_flow_once(flow, ctx).await {
        Ok(()) => record_attempt(&flow_name, attempt, Ok(())),
        Err(e) if attempt < max_retries => {
            record_attempt(&flow_name, attempt, Err(e));
            continue;
        }
        Err(e) => {
            record_attempt(&flow_name, attempt, Err(e));
            return Err(e);
        }
    }
}
```

`record_attempt` populates a `FlowAttempt` record + writes to `~/.local/share/smix/flow-attempts.json` (append + prune to last 32 flows).

### .ips attribution

Before each attempt, capture the current `.ips` filename list under `~/Library/Logs/DiagnosticReports/`. After the attempt, diff; any new entries are attributed to that attempt via the `ips_generated` field.

### CLI dump overlay

`smix diagnostic dump` reads `flow-attempts.json` and overlays into `resp.recent_flows` before display / JSON serialization — same pattern as v1.0.14 reset-app-data counter overlay.
