# Quick start

smix is iOS Simulator automation for AI agents. Tests run end-to-end on a real boot of `iOS 26.x` (or `17.x` / `18.x`) inside the host simulator. The SDK is shaped like Playwright so an AI writes correct code on the first try; selectors are semantic only (no xpath, no pixel coords); failures are AI-readable JSON.

smix is designed to be substantially faster than maestro on the same
end-to-end iOS Simulator flows, with zero step failures across repeated
iterations. See the home page for the latest benchmark numbers.

## Install

Two paths. Both end at the same place: a `smix` CLI that can `run` test files, plus 27 MCP tools that Claude Code calls automatically.

### Path A — Claude Code plugin (end users)

Recommended if you just want to author iOS tests via Claude Code.

```bash
claude --plugin-dir /absolute/path/to/smix
# then inside the claude session:
/mcp
# → enumerates the 27 smix tools (lifecycle, observe, interaction, ...)
```

Full step-by-step: [Plugin install](/docs/plugin-install).

### Path B — local dev (contributors)

```bash
git clone https://github.com/goliajp/smix && cd smix
bun install
bun x tsc --noEmit                  # typecheck
bun x vitest run                    # unit tests
```

You also need Xcode 16+ (for the runner UITest target) and an iOS 26.x
simulator booted and available. `smix doctor` reports what's missing.

## Your first test

```typescript
import { test, expect } from 'smix/test'

test('settings search → wifi result', async ({ app }) => {
  await app.launch('com.apple.Preferences', { fresh: true })

  // Path B — non-text selector goes through the cached tree resolver
  await app.tap({ role: 'searchField' })

  // Path A — daemon fast-path typeText
  await app.fill({ text: '_focused_' }, 'Wi-Fi')

  await expect(app.element({ text: /Wi-Fi/ })).toBeVisible()
})
```

Run it:

```bash
bun x smix run path/to/that.test.ts
```

The runner boots an XCUITest target that hosts the smix HTTP server (port
`22087`, bound to `127.0.0.1` only). Your test talks to it over localhost;
tap goes via host-HID at coord; type goes via the XCTest daemon's
`_XCT_sendString` fast path.

## What you get on failure

Every failed matcher throws an `ExpectationFailure` with three things an AI can immediately act on:

- `visibleElements` — a list of summaries of what's actually on screen
- `suggestions` — edit-distance ranked alternatives ("did you mean `Wi-Fi`?")
- `screenshot` — base64 PNG, also written to `.smix/cells/<id>/trace/<case>/failure-NNNN.png`

Paste a failure JSON back to Claude and it self-corrects on the next run. That's the whole point.
