# v2 — 版本边界（当前大版本）

> 本文件是 CLAUDE.md §0 四层文档结构的第 [2] 层：当前大版本要做什么 / 不做什么。
> v2 cycle 的所有非微小决策记入本文件末尾「决策日志」段（§10）。
> 设计详解见 `.claude/design/v2.0/`（gitignored HTML dossier）。

## 一句话

v2.0.0 是 smix 第一个真正对外的正式发布：功能全面超越 maestro，iOS + Android 全 parity 作发布门槛，代码状态达到可对外的最佳水平，并成为 AI app dev/debug 闭环里的确定性执行 + 观测底座。

## 做什么（in scope）

1. **围栏式 AI 断言层** — `assertCondition` / `extractWithAI`：截图 → 本地 `claude` CLI → 结构化 verdict。opt-in、标注非确定性、firewall 在 resolver/sense 路径之外（§9#2 单 provider）。
2. **iOS + Android 全 parity** 作发布门槛 — 每个当前 iOS-only 的 verb 达成 ✅ 或诚实 re-tier（记录理由）。见 `.claude/design/v2.0/architecture.html` §05 门禁表（12 parity + 2 special = 14 行）。
3. **MCP 驱动面成熟** — 6-tool MVP 扩到完整外部 agent 驱动面（fill/swipe/scroll/launch/stop/assert/session/diagnostic-dump）。
4. **确定性** — `--stable`（冻结动画 / 时间 / 抖动）+ 真 animation-idle（frame-diff 取代固定 sleep，闭合 §9#4 最后一处）。
5. **六项破坏性变更** + `smix migrate` codemod（见下）。
6. **代码 & 文档 hygiene** — 注释去开发噪声（26/28 crate + Swift + Kotlin 受影响，~1300+ 处）；五矛盾收敛；宪法 / roadmap 同步。
7. **面向 AI 的文档** — `llms.txt` / `llms-full.txt`（从 VERB_TABLE 生成）+ 真 MCP 设置指南 + 官网 IA。

## 不做什么（out of scope）

- **真机支持** — 永久不做（§9#1）。
- **multi-provider VLM 抽象** — 不做（§9#2）。
- **分布式 run federation / cross-platform recorder / LLM-in-loop authoring** — post-v2，speculative。
- **任何坐标 selector 表面** — `tapAtCoord` 仍是唯一授权的坐标 escape hatch。
- 本 cycle 的设计阶段（`.claude/design/v2.0/` dossier + 本计划文档）**不实施产品代码**;实施从 C1 起。

- 2026-07-17 [C3 撤回·spec F] **不建 OCR 键盘字符 fallback**。dossier 的 spec F 写着「the deferred behind-a-flag item, now shipped」—— **这是对自家源文档的误读**，C3 动手时才发现。源文档（`insight-v1.0-comprehensive.md:85`）原话：「considered … but **not implemented** — **subsumed by §P0-A** and deferred as a v2.x experimental behind `--enable-ocr-fallback` **if a future consumer surfaces a case §P0-A doesn't cover**」。即：(a) 从未实现、从未在 flag 后；(b) 底层问题已被 **§P0-A（:41 标 ✅ SHIPPED）** 解决 —— KeyEventDispatch 经 runner 的 daemon 级 `sendString` 内部等键盘就绪；(c) 重启条件「出现 P0-A 覆盖不到的案例」**从未满足** —— 无任何消费者报告 `inputText` 丢字符（那些 "drop" 报告是 RN→UIAccessibility 桥丢 **a11y identifier**，另一回事）。**且它本身是降级**：OCR 核验打字文本在密码（渲染成圆点）、长文本滚出视野、格式化输入上必然误报失败 —— 拿确定性机制换有已知误判模式的概率机制。**也不是 maestro 缺口**（maestro 同样没有），故不让步任何 parity。教训同 [C2 发现]：**dossier 里「已 defer / 已 flag」这类关于自家历史的断言，必须回源核对**，agent 报告的**否定式事实比肯定式事实可信**。
- 2026-07-17 [C3 拍板·破坏性] `waitForAnimationToEnd` 的**三种形式统一为「等到静止，上限 N ms」**，字段 `duration_ms` → `ceiling_ms`。此前数字形式是**固定 sleep**。理由：verb 的名字就是它的契约 —— 它承诺「等动画结束」，而非「睡 N 毫秒」；到点即返回严格更优（不动的屏幕不再白付 400ms）。**风险已知**：§9#4 禁裸 sleep，所以有人一直**拿这个 verb 当 sleep 用**（等网络等非动画的事）；这类 flow 会因「屏幕静止 → 提前返回」而行为改变。这是 v2 唯一能改的窗口，**入 deprecation table**。到 ceiling 不算失败 —— 只 warn 并继续（永不静止的多是 spinner，failing 会让该 verb 在任何带 spinner 的屏上不可用）。
- 2026-07-17 [C3 拍板·arg_shape 失真] `ArgShape` 是单值枚举，表达不了联合；而 parser 里有 **170 处形状匹配分支**，多形态是常态（`waitForAnimationToEnd` 吃 bare/数字/`{timeout}` 三种）。**决策：不给 ArgShape 加联合**（等于在一个自称 informational 的枚举里编码整套 yaml 文法，收益不抵 blast radius），改为**让表头对此诚实** —— 明写 arg_shape 只记「主形式」、parser 才是权威、且 C1 的 gate **只验成员关系不验 arg_shape**。同步写进 gate 测试注释。
- 2026-07-17 [C3 已实测·性能权衡] real-sim 实测（sim-smix-02，1206×2622）：**截图往返 median 174ms**（n=10，167–188，PNG 2.8MB）、**解码+比较 39ms**。据此：
  - **原实现（含 60ms cadence）静止屏幕 ≈ 447ms，比它取代的 400ms sleep 慢 12%** —— 我先前预判"可能只是把一种等待换成另一种"**被证实**，而且比预判更差。
  - **修正：删掉 cadence sleep** —— 截图往返本身就是 174ms 采样间隔，再叠 sleep 不多采任何东西、只是变慢。改后静止屏幕 ≈ **387ms vs 400ms = 持平**。
  - **诚实结论：这条改动的价值不是"静止屏幕更快"（是持平），而是 (a) 正确性 —— 长于 ceiling 的动画此前被静默截断；(b) 大 ceiling —— `waitForAnimationToEnd: 5000` 从 5000ms 降到 ~390ms。** 我原先的测试名 `..._is_cheap` 断言 <300ms，只因 mock 截图是瞬时的才通过；已改名为 `..._takes_two_samples_and_stops` 并改为断言采样次数（真机成本写进注释）。**教训：mock 会让测试断言硬件给不了的加速。**
- 2026-07-17 [C3 已实测·参数] 默认值（grid 96 / pixel_delta 4 / max_moved 4）在真机分辨率双向验证：静止 home 4/4 still、静止 Safari 5/5 still、真 launch 过渡 ~870ms 全程 motion、合成光标 9×60(3pt×20pt@3x) **tolerated**、spinner 120×120 **motion**、toast 600×150 motion。**意外发现：静止屏幕上 `max_moved=0` 仍判 still —— 即零采样点变化，模拟器渲染是确定性的、无编码噪声**。故 `pixel_delta` 的注释原写"吸收编码噪声/抖动"**与实测不符**，已改为诚实表述（它是防单级舍入的小护栏；真正干活的是 `max_moved_samples`，为光标而存在）。

- 2026-07-17 [C2 教训·测试布局] ai-tier 的 stub 测试在 `--workspace` 满载下间歇性挂，单跑却稳。分布是证据：**只有依赖"子进程退出并被回收"的测试会挂**，且都走到超时分支。根因指向 `#[tokio::test]` 给每个测试各建一个 runtime，而 tokio 的子进程回收依赖 runtime 的 signal driver ⇒ SIGCHLD 可能落在某个未被 poll 的 runtime 上。**修法：整个测试二进制共享一个 runtime** —— 生产本来就只有一个 `#[tokio::main]` runtime，测试不该发明一个真实调用方从不存在的并发形态。（另：首轮还借此抓到真缺陷 —— 超时只 drop future 而不杀子进程，生产中 hung 的 judge 会滞留；已加 `kill_on_drop`。）
- 2026-07-17 [C1 发现·C8 待落实] **ship gate 从不编译分发给用户的运行器主体**。`ship.sh:54` 只跑 `swift test`，而 `SmixRunnerUITests` 不是 SPM target（是 `project.yml` 的 xcodegen target），所以那 360 tests **不覆盖**它；`build-runner-tarball.sh` 只打包源码，真正的 `xcodebuild` 只发生在用户机器上的 `smix runner up`。即：runner 主体的编译错误会一路发出去，在用户那里才炸。这与 v1.0.27「stale test 潜伏 15+ 版」是同一类门禁盲区。**决策：C8 把 `xcodebuild build-for-testing -scheme SmixRunner -destination 'generic/platform=iOS Simulator'` 加进 ship gate**（本 cycle 已实测可跑通、无需启动模拟器）。附带发现：该 target 有既有的 `lock`/`unlock` in async-context 警告（Swift 6 下将成 error），属 Swift 6 就绪度问题，另记。
