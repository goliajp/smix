## 目标 checkpoint

**C2**：runner 在 `POST /tap` 收到 `{"selector":{"text":"..."}}` 后，**通过 XCUITest 公开 API**（`XCUIApplication` / `XCUIElement` / `XCUIElementQuery.matching(_:)` / `.tap()`）在已 launch 的目标 app 内找到匹配按钮并点击成功；命中返回 `200 {"ok":true,"matched":{"label":"..."}}`，未命中返回 `404 {"ok":false,"error":"not_found","selector":{...},"visible":[]}`。

**已锁定的目标 app**：**Settings**（`com.apple.Preferences`），稳定按钮：text=`"General"`（侧栏 cell label；iOS 26.4 booted sim 上预装且 first-launch 即可见）。

**为什么不是 Calculator**：本机探测确认 iOS 26.4 runtime **未预装 Calculator**（`xcrun simctl listapps FDBDF6F3-... | grep -iE 'calculator|iphonecalc'` → 空）。仅 31 个系统 app；Preferences 是其中**唯一**同时满足"text-only matchable + first-launch 稳定可见 + 不需登录"三条的候选。

**不**做（推 v0.2 后续 checkpoint）：
- `typeText` / `POST /type`（推 C6 — InputChannel + SDK 接通时再做；XCUITest `typeText` iOS 15+ 慢，v1.md §5 风险表已锁兜底策略，C2 范围仅 tap）
- selector 协议除 `{"text":"..."}` 外的所有形态（`id` / `label` / `role+name` / regex / 9 个 modifiers — 推 C5+ 与 InputChannel/resolver 一起做）
- 5-arg / 9-arg Indigo HID（C3 / C4）
- `InputChannel` 抽象 + version dispatch（C5）
- 接入 TS 侧 `Driver`（C6）
- runner 自动启停 / 接入 SimSession 生命周期（v0.2 C6 或 v0.7）
- 失败 payload 含截图 / a11y 树（v1.md SuccessCriteria[2] 需要的"一次自我修正"上下文）— C2 失败 payload 仅 `visible: []` 占位字段，**完整 visible elements 推 C5+**（理由：填充列表需要 `app.descendants(matching: .any).allElementsBoundByAccessibilityElement`，性能与边界都不属 C2 范围）

### S1. `TapRoute` 纯函数 + `SimxRunnerServer` 接受 query closure + `SimxRunnerUITests` 注入 XCUIApplication

> **决策依据（见末尾"关键技术决策"表）**：XCUIApplication 必须在 XCTestCase 上下文构造（XCUITest 框架对 test runner 进程的硬约束），actor `SimxRunnerServer` 在 `SimxRunnerCore` 库内不能直接拿到 — 用**注入路径 (a)**：runner test method 内构造 `app = XCUIApplication(bundleIdentifier: "com.apple.Preferences")` + `.launch()`，把 `@Sendable (text: String) async -> TapOutcome` closure 传 `server.runForever(port:tapHandler:)`。**理由**：(a) 比 (b) "body 含 bundleId 每次构造" 更稳（XCUIApplication 实例需保持 launch 后存活，每次重建会拖 cold start ~2s 进 50ms 单 tap 预算）；比 (c) "默认 frontmost" 更可控（SpringBoard 会污染查询）。本机 booted sim 上 Calculator 不存在 → bundleId 选 `com.apple.Preferences`；c1 的 `SimxRunnerServer` actor 形态保留但扩签名。

**红（写 Swift 单元测试 — XCTest，host 侧 `swift test` 跑，不上 simulator）**

> 路由 handler 拆出**纯函数子集**单测：
> 1. **请求解码**：`TapRoute.decode(_ body: Data) throws -> TapRequest`，输入 raw bytes，输出 `TapRequest { selector: { text: String } }`；非法 JSON / 缺字段 / 错类型 → 抛 `TapRequest.DecodeError`
> 2. **成功响应**：`TapRoute.success(matchedLabel: String) -> HTTPResponse`，status `.ok` + body JSON
> 3. **404 响应**：`TapRoute.notFound(selector: TapRequest.Selector) -> HTTPResponse`，status `.notFound` + body JSON
> 4. **400 响应**：`TapRoute.badRequest(reason: String) -> HTTPResponse`，status `.badRequest` + body JSON
>
> 这 4 个**全纯函数**，host 侧 `swift test` 直接跑。XCUIApplication.tap() 这一段（`closure` 在 simulator 内被调）放 simulator 内才能验，留 S2 端到端验。

- 文件 1（新建）：`swift-bridge/Sources/SimxRunnerCore/TapRoute.swift`
  - 关键签名（**plan 内不写实现**，仅锁形状）：
    ```swift
    public enum TapRoute {
      public struct TapRequest: Equatable {
        public struct Selector: Equatable { public let text: String }
        public let selector: Selector
      }
      public enum DecodeError: Error, Equatable {
        case invalidJSON, missingSelector, unsupportedSelectorForm, missingText, wrongType(String)
      }
      public static func decode(_ body: Data) throws -> TapRequest
      public static func success(matchedLabel: String) -> HTTPResponse
      public static func notFound(selector: TapRequest.Selector) -> HTTPResponse
      public static func badRequest(reason: String) -> HTTPResponse
    }
    ```
  - 实现要点（绿阶段写）：
    - decode 用 `JSONDecoder().decode([String: SelectorOrUnknown].self, ...)` 或 `JSONSerialization` 任一；**锁定用 `JSONSerialization`**（与 `HealthRoute` 风格一致；C2 只支持 1 种 selector form，自定义 `Codable` 是 YAGNI）

    - **不**接触 `XCUIApplication`（避免在 `SimxRunnerCore` library 上引入 XCTest 依赖；XCTest 只在 UITest target 内可用）

- 文件 4（改）：`swift-bridge/SimxRunnerUITests/SimxRunnerUITests.swift`
  - 当前形态：`test_runForever` 调 `server.runForever(port: 22087)`
  - C2 新形态（plan 锁形状，绿阶段写）：
    ```swift
    final class SimxRunnerUITests: XCTestCase {
      func test_runForever() async throws {
        let app = XCUIApplication(bundleIdentifier: "com.apple.Preferences")
        app.launch()
        let server = SimxRunnerServer()
        try await server.runForever(port: 22087) { req in
          // Match by element label / accessibility label / value.
          // XCUIElementQuery does not match by `value` for buttons natively;
          // use the predicate "label == %@ OR identifier == %@".
          let predicate = NSPredicate(format: "label == %@ OR identifier == %@",
                                      req.selector.text, req.selector.text)
          let query = app.descendants(matching: .any).matching(predicate)
          let element = query.firstMatch
          guard element.waitForExistence(timeout: 3) else { return .notFound }
          guard element.isHittable else { return .notFound }
          element.tap()
          // XCUIElement.label is a String, may be empty; echo whatever matched.
          return .matched(label: element.label.isEmpty ? req.selector.text : element.label)
        }
      }
    }
    ```
  - **关键点**：
    - `XCUIApplication(bundleIdentifier:)` 在 launch 前不验证 bundle 存在 → 若目标 sim 缺 Preferences，launch 会 fail；本机已确认存在 ✓
    - `descendants(matching: .any)` + NSPredicate 比 `app.buttons[req.selector.text]` 更通用（C2 selector 仅 text → 既匹配 button 也匹配 cell；Settings 的 "General" 实际是 `XCUIElementTypeCell`，不是 button）
    - `waitForExistence(timeout: 3)` — Settings cold launch ~1-2s + 列表渲染；3s 富余；**不调 sleep**（CLAUDE.md §9.4 — 但这里是 XCUITest 内部 API，不是用户 DSL 表面）
    - `isHittable` 校验避免点到屏幕外 cell
    - 闭包是 `@Sendable` — `app` 在闭包外构造，闭包以非可隔离捕获引用；XCUIApplication 不是 Sendable（Apple 私有类），但 closure 在 actor 内 await 时执行，捕获的引用语义在 UITest 单线程模型下安全。**如 Swift 6 严格并发报 warning**：用 `nonisolated(unsafe)` 或 `@unchecked Sendable` 包装；**决策：先试默认，遇 warning 在绿阶段加 `nonisolated(unsafe)`**（不在 plan 里预编织 — YAGNI）

## 关键技术决策（10 条）

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| 1 | 目标 app（Calculator vs Settings vs Mail） | **Settings (`com.apple.Preferences`)** | 本机 `xcrun simctl listapps FDBDF6F3-...` 探测：iOS 26.4 runtime **未预装 Calculator**；Preferences 是唯一同时满足"预装 + first-launch 稳定可见 + 不需登录 + 有 text-only-matchable cell"四条的候选；Mail 需要账号配置 |
| 2 | 稳定按钮 text | `"General"` | Settings 侧栏顶部稳定 cell；iOS 26.4 首次 launch 默认 root 列表可见；预测匹配 label 而非 identifier 因为 a11y identifier 在系统 app 不稳定 |
| 3 | selector wire format（JSON schema） | `{"selector":{"text":"<string>"}}` 仅此 1 种 form；其他全部推 v0.3 selector resolver | C2 范围锁定（用户提示 + 冷计划 C2 概要）；TS 侧 `src/core/selector.ts` 已定义全集，**故意**只实现子集以快闭环 |
| 4 | JSON 解码器 | `JSONSerialization` 直读 + 手写 dict 走查；**不**用 `JSONDecoder + Codable` | 与 `HealthRoute` 风格一致；C2 仅 1 form 不值得写 Codable；未来 selector 全集来时再迁 |
| 5 | XCUIApplication 注入路径 | **(a) UITest target 构造 + closure 传 server** | (a) launch 一次复用避免 cold start 拖 50ms 单 tap 预算；(b) body 含 bundleId 每次构造 → 多次 launch 慢且 SpringBoard 污染；(c) 默认 frontmost → SpringBoard 误命中风险大；(a) 也保 SimxRunnerCore lib 不 import XCTest/XCUI 不变量 |
| 6 | XCUI query 形态 | `app.descendants(matching: .any).matching(NSPredicate("label == %@ OR identifier == %@"))` + `firstMatch` + `waitForExistence(3)` + `isHittable` | Settings "General" 实为 `XCUIElementTypeCell` 非 button；`descendants(.any)` 通用；NSPredicate 同时覆盖 a11y label 与 identifier；3s 等待覆盖 cold launch；isHittable 校验避免点离屏 cell |
| 7 | 失败 payload 是否含 visible elements 列表 | **C2 仅占位 `"visible":[]` 空数组** | v1.md SuccessCriteria[2] "一次自我修正" 需要 visibleElements，但**完整填充**需要 `descendants(.any).allElementsBoundByAccessibilityElement` + 序列化，性能 + 边界都超 C2 范围（应在 v0.3 selector resolver 一起做）；C2 锁 schema 字段先占位，C5+ 填充 |
| 8 | HTTP 状态码 | 命中 200；未命中 404；解码失败 400 | RESTful 直觉；FlyingFox `HTTPStatusCode.ok`/`.notFound`/`.badRequest` 内建；C2 不用 422（与"语义错误 vs 语法错误"区分推后） |
| 9 | smoke 脚本：新文件 vs 扩 existing | **新文件 `scripts/simx-runner-tap-smoke.sh`** | 单一职责 — `simx-runner-health.sh` 是 C1 验收专用，C2 验收需要 tap 调用；C1 脚本必须仍独立可跑（验收命令 #16）；脚本各自 ~80 行优于合并 1 个超长脚本 |
| 10 | smoke 是否验"未命中 404" 路径 | **是** — `tap_miss` 字段强制 jq 校验 | v1.md SuccessCriteria[2] "一次自我修正" 的前置是 not-found 路径稳定；只验命中等于半验 |

## 与冷计划假设不符之处（必须列出，不要隐瞒）

1. **冷计划 C2 概要写"通过 runner 点 Calculator 按钮成功"**。本机 iOS 26.4 runtime **未预装 Calculator**，本计划改为 Settings (`com.apple.Preferences`) + "General" cell。**实质等价**：目标都是验证"runner HTTP → XCUITest 公开 API → 真实 tap on system app"；不破 C2 语义。**已在决策表 #1 + 决策日志中记录**。
2. **冷计划"TDD 要点"写"用 Apple 的 Calculator app 做基准 e2e（不需要构建 app）"**。改 Settings 同样满足"不需构建 app"。后续 C3/C4/C5/C6 / C7 若再次假设 Calculator，**热化时需逐次重审**目标 sim 上是否预装；本机 iOS 26.4 一律不预装。
3. **冷计划 C2 概要含 "tap/typeText"**。本计划仅做 tap，typeText 推到 C6（v1.md §2.A "兜底" 列 typeText XCUITest 路径与 tap 同列，但实际 XCUITest typeText iOS 15+ 性能 + UIPasteboard 分流逻辑更复杂，独立成 step 更稳）。用户提示明列 "typeText 推 C3+ 或 C2 step 内做简版 — sub-agent 决定" — **决策：推 C6 与 InputChannel/Driver 接通一并做**。
4. **冷计划"出口验收"含 `tap 延迟 P50 < 50ms (iOS 26)`**。C2 不测延迟（XCUITest 公开 API tap 延迟通常 100-300ms，**这是 Indigo HID 主路径要解决的延迟红利**，兜底路径慢是预期）。C2 通过 ≠ 延迟达标 — 后者由 C3/C4 Indigo HID 实现并在 C5 doctor + C7 e2e 验。
