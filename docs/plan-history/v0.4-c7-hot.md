## 关键发现（基于现状代码精确引文）

### F1. `matchers.ts pollFor` 现状 (matchers.ts line 120-134)

```ts
private async pollFor<T>(
  probe: () => Promise<T | null>,
  timeoutMs: number,
  invert = false,
): Promise<T | null> {
  const deadline = Date.now() + timeoutMs
  let interval = 50
  while (true) {
    const result = await probe()
    if (invert ? result === null : result !== null) return result
    if (Date.now() >= deadline) return invert ? null : null   // ← BUG: 两分支同值
    await sleep(Math.min(interval, deadline - Date.now()))
    interval = Math.min(interval * 1.5, 500)
  }
}
```

**C7 改造**：**仅** line 130 `return invert ? null : null` → `return invert ? result : null`。其余 line 120-134 退避算法零改动（已正确：50 起步 + 1.5 倍率 + 500 cap + deadline 截断 + immediate-first-probe）。

**Bug 语义证明**：
- `toBeHidden` caller (matchers.ts line 48-63)：`const stillVisible = await this.pollFor(..., invert=true)`，然后 `if (stillVisible) throw`。
- pollFor 内 invert=true：当 `result === null`（元素消失）时 return result = null → caller `if (null)` = false → 不 throw = 正确（元素真消失 = 成功）。
- pollFor 内 invert=true 且 timeout：`result` 一直 non-null（元素一直可见，否则前一行已返）→ deadline 命中 → **当前**返 null → caller `if (null)` = false → 不 throw = **错误**（元素永远没消失 = 应失败）。
- 修正后：deadline 命中 → 返 last `result`（non-null A11yNode）→ caller `if (node)` = true → throw `ASSERTION_FAILED` = 正确。

**类型安全**：返回类型 `Promise<T | null>` 兼容（result 是 `T | null`，invert 路径 timeout 时实际是 T，但 `T | null` 是超集）。

**non-invert 路径 0 影响**：`return invert ? result : null` 在 invert=false 时仍返 null（与原 `invert ? null : null` 相同）。既有 5 matcher 全 18 既有测试全过。

```ts
async waitFor(selector: Selector, timeoutMs?: number): Promise<A11yNode> {
  const total = timeoutMs ?? WAITFOR_DEFAULT_TIMEOUT_MS
  if (total <= 0) { /* single-shot */ }
  const deadline = Date.now() + total
  while (true) {
    const node = await this.findOne(selector)
    if (node !== null) return node
    if (Date.now() >= deadline) { /* throw TIMEOUT */ }

}
```
