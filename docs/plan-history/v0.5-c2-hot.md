通过后世界变成：

- **REPL 命令表面新增 3 个 meta verb**（决策 7：A 字面 3 个 meta verb 不带 arg）：

  ```
  .history          # 打印 undo-stack 与 redo-stack 合并视图
                    # 格式（undo 段，最旧→最新）：
                    #   1. launch com.apple.Preferences
                    #   2. tap text=General
                    # 格式（redo 段，最旧→最新；undo 段后空一行）：
                    #   3. (redo) tap text=About
                    # 0 条时：no history yet
  .undo             # pop undoStack 顶 → push redoStack 顶 + 打:
                    #   ← undo: <raw>     (raw 是原始用户输入字符串)
                    # 空栈时：nothing to undo
                    # 不触发 describe（meta 命令一致语义）
  .redo             # pop redoStack 顶 → push undoStack 顶 + 打:
                    #   → redo: <raw>
                    # 空栈时：nothing to redo
                    # 不触发 describe
  ```

- **history 入栈语义**（决策 4：A 字面"仅 dispatch 成功的 action verb 入栈"）：
  - **入栈条件**：`parseReplLine` 返 `{kind:'verb', ...}` **且** SDK 调用 (`app.launch/terminate/tap/screenshot/describe`) 未抛错（即 `runVerb` 内 try 块 line 120-139 未走 catch 分支）→ push undoStack；
  - **入栈时机**：在 `runVerb` 成功路径 try block 末尾、auto-describe 之前；describe 自己失败不影响入栈（决策 4 字面：core action 成功 = 入栈，auto-describe 是观察不是 mutation）；
  - **不入栈**：(1) parser error (`{kind:'error'}`) (2) dispatch error / runtime error (`runVerb` catch 分支) (3) meta verb (`.help` / `.exit` / `.history` / `.undo` / `.redo`) (4) noop (空行)；
  - **新 action 入栈 → redoStack.length = 0**（决策 3：经典文本编辑器双栈语义 字面）；
  - **describe verb 入栈但 SDK side-effect = 0**：保留入栈是为了 C3 `.save` 时 describe 可作为"显式 wait/observe step" 落 TS 文件（决策 4.b 字面，cold plan C3 `.save` 隐含"序列里 describe 也算"）。

- **HistoryEntry 数据结构**（决策 6：A 三字段最小集，决策 6.b 不存 result/error）：

  ```ts
  type HistoryEntry = {
    seq: number              // 全局序号，从 1 起递增（不重用，undo/redo 不改）
    raw: string              // 用户原始 input（trim 后）
    parsed: ParsedCommand    // 已解析的 ParsedCommand，C3 需要它生成 TS 代码
  }
  ```
  - **seq 字段为何全局递增不重用**：`.history` 渲染要稳定 seq 标号（user 看到 "3. tap text=About" 撤销后再 redo seq 仍为 3，避免 mental model 混乱）；
  - **不存 timestamp**：C2 plain text 渲染无需时间，C3 `.save` 也不需要（generated TS 是脚本不是日志）；推 C4 doctor 或 v0.7 长跑监控时再加；
  - **不存 result / error**：C2 只入栈成功命令，无 error；result（如 `app.describe()` 的 ScreenDescription）属 transient 状态，C3 `.save` 也只需要 parsed 命令而非 result（决策 6.b）。

- **双栈语义**（决策 3：经典 vim/text-editor 双栈）：
  - `undoStack: HistoryEntry[]`（push tail，`.undo` pop tail；最旧在 [0]）
  - `redoStack: HistoryEntry[]`（同上）
  - `.undo`：`const last = undoStack.pop(); if (last) redoStack.push(last)`
  - `.redo`：`const last = redoStack.pop(); if (last) undoStack.push(last)`
  - 新 action 入栈：`undoStack.push(entry); redoStack.length = 0`
  - 上限：`if (undoStack.length > MAX_HISTORY) undoStack.shift()`（FIFO 删最旧——保新行为；redoStack 不限上限因其 ≤ undoStack 历史 + `.undo` 一次只能 pop ≤ undoStack 一次的量，理论上限同 MAX_HISTORY 自然）

- **`MAX_HISTORY = 1000`** 顶部 const（决策 6.c：A 字面 1000）。`undoStack.length > 1000` 时 shift 删最旧（防长跑爆内存；REPL 长跑 8h 内不会触；推 v0.7 长跑稳定性时若需更高再 config 化）。

- **空栈 hint 形态**（决策 9）：
  - `.undo` 空栈 → `output.write('nothing to undo\n')`（不入 err 因不是错误）
  - `.redo` 空栈 → `output.write('nothing to redo\n')`
  - `.history` 空（undo+redo 都空）→ `output.write('no history yet\n')`

- **`.history` 渲染格式**（决策 7.b：合并视图，undo 段在前 redo 段在后，redo 段标 `(redo)` 后缀）：
  ```
  history (3 entries):
    1. launch com.apple.Preferences
    2. tap text=General
    3. (redo) tap text=About
  ```
  - "(N entries)" 总数 = undoStack.length + redoStack.length；
  - 顺序：undo 段按 seq 升序 + redo 段按 seq 升序拼接（**不**按 push 顺序，避免 redo 多次后 seq 跳序观感差）；
  - 0 条 → `no history yet`；
  - 单行 plain text；不触发 auto-describe（meta 命令）。

- **错误处理与既有 C1 兼容**（决策 10：C2 新增 meta 全部 print hint 不退出 / 不影响 C1 错误链）：

  - 3 个 新 meta 自身不会抛错（数组操作 + console output 都是确定的）；
  - `.history` 永远不报错（即便 0 条也是"no history yet"非 err）。

     if (undoStack.length > MAX_HISTORY) undoStack.shift()

   function renderHistory(): void {
     const total = undoStack.length + redoStack.length
     if (total === 0) {
       output.write('no history yet\n')
       return
     }
     output.write(`history (${total} entries):\n`)
     for (const e of undoStack) output.write(`  ${e.seq}. ${e.raw}\n`)

     if (last === undefined) {

       return
     }
     redoStack.push(last)
     output.write(`← undo: ${last.raw}\n`)

       return

## 决策表

| # | 决策 | 选 | 拒绝路径 | 理由 |
|---|---|---|---|---|
| 1 | **undo 语义边界** | **A 纯命令历史（buffer 草稿；0 sim 状态逆操作）** | B 有限可逆 (`launch X` 逆 = `terminate X`；`tap`/`screenshot` 无逆 → "无法 undo last action" 报错) (违反"用户输入相同命令，REPL 行为不同"的可预测性；半逆操作让 user 误以为 sim 状态已回退而实际只 partial) / C 完整状态快照 (每 action 前快照 tree+screenshot；sim 内部导航栈/滚动位置/text-field 输入光标位置等无法从 outside snapshot 恢复 → 假"快照"+ 大开销) / D combo (`.undo` 仅 buffer 删；可逆 action 顺便调 inverse) (双行为更难解释 + Code 量大 + 边缘 case 爆) | iOS UI 的 action 大多无 deterministic 逆——`tap` 无法 untap、`launch` 后导航栈状态丢失、`fill` 后 cursor 位置 + IME 状态丢失；A 把 `.undo` 定位为"编辑命令草稿"语义（shell history 编辑 / vim 草稿模式同源）= 心智模型清晰；user 真要回退 sim 状态用 `.exit` 重启 REPL 重 `launch`；C3 `.save` 把 undoStack 当脚本草稿落盘是 A 的自然延伸 |
| 2 | **.history 渲染格式** | **A 简单 ordered list of all entries（undo+redo 合并视图，redo 段标 `(redo)` 后缀）** | B 按 verb 分类 (`launches: 1\ntaps: 2\nscreenshots: 0`) (聚合视图无 step 序号 → user 无法定位"撤销第几条"；与 `.undo` LIFO 语义不一致) / C 含 result snapshot (每 step 后 `result: <screenDescription summary>`) (噪声大 + 跨 step 状态污染 + 与 cold plan 字面"列出最近命令"不符) | A 与 bash history / readline history 同源，AI / human 都熟；合并视图（undo 段 + redo 段）让 `.redo` 后 user 看到完整可恢复轨迹；seq 字段渲染稳定标号；trailing `(redo)` 后缀视觉一目了然；plain text 单行 |
| 3 | **双栈 vs 单栈** | **双栈 (undoStack + redoStack)，新 action 清 redoStack** | A 单栈 + pointer (cursor index 指向当前位置，新 action 截断 tail) (经典实现，但 vitest 单测断言"new action clears redo"要看 stack length，单栈 + cursor 需暴露 cursor → 类型表面更复杂) / B 单栈 + 永不清 (`.redo` 重 push old action) (违反经典 undo 语义；vim/word/photoshop 都是新 action 清 redo) | 双栈是 vim / Word / Photoshop / Atom / VSCode 等经典实现，AI 训练语料金标准；`.length === 0` 检查空栈最直观；新 action `redoStack.length = 0` 一行；测试断言简单 |
| 4 | **入栈条件** | **A 仅 dispatch 成功的 action verb 入栈** (`runVerb` core try 块未抛错 = success；auto-describe 失败不影响) | B parser-error 也入栈但标 `failed` (噪声 + 与 `.redo` 语义冲突 — 失败命令 redo 没意义) / C dispatch-error 也入栈但标 `failed` (同) / D auto-describe 失败回退 outcome 为 dispatch-error → 不入栈 (违反"describe 是观察非 mutation"——core action 已发生事实不该被 describe 失败否决；vlm/网络/sim 状态等 transient describe 失败会丢真发生的 action 历史) | cold plan §C2 字面"REPL 命令历史"——失败命令不算"历史事件"，与 bash `history` 默认行为对齐（bash 也记录所有命令含错误，但 simx 是 mutate-or-not 二分而非 shell 通用 history → 仅成功 mutation 入栈语义更清晰）；C3 `.save` 序列化也只需成功 mutation，B/C/D 路径都要过滤 |
| 5 | **跨重启持久化** | **A 仅内存** | B 落 `.simx/repl-history`（接近 bash history） (违反 v1.md §9.4 "默认不暴露持久化"——repl-history 是新文件夹引入，与 `.simx/trace/` 文件夹策略不统一；cold plan §资源依赖未要求；C3 `.save` 落 `examples/<name>.test.ts` 才是 user 想要的持久化) | cold plan §C3 字面 `.save as <name>` 是落盘语义的唯一表面；C2 仅 buffer = 易测 + 0 fs 副作用 + 与决策 1 "命令草稿"语义对齐；REPL 长跑 8h 内 1000 上限不会触；user 退出前没 `.save` = 草稿弃用，符合"REPL 是探索 sandbox"心智 |
| 6 | **HistoryEntry 数据结构** | **A 三字段最小集 `{seq, raw, parsed}`** | B 加 `timestamp: number` (C2 plain text 渲染无需时间；C3 `.save` 生成 TS 也不需要；C4 doctor / v0.7 长跑监控时再加) / C 加 `result?: unknown` (transient 状态污染 + `.history` 渲染会要"摘要"是 vlm 范围 v2) / D 加 `error?: string` (决策 4 否决——失败不入栈) / E 加 `udid: string` / `cellId: string` (single-cell REPL，决策 1 单 cell 不存) | C3 `.save` 输入只需 parsed (生成 TS 代码) + raw (TS 注释为 user 原文)；seq 字段稳定标号 `.history` 渲染；最小集减少 schema 演化负担 |
| 6.c | **`MAX_HISTORY` 上限** | **A 1000 字面** | B 100 (短跑测试用；user 1h REPL 可能 >100 命令；防爆内存的真值不该这么小) / C 无上限 (长跑爆内存风险——8h REPL 几万条 entry，每条含 ParsedCommand discriminated union 几 KB；推 v0.7 长跑稳定性时再 config 化) | 1000 条 entry × 平均 200 bytes ParsedCommand ≈ 200KB 内存；REPL 长跑 8h 不会触；FIFO shift 删最旧保新行为（user 想 `.save` 时最新的更重要） |
| 7 | **3 个新 meta verb 表面** | **A 字面 `.history` / `.undo` / `.redo`，0 arg 严格** | B 带 arg flag（`.history --json` / `.history 20` / `.undo 5` 一次撤 5 条） (推 C3/C5 加 flag；C2 严格 0 arg = parser 简单 + 行为可预测) / C 改写为 `history` / `undo` / `redo` 不带 `.` 前缀（与 action verb 同表面） (`history` 与 `launch` 同级会让 AI 误以为"history" 是个 sim action；node REPL 字面 `.editor` / `.save` / `.load` 全 dot-prefix；保 meta vs action 二分清晰) / D 一组 flag `.h` / `.u` / `.r` 短名 (噪声 + 别名增加学习成本) | node REPL 字面 dot-prefix 是 AI 训练语料金标准 (`.exit` / `.help` 已选)；C2 严格 0 arg = parser strict-equality 单行实现 + test simple；C3 `.save` flag 一并引入 arg parsing 风格更经济 |
| 7.c | **trailing arg 报错形态** | **A `${metaTok} takes no arguments`** (与既有 `screenshot takes no arguments` / `describe takes no arguments` 形态一致) | B `unknown meta '.history 20'` (误导——user 输 `.history` 是 known 的，trailing arg 才是问题) / C silent 忽略 trailing arg (违反"严格 parser fail-fast"原则) | line 56-63 既有形态对齐，AI 一致性 ↑ ；user 看到错误马上知道 = "我多打了空格 + 数字，删掉就对" |
| 8 | **新建 `repl-history.ts` / `repl-history.test.ts`？** | **不新建**（history state 内联到 `repl.ts` closure；test 追加到 `repl.test.ts` describe block） | A 新建 `src/cli/commands/repl-history.ts` 把 undoStack/redoStack/pushHistory/render/undo/redo 抽出为 module (单 instance state 多 instance 单测 race condition 风险；history 是 REPL 进程私有状态 = closure local 最自然；module-level state 让多 REPL instance unit-test 之间状态泄漏；module API 增加抽象成本无 reuse value) / B 新建 `src/cli/__tests__/repl-history.test.ts` (test scope 跨文件 = setup 重复；新 meta verb 与既有 dispatch 测试同一 readline 形态，同文件 describe block 更易) | history 是 REPL 进程私有状态；closure local 单文件 = 单一事实源；C3 `.save` 时把 undoStack 取出作为输入（可能 lift 到 export const），届时再考虑模块化；C2 不预抽 |
