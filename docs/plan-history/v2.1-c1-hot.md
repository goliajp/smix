# plan-hot — v2.1 到 C1:smix-store,唯一打开 kevy 的地方

## 目标 checkpoint

C1:存在一个 `smix-store` crate,它是全仓唯一 `kevy_embedded::Store::open` 的调用点;
它定义 key schema、暴露类型化访问、并能把整库导出为 JSON 供人排障。此后任何存储需求
都从它走,不再有第二处打开数据库。

## 前置条件

```bash
cargo info kevy-embedded | grep -q 'version: 3.18' && echo OK
```

## 步骤(线性)

### S1. crate 骨架 + 打开/落盘/重开

**红**
- 文件:`crates/smix-store/tests/roundtrip.rs`
- 断言:写入一个键 → 同一 `Store` 读回一致;`drop` 后用同一目录重新 `open` → 仍读得到
  (证明落盘真的发生,而不是只活在内存)

**绿**
- 文件:`crates/smix-store/src/lib.rs`
- API:`Store::open(root: &Path) -> Result<Store, StoreError>`(root = `.smix/` 或
  `~/.local/share/smix/`),内部 `kevy_embedded::Config::default().with_persist(root.join("kv"))`
- 关键点:
  - `StoreError` 用 thiserror,包住 `io::Error`,消息里带 key 与路径 —— 不要裸 io 错误
  - **不提供** `set(&str,&str)` 这种裸接口;只暴露下一步会用到的类型化访问,
    避免 key 命名散落到调用方

**重构**
- 无(新 crate)

### S2. key schema + 类型化访问

**红**
- 文件:`crates/smix-store/tests/schema.rs`
- 断言:
  - `store.sims().put(&SimRecord{..})` 后 `store.sims().list()` 含它、`get(udid)` 一致
  - key 前缀是稳定字面量:`sim:<udid>` / `runner:<udid>` / `attempt:<flow-hash>`;
    测试直接断言 `raw_keys()` 的形状,让 key 改名必须改测试(schema 是契约)
  - 未知/损坏的值读出来是**具名错误**,不是 `None` —— 静默当作"不存在"正是本轮反复
    修的那种病

**绿**
- 文件:`crates/smix-store/src/lib.rs`
- API:`store.sims()` / `store.runners()` / `store.attempts()`,各自 `get/put/delete/list`
- 关键点:
  - 值用 serde_json 序列化(可读、可 dump、与既有 JSON 结构同形,便于 C2 导入)
  - 每个命名空间一个 key 前缀常量,集中在一处

**重构**
- 把三个命名空间的重复访问逻辑收成一个泛型 `Namespace<T>`

### S3. `dump`:可检视性不降级

**红**
- 文件:`crates/smix-store/tests/dump.rs`
- 断言:写入两个命名空间的数据后,`store.dump_json()` 输出可被 `serde_json` 解析,
  且包含两者的 key 与值;空库 dump 出合法 JSON 而非空串

**绿**
- 文件:`crates/smix-store/src/lib.rs`
- API:`pub fn dump_json(&self) -> Result<String, StoreError>`
- 关键点:用 `collect_keys(None, None)` 遍历,值按 UTF-8 尝试解析为 JSON,失败则以
  十六进制字符串呈现(不能因为一个坏值让整个 dump 失败)

**重构**
- 无
