### 决策 2：PNG 文件名

**答**：**`<NNNN>-failure.png`**（与 v0.2 C6 `<NNNN>-screenshot.png` 同 seq 序，share 同一个 4 digit zero-pad counter）。

理由：
- `TracingDriver` 既有 seq 是 driver-level (`run.ts` line 138 `String(this.seq).padStart(4, '0')`)——matcher 失败 PNG **不**经 TracingDriver（matcher 调 `driver.describe()` 拿 base64，不调 driver.screenshot），但视觉序号上要"接得上"——如果 case 内已经 screenshot 过 3 次，第 4 次是 matcher 失败，理想是 `0004-failure.png`，让 trace 目录看时间序连贯。
- → trace sink 必须 **共享 seq counter** 与 TracingDriver。最小实现：`TracingDriver` 暴露 `nextSeq(): string` 方法（返回 `'0004'` zero-pad），matcher 失败时调 sink → sink 调 `nextSeq()` → 写 PNG。**或**更简：matcher 失败 sink 持自己 counter（独立于 screenshot seq），文件名形如 `failure-<NNNN>.png` —— 这样不需要 TracingDriver 暴露内部状态。
- **选后者** = `failure-<NNNN>.png`（matcher 自己 1 个 counter，与 TracingDriver screenshot counter 独立）。理由：(1) 不动 `run.ts` `TracingDriver` 内部（接口纪律：sink 是新 helper，不破既有）；(2) `failure-` 前缀让 AI / 人扫 trace 目录立即区分"action screenshot" vs "matcher failure"；(3) 多 case 跑时每 case 各自 reset，不冲突。
- 拒绝 `failure.png` overwrite：决策 3 见——1 个 case 内可能多次 expect 失败（但其实 1 次失败就抛出 throw 整 case 终止——见 sdk/test.ts line 65 catch；**单次 case 内最多 1 个 matcher 失败**）。即便如此，"overwrite" 在跨重跑场景（同一 cwd 同 case slug 反复跑）会丢历史，`<NNNN>` 让历史保留，AI 可对比"上次失败 vs 这次失败"。
- 拒绝 timestamp `failure-<unix>.png`：(1) AI 看 trace 目录序号比时间戳直观（与 0001-screenshot 形态一致）；(2) timestamp 在测试快速重跑时易碰（毫秒级冲突）；(3) seq 4 digit 9999 上限对单 case 来说远超过限制。
- 拒绝 `<NNNN>-failure.png` 与 screenshot 共序：(1) 接口侵入（暴露 TracingDriver.nextSeq）；(2) matcher 不知道 TracingDriver 存在（matcher 看 `driver.describe()`，看不到 TracingDriver 包装层）；(3) `failure-<NNNN>.png` 前缀分桶更清晰。

### 决策 3：多 matcher 失败串联

**答**：**单 case 最多 1 次 failure PNG（throw 即抛出，case 终止）**——seq counter 仍设计 4-digit 允许 N≥2，但实际运行不会触达。

理由：
- 看 `sdk/test.ts` line 65: 每个 test case `await c.fn(ctx)` 在 try/catch 内；`expect(...).toBeVisible()` 抛 `ExpectationFailure` 后 → case 即被 catch → `result.failed++` → 下一个 case—— **单 case 内只能 1 次 matcher 失败**。
- 这是 Playwright / vitest / jest 同语义——assertion fail 即停。simx 不破。
- 但 sink 的 seq counter **必须设计能支持 ≥2**（未来 soft-assert API / `expect.soft()` 推 v0.5+，counter 留余地，但 C2 实测路径只走 N=1）。
- → **C2 实测断言**：1 case 失败 → 目录内仅 `failure-0001.png`；如果手工注入 2 次失败（test fn 内 try-catch 后再次抛），目录内应 `failure-0001.png` + `failure-0002.png`（单测覆盖此理论路径，但 e2e 只验 N=1）。
- 拒绝 "case 内 overwrite single failure.png"：上面 决策 2 已答；保 seq counter design 为未来 soft-assert 留路径。

### 决策 4：matcher 如何知道 trace dir / case slug

**答**：**模块级 trace sink registry**——matcher 调单例 `getMatcherTraceSink()`，由 `run.ts` 在 `beginCase(slug)` 时 register（`setMatcherTraceSink({ traceRoot, caseSlug })`），结束 case unregister。

理由：
- 候选 (A) **构造注入**：`new ElementExpectation(handle, { traceSink })`—— **拒绝**。`expect()` 函数（`src/sdk/expect.ts` line 22）是 `(handle) => new ElementExpectation(handle)`，添加 sink 参数破公开 API 表面，要改 expect() 签名 / 用户测试代码全部 break——违反 "Driver interface 0 改动" 邻区精神（matcher 不是 driver 但同等表面）。
- 候选 (B) **从 driver 拿**：`driver.traceSink` —— **拒绝**。violates Driver interface 0 改动硬约束。
- 候选 (C) **从 handle.driver 走 instanceof 检查 TracingDriver** —— **拒绝**。matcher 不应当 `import TracingDriver`（违反层级——matchers.ts 在 sdk/，TracingDriver 在 cli/commands/；sdk 不能依赖 cli）。
- 候选 (D) **模块级 registry**（`setMatcherTraceSink` / `getMatcherTraceSink` 在新文件 `src/sdk/trace-sink.ts`）—— **选**。理由：
  1. sdk/ 自己持自己的模块单例，无层级倒挂
  2. run.ts 在 `onCaseStart` 中 set，在 `onCaseEnd` 中 clear——单 process 串行跑天然安全（`sdk/test.ts` line 59 串行 for loop，v1 sub-cell 并行推 v1.1）
  3. matcher 拿不到 sink (`sink === undefined`) 时降级 = 0 PNG 落盘 + ExpectationFailure.screenshot 字段仍真填（base64 from driver.describe），与 C1 行为完全一致——sink 缺失不破 matcher
  4. 测试时 matchers test 可注入 fake sink，不需要构造 TracingDriver
- 候选 (E) **`AsyncLocalStorage`**：现代标准答案但需要 wrap 整个 `runRegistry` 调用 + 跨 await 链路 —— C2 范围超载（额外 1 step）；模块级 registry 在 v1 单 cell 串行下等价。v0.5+ 多 cell 并行时如果引入并行 case，再升级 AsyncLocalStorage（cold plan v0.4/v0.5 都不要求）。
- 拒绝 "由 driver 注入 sink (driver.context.trace)"：driver 不该知道"case slug"（case 是 SDK / runner 概念，driver 不应该知道）；TracingDriver 已是"driver wrap"形态，把 sink 内嵌 wrap 内是把 matcher PNG 落盘职责给了 driver wrap，但 matcher 是 sdk 层概念，违反单一职责。

```ts
import { mkdir, writeFile } from 'node:fs/promises'
import { join } from 'node:path'

export type MatcherTraceSink = {
  readonly traceRoot: string
  readonly caseSlug: string
}

let activeSink: MatcherTraceSink | undefined
let seqByCase: Map<string, number> = new Map()

export function setMatcherTraceSink(sink: MatcherTraceSink): void {
  activeSink = sink
  seqByCase.set(sink.caseSlug, 0)
}

export function clearMatcherTraceSink(): void {
  activeSink = undefined
}

export function getMatcherTraceSink(): MatcherTraceSink | undefined {
  return activeSink
}

/** Write failure PNG; returns absolute path written or null on no-op. */
export async function writeFailurePng(
  sink: MatcherTraceSink,
  pngBase64: string | undefined,
): Promise<string | null> {
  if (pngBase64 === undefined || pngBase64.length === 0) return null
  const next = (seqByCase.get(sink.caseSlug) ?? 0) + 1
  seqByCase.set(sink.caseSlug, next)
  const num = String(next).padStart(4, '0')
  const dir = join(sink.traceRoot, sink.caseSlug)
  const out = join(dir, `failure-${num}.png`)
  await mkdir(dir, { recursive: true })
  const bytes = Buffer.from(pngBase64, 'base64')
  await writeFile(out, bytes)
  return out
}
```
