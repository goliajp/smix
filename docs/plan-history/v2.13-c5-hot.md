# plan-hot — v2.13 到 C5：plugin 装得上，装不上时说得清

## 目标 checkpoint

C5：`claude --plugin-dir ./plugin` 能加载 smix plugin，MCP 的 16 个 tool 出现在会话里；
仓库同时是一个 marketplace，`/plugin marketplace add goliajp/smix` 有东西可读；
`smix` 不在 PATH 或版本对不上时，SessionStart hook **说出该敲什么**，
而不是丢给用户一个空的 tool 列表。

## 前置条件

```bash
claude plugin validate --help          # 官方校验器可用 = 机器判据
./target/release/smix-mcp --help 2>/dev/null | head -1 || true
ls .claude-plugin 2>/dev/null || echo "(还没有 marketplace)"
```

## 步骤（线性，3 步）

### S1. 就绪 hook（先写，因为它是装不上时唯一还会说话的东西）

**红（写测试）**
- 文件：`scripts/dev/plugin-readiness.test.sh`（表驱动，device-free）
- 断言：
  - `smix` 与 `smix-mcp` 都在 PATH 且版本一致 → 退出 0，输出里含 `smix <版本>`
  - `smix-mcp` 不在 PATH → 退出 0（**不阻断会话**），但输出含 `npm install -g @goliapkg/smix-cli`
  - 版本与 plugin 声明的不一致 → 输出同时含两个版本号与「升级哪一个」的话
  - hook 读的是 `${CLAUDE_PLUGIN_ROOT}`，不假设 cwd

**绿（实现）**
- 文件：`plugin/scripts/readiness.sh`
- 关键点：**永不退出非零** —— SessionStart 阻断会让整个会话起不来，而缺一个二进制
  不该是「你不能开始工作」。它的职责是把话说清楚，不是拦路

**重构**
- 无

### S2. plugin 骨架 + MCP 接线

**红（写测试）**
- 文件：`scripts/dev/plugin-structure.test.py`
- 断言：
  - `plugin/.claude-plugin/plugin.json` 与 `.claude-plugin/marketplace.json` 都是合法 JSON，
    且 marketplace 里的 `source` 指向真实存在的目录
  - `plugin/.mcp.json` 的 server 命令是 `smix-mcp`（**不写绝对路径**：用户装在哪不由我们决定）
  - 组件目录一律在 plugin 根，**`.claude-plugin/` 里只有 `plugin.json`**
    （官方文档把这条列为最常见错误）
  - plugin.json 的 `version` 与工作区 crate 版本一致

**绿（实现）**
- `plugin/.claude-plugin/plugin.json` / `plugin/.mcp.json` / `plugin/hooks/hooks.json`
  （只挂 SessionStart，护栏留 C6）/ `.claude-plugin/marketplace.json`

**重构**
- 无

### S3. 官方校验 + 真加载

**红（写测试）**
- 文件：`scripts/dev/v2.13-c5-plugin-load-e2e.sh`
- 断言：
  1. `claude plugin validate ./plugin --strict` 退出 0
  2. `claude plugin validate .` （marketplace）退出 0
  3. 起一个 `claude --plugin-dir ./plugin -p` 的最小会话，
     `/context` 或 tool 列表里能看到 `smix_use`（**真加载，不是只校验 JSON**）
  4. 就绪 hook 在该会话里跑过（输出里留有痕迹）

**绿（实现）**
- 按需修正结构直到三条都过

**重构**
- 无
