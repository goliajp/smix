# plan-hot — v2.13 到 C1：拿到 smix 不再需要 Rust

## 目标 checkpoint

C1：`smix` 与 `smix-mcp` 的**预构建二进制**在三个 triple 上由 CI 产出，并由一个 npm 包
按平台分发；在一台没有 Rust 的机器上 `npm i` 之后就能 `smix --version`。
**不发布** —— 发布位留到用户重新考虑发布时再定；本 checkpoint 只把机器建起来并验证到位。

## 前置条件

```bash
grep -n "napi-prebuild" .github/workflows/ci.yml     # 已有的三 triple 矩阵
ls npm/                                              # 现有 npm 包布局
python3 -c "import json;print(json.load(open('crates/smix-node/package.json'))['optionalDependencies'])"
```
期望：矩阵存在（3 个 triple）；`crates/smix-node` 的 optionalDependencies 是已验证过的
「主包 + per-triple 子包」形状，本 checkpoint 照抄它，不发明第二种。

## 步骤（线性，3 步）

### S1. 平台解析写成可测的纯函数

**红（写测试）**
- 文件：`npm/smix-cli/src/resolve.test.ts`
- 断言：
  - `resolvePackage('darwin','arm64',null)` → `@goliapkg/smix-cli-darwin-arm64`
  - `resolvePackage('linux','x64','glibc')` → `@goliapkg/smix-cli-linux-x64-gnu`
  - 不支持的组合（如 `win32`/`arm64`）不返回猜测值，抛出的消息里**同时**含该平台名与
    `cargo install smix-cli` 这条退路 —— 装不上时用户要看到还能怎么办，而不是一个 undefined

**绿（实现）**
- 文件：`npm/smix-cli/src/resolve.ts`
- API：`export function resolvePackage(platform: string, arch: string, libc: string | null): string`
  与 `export function binaryPath(pkg: string, exe: 'smix' | 'smix-mcp'): string`
- 关键点：三 triple 与 CI 矩阵**同源**（同一张表，测试钉住它与矩阵一致）；不做 fallback 到
  任意可用包 —— 装错架构的二进制比装不上更糟

**重构**
- 无（新文件）

### S2. 包结构 + CI 产出二进制

**红（写测试）**
- 文件：`npm/smix-cli/src/layout.test.ts`
- 断言：主包 `package.json` 的 `optionalDependencies` 键集合 == S1 那张表的三个包名；
  `bin` 同时声明 `smix` 与 `smix-mcp`；三个子包各自的 `os`/`cpu` 与其 triple 相符

**绿（实现）**
- 文件：`npm/smix-cli/package.json`、`npm/smix-cli/bin/smix.mjs`、`npm/smix-cli/bin/smix-mcp.mjs`、
  `npm/smix-cli/npm/<triple>/package.json`（三份）
- 文件：`.github/workflows/ci.yml` 加 `cli-prebuild` job（与 `napi-prebuild` 同矩阵）：
  `cargo build --release -p smix-cli -p smix-mcp --target <triple>` → 上传二进制
- 关键点：launcher 用 `execFileSync` 透传 argv 与退出码（MCP 走 stdio，**不能**缓冲或改写流）；
  找不到子包时报 S1 那条含退路的消息

**重构**
- 无

### S3. 无 Rust 的清洁室验证

**红（写测试）**
- 文件：`scripts/dev/v2.13-c1-cli-dist-e2e.sh`
- 断言：把主包与宿主 triple 子包 `npm pack` 成 tarball → 在一个空临时目录 `npm i` 这两个 tarball
  → 该目录下 `npx smix --version` 输出与 `cargo metadata` 的工作区版本一致；
  → `npx smix-mcp` 能在 stdio 上完成一次 MCP initialize 握手；
  → 全程 `PATH` 里**不含** cargo/rustc（脚本自己剥掉），证明没有现编

**绿（实现）**
- 把宿主二进制从 `target/release/` 暂存进子包再 pack（CI 上则用矩阵产物）

**重构**
- 无
