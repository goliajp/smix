# plan-hot — v2.13 到 C2：doctor 说下一步，init 替你走完开场

## 目标 checkpoint

C2：`smix doctor` 从「数设备」变成**就绪判定**——每条检查失败时说出**下一条该敲的命令**，
并有 `--json` 供机器读；`smix init` 一条命令走完注册表引导，替代
「`sim list` → 肉眼抄 UDID → `sim register`」这三步。全程 device-free 可测。

## 步骤（线性，3 步）

### S1. 就绪判定写成纯函数

**红（写测试）**
- 文件：`crates/smix-cli/src/readiness.rs`（`#[cfg(test)] mod tests`）
- 断言：
  - 给定「simctl 可达 / 有可用 runtime / 无注册表」→ 判定为**未就绪**，
    `next` 是 `smix init`，理由句里出现 `.smix`
  - 给定「注册表已有别名、无 runner 在跑」→ `next` 是 `smix capsule up <别名>`
  - 给定「simctl 不可达」→ `next` 讲的是 Xcode 命令行工具，**不是** `smix init`
    （最先断的那一环要排在最前，否则用户会照着一条注定失败的命令走）
  - 全部就绪 → `next` 为 `None`，且没有任何一条检查处于失败态

**绿（实现）**
- API：`pub struct Facts { simctl: Option<SimctlFacts>, registry: Option<RegistryFacts>, runner_port_open: bool, android: AndroidFacts }`
  → `pub fn assess(facts: &Facts) -> Readiness`；`Readiness { checks: Vec<Check>, next: Option<NextStep> }`
- 关键点：**纯函数,不做 IO**；检查按依赖顺序短路（前置断了就不报后续的假失败）

**重构**
- 无（新模块）

### S2. doctor 接上它，并把话说真

**红（写测试）**
- 同文件加断言：`Readiness` 序列化出的 JSON 含 `ready` / `checks[].status` / `next.command`
- 新断言：平台说明句**不得**声称只支持 iOS —— Android emulator 早已支持，
  现行 `main.rs:3178` 的措辞是错的（`assert!(!text.contains("iOS Simulator only"))`）

**绿（实现）**
- `cmd_doctor` 改为：采集 facts → `assess` → 打印；加 `--json`
- 平台句改为陈述真实边界：模拟器 / 模拟器化设备，真机不做（§9#1），iOS 与 Android 都在内

**重构**
- 无

### S3. `smix init`

**红（写测试）**
- 断言（device-free，注入设备清单 + 临时注册表根）：
  - 空目录 + 一台可用 sim → 写出 `.smix/sims.json`，别名默认 `dev`，UDID 正确
  - 已存在同名别名 → **不覆盖**，退出非零并说明怎么改（别名是引用锚，静默改写会让既有 flow 指向别的设备）
  - 无可用设备 → 非零，消息里给出创建设备的命令，而不是空注册表

**绿（实现）**
- `smix init [--alias <名>] [--device <UDID>]`：解析设备 → 注册 → 打印 `next`（复用 S1 的 `NextStep`）
- 关键点：不猜设备。多台可用且未给 `--device` 时列出候选并退出非零
  （与 `pick-dev-sim.sh` 同一条纪律：歧义是错误不是选择）

**重构**
- 无
