## 步骤(线性)

### S1. 闸门:旧存储不能回来

**红**
- 文件:`crates/smix-store/tests/no_json_state.rs`
- 断言:
  - 生产源码(`crates/*/src/**`)里不出现写 JSON 状态文件的形态:
    `sims.json` / `state.json` / `flow-attempts.json` / `subprocess-ring.json` /
    `reset-app-data-counters.json` 作为**写入目标**
  - 不出现 `sqlx` / `redis::` —— 两个外部存储都退场了,回来必须是明确决定
  - **抽取下限**:扫到的源文件数少于阈值即失败,避免"路径写错→什么都没扫→绿"
  - 允许的例外:导入模块(读旧文件是它的职责)、测试、以及本闸门自身

**绿**
- 该闸门当前应当直接绿(迁移已完成);但必须**先证明它会红** ——
  临时在某个 crate 里写一行 `std::fs::write("sims.json", ...)` 看它抓不抓得到

### S2. CHANGELOG:用户会看见什么

**红**
- 无(文档)

**绿**
- 文件:`CHANGELOG.md`
- 关键点:
  - **Breaking**:`DATABASE_URL` / `REDIS_URL` 不再使用(设置了会打印提示);
    smix-server 不再需要 postgres 与 valkey
  - **Changed**:CLI 本地状态从 `.smix/*.json` 迁到 `.smix/kv/`;旧文件**自动导入
    且不删除**;`smix runner down` 语义不变但 iOS/Android 不再互相覆盖
  - **Fixed**:并发 `sim register` 不再丢别名;损坏的状态不再被读成"不存在";
    ring/counters/attempts 的写入失败不再静默
  - 每条都必须能对应到已合入的实现,不写没做的事

### S3. 真机端到端

**红**
- 无(验证)

**绿**
- 真模拟器上跑一遍:`sim register` → `sim boot` → `runner up` → `run` → `runner down`
- 关键点:
  - 确认 `.smix/kv/` 产生、`.smix/sims.json` **未**被创建
  - 确认 `smix runner down` 正常拆解
  - 环境用完回收(runner down + simctl shutdown)
