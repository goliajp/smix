# plan-hot — v2.1 到 C4:smix-simctl 的三处持久化

## 目标 checkpoint

C4:subprocess ring、reset-app-data 计数器、flow attempts 三处不再写 JSON 文件。
三份重复的 `write_json_atomic` 收成零份(store 负责持久化)。三处的
`let _ = write_json_atomic(...)`(丢弃写入)与 `let Ok(..) else { return }`
(把损坏读成空)全部变成具名结果。

## 前置条件

```bash
cargo test -p smix-store -p smix-cli   # C1-C3 全绿
```

## 步骤(线性)

### S1. 三处统一到 store 的 singleton

**红**
- 文件:`crates/smix-simctl/src/lib.rs` 内既有测试改造 + 新增
- 断言:
  - 三者各自 round-trip:写入 → 换新进程视角(清内存后重读)→ 取回一致
  - **ring 的 128 上限仍在**:写 200 条,读回 128 条,且保留的是最新的
    (上限是调用方语义,store 不管;迁移不得把它弄丢)
  - 写入失败**返回错误**而不是被吞:注入一个不可写的 root,`record` 报错
  - 损坏的存量值 → 具名错误,不是"当作空"
  - 旧 JSON 文件存在时仍能读到(导入路径),且原文件不动

**绿**
- 文件:`crates/smix-simctl/src/lib.rs`
- 关键点:
  - 三者都是 singleton(`one:subprocess-ring` / `one:reset-counters` /
    `one:flow-attempts`)——都是"整体读、整体写"的单值
  - 三份 `write_json_atomic` 全删:store 已经负责原子性与落盘
  - `set_*_persist_path` 的签名保持不变(调用方在 `main.rs`,不动它们),
    但语义从"JSON 文件路径"变为"store root";路径末尾是 `.json` 时取其父目录,
    与 C2 的 `smix_dir` 同一处理

**重构**
- 三处的 `load_persisted` / `persist_best_effort` 结构完全同型,收成一个泛型辅助
