# plan-hot — v0.2 到 C3：host-side 9-arg Indigo HID 跑通——`simx-host-hid` 二进制接收 `(udid, x, y)` 调 `SimDeviceLegacyHIDClient` + 9-arg `IndigoHIDMessageForMouseNSEvent`，在已 launch 的 Settings 上**真**点中 "General" cell（与 C2 XCUITest tap 等价语义，但走私有 framework 主路径）

> [3/4 信息层] 当前唯一热计划。完成 C3 后归档到 `plan-history/v0.2-c3-hot.md`，调 sub-agent 生成 v0.2 C4（5-arg Indigo HID 路径，iOS 17/18 — 推到 v0.7 多 runtime CI 矩阵时才能真验证；C4 可能在 v0.2 内推进到 InputChannel 抽象/version dispatch 阶段并把 5-arg 占位）的热计划。
>
> **范围决策**：本计划走**调换顺序方案 (B)** — 冷计划 v0.2.md 原列 C3 = 5-arg / C4 = 9-arg，本计划反过来：**C3 = 9-arg only**，5-arg 推 C4+。理由见末尾"范围决策"段。

## 目标 checkpoint

**C3**：新增 host-side macOS 可执行二进制 `simx-host-hid`（住在 `swift-bridge/Sources/SimxHostHID/` + 通过 `swift-bridge/Package.swift` 新 executable target），CLI 形态：

```bash
simx-host-hid tap --udid <UDID> --x <0-1> --y <0-1>
```

行为：
1. `xcode-select -p` 拿 developer dir → dlopen `SimulatorKit.framework/SimulatorKit`（绝对路径，**不**硬链接、**不** Package.swift `linkedFramework`）
2. dlsym 6 个 C 符号：`IndigoHIDMessageForMouseNSEvent`、`IndigoHIDMessageForButton`、`IndigoHIDMessageToCreatePointerService`、`IndigoHIDMessageToCreateMouseService`、`IndigoHIDMessageToRemovePointerService`、`IndigoHIDMessageForHIDArbitrary`（仅前 4 在 C3 实际调用；后 2 仅 dlsym + 报告以验证可解析，为 C4/C5 留资产）
3. dlopen `CoreSimulator.framework/CoreSimulator` → `NSClassFromString("SimDeviceSet")` + 工厂方法拿到 udid 对应的 `SimDevice`（host-side 端，与 simulator runtime 内进程**完全无关**；这是 baguette 实测模式）
4. `NSClassFromString("_TtC12SimulatorKit24SimDeviceLegacyHIDClient")` → `alloc` + `initWithDevice:error:`
5. 调 `IndigoHIDMessageToCreatePointerService()` + `IndigoHIDMessageToCreateMouseService()` warm-up → 通过 `sendWithMessage:freeWhenDone:completionQueue:completion:` selector 发到 client（baguette 用 ObjC selector 调用 → Mach port 由 SimDeviceLegacyHIDClient 内部维护，simx 不直接构造 mach_msg；CLAUDE.md §9.6 私有符号 dlsym 不变量满足）
6. 调 `IndigoHIDMessageForMouseNSEvent` 9-arg shape 三次：`down` (nsEventType=1, direction=1) → `up` (nsEventType=2, direction=2)；hold 100ms（默认）。坐标传**归一化** 0-1（baguette 实测 NSSize(1.0, 1.0) 让 9-arg 函数按"屏幕分数"解释 CGPoint）
7. 成功 exit 0 + stdout 单行 JSON `{"ok":true,"path":"indigo9","resolved":{...符号列表...}}`；任何 dlopen/dlsym/class lookup/init/send 失败 → exit 非 0 + 单行 JSON `{"ok":false,"error":"<code>","detail":"<msg>"}`

**真验证终点**：
- host CLI `simx-host-hid tap --udid <booted> --x 0.5 --y 0.18` → 已 launch 的 Settings 上"General" cell 被点中 → Settings 跳到 General 详情页 → host 立即 `xcrun simctl io <udid> screenshot --type=png /tmp/c3-after.png` → 通过**目标元素的 a11y label** 间接验证（用 `xcrun simctl ui <udid>` 或 XCUIElementQuery 兜底；具体验收命令见 §Checkpoint）

**已锁定的目标 app + 验证元素**（与 C2 一致避免双轨）：
- bundleId `com.apple.Preferences`（iOS 26.4 sim 预装；Calculator 不存在，与 C2 决策对齐）
- 验证目标：tap 归一化坐标 `(0.5, 0.18)`（iPhone 17 Pro 屏幕上 "General" cell 大致位置）→ Settings 当前根列表转 General 子页 → 验证手段：**对比 tap 前后截图，前者含 "General"+"Display & Brightness"+"Accessibility" 三个 OCR-able 字符串，后者不再含 "Display & Brightness" 兄弟项**（C3 不用 OCR，改用更稳的"a11y dump"：`xcrun simctl ui <udid> accessibility-tree`，若该子命令在 26.x 不存在则降级到"Settings 跳页后 SpringBoard 不会再有 Home Screen 状态"——见决策表 #6）

**不**做（推 v0.2 后续 checkpoint / 后续 minor 版本）：
- 5-arg `IndigoHIDMessageForMouseNSEvent` iOS 17/18 ABI（推 C4 — 但本机无 iOS 17/18 runtime 无法真验证；C4 可能进一步推到 v0.7 CI 多 runtime 矩阵）
- `swipe` / `doubleTap` / `longPress` / `typeText` / `key` / `scroll` / multi-touch / IOHIDEvent 树（推 C4/C5/C6）
- `InputChannel` 抽象 + version dispatch + `simx doctor` 报告（C5）
- 接入 TS 侧 `Driver` / `tap()` API / `SimSession` 生命周期 / 通过 runner HTTP `POST /hid-tap`（C6）
- baguette 全套 `IOHIDDigitizerDispatch` 高级路径（home/app-switcher 边缘手势 — v1.md 范围外）
- 性能 P50 < 50ms 实测（C5 doctor + C7 e2e 时再测；C3 仅证"调通"）
- 单 `simx-host-hid` 长跑复用 `SimDeviceLegacyHIDClient`（C3 是 one-shot CLI，warm-up + 一次 tap + exit；连接复用推 v0.7 测 manager 长跑）
- baguette `IOHIDDigitizerDispatch.swift`（iOS 26 mouse-event 回归绕过路径）—— C3 走 9-arg 直接 mouseFn（baguette 现在生产代码 `tap()` 优先走 IOHIDDigitizerDispatch；但其 `mouseFn` 通路也保留且验证过。**决策：C3 走 mouseFn 直接路径** —— 简单 4 行实测，**绕过 IOHIDDigitizerDispatch 复杂 IOHIDEvent 树构造**，推 C4/C5 再决定是否需要 digitizer 路径。**已知风险**：iOS 26.4 上 mouseFn 单 tap 可能被识别为 Home 手势或丢弃 — 见决策表 #7 降级策略）

### S1. `SimxIndigoHID` 库 + `SimxHostHID` executable target — dlsym wrapper + Indigo 9-arg 调用 + CLI（Swift XCTest 红→绿）

> **决策依据（见末尾"关键技术决策"表 1-5）**：把 dlsym 解析 + 函数指针类型别名 + 错误分类抽到 `SimxIndigoHID` 库 target，CLI `simx-host-hid` 仅做参数解析 + 调库 + JSON 输出。库 target 的非 dlsym 部分（CLI 参数解析 / JSON envelope / 错误码常量）host 侧 `swift test` 直接覆盖；真 dlsym + 真 SimulatorKit 加载推 S2 端到端验。

**红（写 Swift 单元测试 — XCTest，host 侧 `swift test` 跑，不上 simulator）**

> 抽出**纯函数 / 可注入子集**单测：
> 1. **CLI 解析**：`SimxHostHIDArgs.parse(_ args: [String]) throws -> SimxHostHIDArgs`，输入 `["tap", "--udid", "ABCD", "--x", "0.5", "--y", "0.18"]` → 输出 `.tap(udid: "ABCD", x: 0.5, y: 0.18)`；非法输入抛 `ParseError`
> 2. **JSON envelope**：`SimxHostHIDResult.success(path: "indigo9", resolved: [...]) -> String` 与 `SimxHostHIDResult.failure(code: "dlopen_failed", detail: "...") -> String`，与 v0.2 C2 `TapRoute.success/notFound` 风格一致（单行 raw JSON + jsonEscape）
> 3. **错误码常量集合**：`HostHIDErrorCode` enum 全集（`dlopen_failed` / `dlsym_failed` / `class_lookup_failed` / `device_lookup_failed` / `init_failed` / `send_failed` / `unsupported_subcommand` / `invalid_argument` / `udid_not_booted`）— 单测断言 raw string 稳定（C5 doctor / TS 侧反查会用）
> 4. **DlsymResolver 协议 + 注入式假实现**：`protocol DlsymResolver { func open(_ path: String) -> UnsafeMutableRawPointer?; func sym(_ handle: UnsafeMutableRawPointer, _ name: String) -> UnsafeMutableRawPointer? }`；在测试里注入 `FakeDlsymResolver`（一张 `[String: UnsafeMutableRawPointer?]` map），断言：
>     - 所有符号都解析成功 → `IndigoSymbols(mouseFn:..., buttonFn:..., createPointerSvc:...)` 非 nil
>     - 任一关键符号 nil → 抛 `HostHIDError.dlsymFailed(name: "<sym>")`
>     - dlopen 返回 nil → 抛 `HostHIDError.dlopenFailed(path: "<path>")`
>
> 这 4 类**全在 host 侧 `swift test` 跑**，零 simulator 依赖。真 dlopen / SimulatorKit / SimDeviceLegacyHIDClient init / IndigoHIDMessageForMouseNSEvent 调用这一段只能进 simulator 上下文（其实是 host process — baguette 模式 — 但需要真 booted sim 的 SimDevice 对象），留 S2 端到端验。

    ```swift
    import Foundation
    import SimxIndigoHID

    @main
    enum SimxHostHIDCLI {
      static func main() {
        let raw = CommandLine.arguments.dropFirst()
        do {
          let parsed = try SimxHostHIDArgs.parse(Array(raw))
          switch parsed {
          case .tap(let udid, let x, let y):
            let resolved = try runTap(udid: udid, x: x, y: y)
            print(SimxHostHIDResult.success(path: "indigo9", resolved: resolved))
            exit(0)
          }
        } catch let e as HostHIDError {
          FileHandle.standardError.write(Data("\(e)\n".utf8))
          print(SimxHostHIDResult.failure(error: e))
          exit(1)
        } catch let e as SimxHostHIDArgs.ParseError {
          FileHandle.standardError.write(Data("\(e)\n".utf8))
          print(SimxHostHIDResult.failure(error: .invalidArgument("\(e)")))
          exit(2)
        } catch {
          print(SimxHostHIDResult.failure(error: .invalidArgument("\(error)")))
          exit(3)
        }
      }

      static func runTap(udid: String, x: Double, y: Double) throws -> [String] {
        let resolver = SystemDlsymResolver()
        let dev = try CoreSimulatorBridge.developerDir()
        let skPath = CoreSimulatorBridge.simulatorKitPath(dev)
        guard let skHandle = resolver.open(skPath) else {
          throw HostHIDError.dlopenFailed(path: skPath, detail: resolver.lastErrorDescription())
        }
        guard let csHandle = resolver.open(CoreSimulatorBridge.coreSimulatorPath) else {
          throw HostHIDError.dlopenFailed(path: CoreSimulatorBridge.coreSimulatorPath,
                                          detail: resolver.lastErrorDescription())
        }
        let syms = try IndigoSymbols.resolve(handle: skHandle, via: resolver)
        try IndigoHIDDispatcher.tapNormalized(
          udid: udid, x: x, y: y,
          symbols: syms, coreSimulatorHandle: csHandle
        )
        return IndigoSymbolNames.allRequiredForC3
      }
    }
    ```
