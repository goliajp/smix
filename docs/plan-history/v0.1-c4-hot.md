## 目标 checkpoint

**C4**：在 C3 的 `SimctlClient`（含 `listDevices` / `boot` / `shutdown` 等 11 个方法）之上，新增**独立文件** `src/sim/session.ts`，导出 thin lifecycle 封装：

- `acquireSession(opts: AcquireOptions, deps?: SessionDeps): Promise<SimSession>`
- `class SimSession`，含：
  - `udid: string`（构造时 freeze 的 getter / readonly 属性）
  - `device: SimctlDevice`（acquire 时拍下的快照）
  - `release(opts?: { shutdown?: boolean }): Promise<void>`
  - `isAlive(): Promise<boolean>`
- 4 个结构化错误类：`DeviceNotFoundError` / `DeviceAmbiguousError` / `BootTimeoutError` / `BootFailedError`，全部继承自 `SessionError`（带 `code: 'DEVICE_NOT_FOUND' | 'DEVICE_AMBIGUOUS' | 'BOOT_TIMEOUT' | 'BOOT_FAILED'` 与可机器读的 `details`）

auto-boot 流程（**已锁定，无分叉**）：

1. `acquireSession` 调 `client.listDevices()` → 按 `udid` / `(deviceName, runtimeIdentifier)` 过滤
2. 0 个匹配 → 抛 `DeviceNotFoundError`；≥2 个匹配且未传 `udid` → 抛 `DeviceAmbiguousError`（带候选列表）
3. 唯一匹配且 `state === 'Booted'` → 直接返回 `SimSession`
4. 唯一匹配且 `state !== 'Booted'` 且 `autoBoot !== false` → 调一次 `client.bootAndWait(udid, bootTimeoutMs)`（**新增公开方法**，见下），返回 `SimSession`
5. 唯一匹配且 `state !== 'Booted'` 且 `autoBoot === false` → 抛 `BootFailedError`（code `BOOT_FAILED`, hint "device not booted and autoBoot=false"）

**bootstatus 行为决策**（见下方"决策"段）：在 `SimctlClient` 上**新增 1 个公开方法** `bootAndWait(udid, timeoutMs)`，包装 `xcrun simctl bootstatus <udid> -b` 一条命令（已 boot 时 no-op、否则发起 boot 并阻塞至完成），不再写 polling 循环。超时由我们设的 `timeoutMs` 用 race 实现（命令进程 vs setTimeout），超时即抛 `BootTimeoutError`，**不杀子进程**（让 simctl 自己处理）。

测试全过 = `bun run test` exit 0，passed 数比 C3 末态 32 多 9（S1 5 + S2 4 = 9 新 case），即 ≥ 41。

**绿（实现）**

- 文件：`src/sim/simctl.ts`（仅在 `SimctlClient` 内新增 1 个公开方法 + 1 个 const；不改任何既有签名）
- 类型表面：无新导出类型。`timeoutMs` 用 `number`（毫秒），默认 60_000。
- `SimctlClient` 新增方法：
  ```ts
  async bootAndWait(udid: string, timeoutMs: number = 60_000): Promise<void>
  ```
- 关键点：
  - 内部不调 `this.runText`（要 race 超时），直接：
    ```ts
    const work = this.spawn('xcrun', ['simctl', 'bootstatus', udid, '-b'])
    const timeout = new Promise<never>((_, reject) => {
      setTimeout(() => reject(new BootstatusTimeoutMarker(timeoutMs)), timeoutMs).unref()
    })
    const r = await Promise.race([work, timeout])
    if (r.exitCode !== 0) throw new Error(`simctl bootstatus failed (exit ${r.exitCode}): ${truncate(r.stderr)}`)
    ```
  - 用 `setTimeout(...).unref()` 防止 timer 阻塞 node 退出；`BootstatusTimeoutMarker` 是文件局部 class，仅承载 `timeoutMs`。`catch` race 后用 `instanceof` 判断 timeout，抛 `Error('simctl bootstatus timed out after <timeoutMs>ms')`（普通 Error；session 层会包成 `BootTimeoutError`）
  - **WHY 注释一行**：`simctl bootstatus <udid> -b` 既负责"if not booted, boot it"，也阻塞至 finished，所以这里只跑一次而非 polling
  - 不杀子进程（`xcrun simctl bootstatus` 没有 detach 副作用；让 OS 在 node 退出时回收 / 用户后续操作覆盖）
- 跑：`cd /Users/doracawl/workspace/labs/lab15-autofix && bun run typecheck && bun x vitest run src/sim/__tests__/simctl.test.ts`
- 期望：**exit 0**，passed 数比 C3 末态多 4（≥ 36 total，含 C3 29 + 这里 4 + sanity 不在该文件内）。验证用 `grep -Eq 'Tests +([0-9]+) passed'` 后比对 ≥ 33（该单文件内 ≥ 33；32 是包含 sanity，本步只跑 simctl.test.ts 应 ≥ 33）

- 公开类型表面（CLAUDE.md §8.3 强制显式返回类型）：
  ```ts
  import type { SimctlClient, SimctlDevice } from './simctl.js'

  export type AcquireOptions = {
    udid?: string
    deviceName?: string
    runtimeIdentifier?: string
    autoBoot?: boolean        // 默认 true
    bootTimeoutMs?: number    // 默认 60_000
  }

  export type SessionDeps = {
    client: SimctlClient
  }

  export type SessionErrorCode =
    | 'DEVICE_NOT_FOUND'
    | 'DEVICE_AMBIGUOUS'
    | 'BOOT_TIMEOUT'
    | 'BOOT_FAILED'

  export class SessionError extends Error {
    readonly code: SessionErrorCode
    readonly details: Readonly<Record<string, unknown>>
    constructor(code: SessionErrorCode, message: string, details: Record<string, unknown>) { ... }
  }
  export class DeviceNotFoundError extends SessionError {}
  export class DeviceAmbiguousError extends SessionError {}
  export class BootTimeoutError extends SessionError {}
  export class BootFailedError extends SessionError {}

  export class SimSession {
    readonly udid: string
    readonly device: SimctlDevice
    constructor(client: SimctlClient, device: SimctlDevice) { ... }
    async release(opts?: { shutdown?: boolean }): Promise<void>
    async isAlive(): Promise<boolean>
  }

  export async function acquireSession(
    opts: AcquireOptions,
    deps: SessionDeps,
  ): Promise<SimSession>
  ```
- 关键点：
  - **device 选择算法**（按优先级）：
    1. `opts.udid` 存在 → 在 `listDevices()` 结果里精确匹配 `d.udid === opts.udid && d.isAvailable`；0 → `DeviceNotFoundError`；多个不可能（udid 唯一），但若发生（数据脏）→ 按"无歧义"处理（取第一个），同时 message 带 warning（详见错误消息表）
    2. 否则按 `deviceName` / `runtimeIdentifier` 过滤（任一为 undefined 视作 wildcard），`isAvailable` 必为 true；0 → `DeviceNotFoundError`；≥2 → `DeviceAmbiguousError`（`details.candidates = [{udid, name, runtimeIdentifier, state}, ...]`）
    3. 都没传 → 也走 case 2 的全集，必然 ≥2（本机 3 台）或 0；同样按上面规则
  - **boot 路径**：选中 device 后，若 `state === 'Booted'` → 直接构造 `new SimSession(client, device)`；否则若 `autoBoot !== false` → 调 `client.bootAndWait(udid, bootTimeoutMs ?? 60_000)`，try/catch 把 `Error('… timed out after Xms')` 转 `BootTimeoutError`、其他错误转 `BootFailedError`（保留原 `cause`）；若 `autoBoot === false` → 直接抛 `BootFailedError`（code `BOOT_FAILED`, message `device <udid> not booted and autoBoot=false`）
  - **错误消息（必须可 feed 给上层 AI fix）**：
    - `DeviceNotFoundError`: `device not found: { udid: 'NOPE' }` 或 `device not found: { deviceName: 'iPhone 16 Pro', runtimeIdentifier: '...' }`，`details` 含传入的查询条件
    - `DeviceAmbiguousError`: `multiple devices match: <N> candidates; pass udid to disambiguate`，`details.candidates` 含 udid 列表
    - `BootTimeoutError`: `bootstatus timed out after <ms>ms for udid <udid>`，`details.timeoutMs` / `details.udid`
    - `BootFailedError`: `boot failed for udid <udid>: <underlying message>`，`details.udid` / `details.cause`
  - **SimSession.release**：`opts?.shutdown === true` → `await this.client.shutdown(this.udid)`；否则 no-op。**WHY 注释一行**：默认不 shutdown，避免影响共享 device（v1 不做 sim pool，但保留礼貌）
  - **SimSession.isAlive**：`const list = await this.client.listDevices(); return list.find((d) => d.udid === this.udid)?.state === 'Booted'`
  - 文件不导入 `node:child_process`，不写 spawner（client 已封装）

### 4. bootstatus 行为决策（**关键**）
本机 `xcrun simctl help bootstatus` 输出已确认：

> `Usage: simctl bootstatus <device> [-bcd]`
> `-b   Boot the device if it isn't already booted.`
> `Monitors the specified device and prints boot status information until the device finishes booting.`

→ **决策：用 `bootstatus -b` 单条命令**，**不**做 listDevices polling。
- 一次调用同时承担"if not booted, boot it" + "block until finished"；无需我们再写状态轮询循环
- 子进程会一直运行直到 boot 完成（或上游 simctl 报错退出），exitCode 直接代表成功/失败
- 我们自己的 timeout 用 `Promise.race(work, setTimeout)` 实现；超时不 kill 子进程（让 OS 在 node 退出时回收，避免引入 kill 时序坑；boot 半途无副作用）
- `setTimeout(...).unref()` 防止挂起的 timer 阻塞 node 进程退出

这把"boot 是异步"的冷计划风险（plan-cold v0.1 已知风险段）正式落到 `SimctlClient.bootAndWait` 一个方法里，session 层只是消费。

### 5. 错误模型决策（AI-friendly）
4 个错误类继承 `SessionError`，每个带固定 `code` + 结构化 `details`：

| 类 | code | message 示例 | details |
|---|---|---|---|
| `DeviceNotFoundError` | `DEVICE_NOT_FOUND` | `device not found: { udid: 'NOPE' }` | 传入的查询条件原样回显 |
| `DeviceAmbiguousError` | `DEVICE_AMBIGUOUS` | `multiple devices match: 2 candidates; pass udid to disambiguate` | `candidates: [{udid, name, runtimeIdentifier, state}]` |
| `BootTimeoutError` | `BOOT_TIMEOUT` | `bootstatus timed out after 30ms for udid AAAA-1111` | `udid`, `timeoutMs` |
| `BootFailedError` | `BOOT_FAILED` | `boot failed for udid AAAA-1111: <underlying>` | `udid`, `cause`（保留原 Error） |

这与冷计划"已知风险 / 报清晰错误"+ v1.md SuccessCriteria[2]（一次自我修正）对齐：上层 AI 看 `code` 走分支、看 `details` 填修复参数。和 C5 的 `DRIVER_ERROR with hint` 形态一致（不强耦合，C5 可独立选择是否包一层 `ExpectationFailure`）。

### 7. 与冷计划假设不符之处
- **冷计划"已知风险"建议 `bootstatus -b` 轮询**，措辞暗示"周期性查询"。本机探测显示 bootstatus 本身就是阻塞的 monitor 命令（非 polling 接口）。决策：**单次同步 race**而非 polling 循环；冷计划用语在 v0.1 冷计划已是"对策建议"层级，未与现实冲突，仅是细化。
- **本机仅 1 个 iOS-26-4 runtime + 1 个 iOS-18-6 runtime（且 18-6 device `isAvailable=false`）**，未覆盖冷计划入口条件期望的"≥1"之外的多 runtime 矩阵。C4 单测全 mock 不受影响；保留给 v0.7 CI 矩阵或单独安装步骤。
- **C3 留给 C4 的"`SimctlClient.boot` 不做完成轮询"约定**：C4 不改 `boot` 行为；新增 `bootAndWait` 作为独立公开方法（不替代 `boot`）。session 层只用 `bootAndWait`，但 `boot` 仍保留给希望"只发起、不等"的下游（如 driver 调试）。
- **`Spawner` 类型已能承载 race timeout**：S1 直接 `Promise.race(this.spawn(...), timer)`，无需为 timeout 再扩 spawner 类型表面（保持 C3 的 spawner 形态）。
- 冷计划 C4 描述未明示"歧义 vs 找不到 vs 超时"分类。本热计划用 4 个独立错误类落地，作为对"错误消息应可被 AI 上层 fix"的具体兑现；C5 driver 层可在此基础上再统一映射为 `DRIVER_ERROR with hint`。
