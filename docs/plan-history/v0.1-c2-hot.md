## 步骤（线性，无分叉；2 个 step）

### S1. 类型 + listRuntimes（spawner DI，单测红→绿）

**红（写测试）**

- 文件：`src/sim/__tests__/simctl.test.ts`
- 在此文件 `import { SimctlClient } from '../simctl.js'`，以及 `import type { SimctlRuntime } from '../simctl.js'`（NodeNext ESM，需 `.js` 后缀）
- spawner 的最小契约（测试侧定义、传入 `new SimctlClient({ spawn: fakeSpawn })`）：
  - `type Spawner = (cmd: string, args: readonly string[]) => Promise<{ stdout: string; stderr: string; exitCode: number }>`
- 3 个 test case：
  1. `listRuntimes() 解析 iOS runtimes 并跳过非 iOS`
     - fakeSpawn 断言被调用一次，参数恰为 `('xcrun', ['simctl', 'list', 'runtimes', '-j'])`
     - 返回固定 stdout（含 `platform: "iOS"` 的 1 条 + `platform: "tvOS"` 的 1 条），`exitCode: 0`
     - 断言：返回 `SimctlRuntime[]` 长度 1；元素含 `identifier`、`name`、`version`、`isAvailable` 四个字段且类型正确；非 iOS 项被过滤掉
  2. `listRuntimes() 在 exitCode 非 0 时抛错并带 stderr 片段`
     - fakeSpawn 返回 `{ stdout: '', stderr: 'xcrun: error: ...', exitCode: 72 }`
     - 断言：`await expect(client.listRuntimes()).rejects.toThrow(/simctl list runtimes failed.*exit 72/)`，且错误消息包含 `xcrun: error:` 子串
  3. `listRuntimes() 在 stdout 不是合法 JSON 时抛错并带 stdout 片段`
     - fakeSpawn 返回 `{ stdout: 'not-json-{{{', stderr: '', exitCode: 0 }`
     - 断言：`rejects.toThrow(/failed to parse simctl runtimes JSON/)`，错误消息包含被截断的原始 stdout 前缀
- 跑：`cd /Users/doracawl/workspace/labs/lab15-autofix && bun x vitest run src/sim/__tests__/simctl.test.ts`
- 期望：**exit 非 0**（`src/sim/simctl.ts` 尚未创建）

**绿（实现）**

- 文件：`src/sim/simctl.ts`
- 公开 API（v0.1 C2 仅 list 类）：
  ```ts
  export type SimctlRuntime = {
    identifier: string
    name: string
    version: string
    isAvailable: boolean
  }
  export type Spawner = (
    cmd: string,
    args: readonly string[],
  ) => Promise<{ stdout: string; stderr: string; exitCode: number }>
  export type SimctlClientOptions = { spawn?: Spawner }
  export class SimctlClient {
    constructor(opts?: SimctlClientOptions)
    listRuntimes(): Promise<SimctlRuntime[]>
  }
  ```
- 关键点：
  - 构造函数的 `spawn` 缺省值用 `node:child_process` 的 `execFile` 包装成 `Spawner`（私有 helper `defaultSpawn`，放同文件底部）；测试一律走注入路径，**不**用 `vi.mock('node:child_process')`
  - `listRuntimes()` 步骤：调 `spawn('xcrun', ['simctl', 'list', 'runtimes', '-j'])` → 非 0 退出抛 `Error('simctl list runtimes failed (exit <code>): <stderr 前 200 字符>')` → `JSON.parse` 失败抛 `Error('failed to parse simctl runtimes JSON: <stdout 前 200 字符>')` → 过滤 `platform === 'iOS'` → 映射到 `SimctlRuntime`（只摘四个字段，不暴露上游 schema）
  - 公开 API 必须显式标注返回类型（CLAUDE.md §8.3）
- 跑：`cd /Users/doracawl/workspace/labs/lab15-autofix && bun run typecheck && bun x vitest run src/sim/__tests__/simctl.test.ts`
- 期望：**exit 0**，输出含 `3 passed`

- 无（保持最小实现，错误消息构造逻辑等 S2 加完 `listDevices` 后若重复再抽 helper）

### S2. listDevices（同套 spawner DI；S1 红绿后接力）

**红（写测试）**

- 文件：在 `src/sim/__tests__/simctl.test.ts` 内 `describe('listDevices', ...)` 块追加 3 个 test case
- 形态参考 `xcrun simctl list devices -j`，其顶层为 `{ devices: { "<runtime identifier>": [ { udid, name, state, isAvailable, deviceTypeIdentifier } ... ] } }`
- 3 个 test case：
  1. `listDevices() 展平嵌套结构并附 runtimeIdentifier`
     - fakeSpawn 断言参数恰为 `('xcrun', ['simctl', 'list', 'devices', '-j'])`
     - 返回固定 stdout 含两个 runtime key，每个 key 下各 1 个 device，`exitCode: 0`
     - 断言：返回 `SimctlDevice[]` 长度 2；每个元素含 `udid`、`name`、`state`、`isAvailable`、`runtimeIdentifier`、`deviceTypeIdentifier` 六个字段；`runtimeIdentifier` 等于其所在 key
  2. `listDevices() 在 exitCode 非 0 时抛错并带 stderr 片段`
     - fakeSpawn 返回 `{ stdout: '', stderr: 'boom', exitCode: 1 }`
     - 断言：`rejects.toThrow(/simctl list devices failed.*exit 1/)`，消息含 `boom`
  3. `listDevices() 在 stdout 不是合法 JSON 时抛错并带 stdout 片段`
     - fakeSpawn 返回 `{ stdout: '<<broken>>', stderr: '', exitCode: 0 }`
     - 断言：`rejects.toThrow(/failed to parse simctl devices JSON/)`
- 跑：`cd /Users/doracawl/workspace/labs/lab15-autofix && bun x vitest run src/sim/__tests__/simctl.test.ts`
- 期望：**exit 非 0**（`SimctlClient` 还没 `listDevices` 方法 / `SimctlDevice` 类型不存在）

**绿（实现）**

- 文件：`src/sim/simctl.ts`（追加；不动 S1 已有代码的行为）
- 公开 API 追加：
  ```ts
  export type SimctlDevice = {
    udid: string
    name: string
    state: string
    isAvailable: boolean
    runtimeIdentifier: string
    deviceTypeIdentifier: string
  }
  // class SimctlClient 内追加：
  listDevices(): Promise<SimctlDevice[]>
  ```
- 关键点：
  - 调 `spawn('xcrun', ['simctl', 'list', 'devices', '-j'])`，错误 / 解析失败分支与 `listRuntimes` 同形（短语 "simctl list devices failed" / "failed to parse simctl devices JSON"）
  - 展平：`Object.entries(parsed.devices)` → 对每个 `[runtimeIdentifier, deviceArr]`，把 runtimeIdentifier 拍到每条 device 上；只摘 6 个字段
  - 占位集成测试：新建空文件 `src/sim/__tests__/integration/simctl.test.ts`，内容仅一行 `// integration tests for src/sim/simctl.ts — populated in later checkpoints`（被 `vitest.config.ts` 的 `**/integration/**` exclude 跳过；不让目录"幽灵存在"）
- 跑：`cd /Users/doracawl/workspace/labs/lab15-autofix && bun run typecheck && bun run test`
- 期望：**exit 0**，输出含 `6 passed`（S1 三个 + S2 三个；C1 sanity 的 3 个不在此文件，全套 vitest 总数 ≥ 9 passed）

**重构**

- 若 `listRuntimes` 与 `listDevices` 的"调 spawn + 校验 exitCode + JSON parse"骨架明显重复，抽一个私有函数 `runSimctlJson<T>(args: readonly string[], op: string): Promise<T>`（op 用于错误消息），并让两个 list 方法只负责"取字段子集 / 展平"。重构期间所有 6 个 test 保持绿。
