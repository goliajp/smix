### S1. 纯 TS 实现 — 移除 C4 护栏 + 加 modifier filter 三段管线

> **决策依据（见末尾"关键技术决策"表 #1-#6）**：
> - **collect-all → spatial filter → index pick 三段管线（决策 #6）**：C4 是 DFS first-match；C5 base 必须先 collect-all（所有 base 命中），否则 nth/first/last 无 list 可索引、spatial filter 无候选集可过滤。三段管线天然组合所有 modifier，避免"先 first-match 再修正"的反复回溯
> - **`near` 固定 100pt 阈值（决策 #1）**：iOS Settings cell 高度 ≈ 44pt，相邻 cell 中心距 ≈ 50-60pt；按钮 + label 组距 ≈ 60-80pt；100pt 涵盖典型 UI "邻近" 直觉，且远小于屏幕宽度（390-440pt），避免误命中远处元素。自适应（基于元素 size）会让"near" 行为随元素大小漂移，AI 测试作者不可预测
> - **`below/above/leftOf/rightOf` centroid 比较，无 alignment 容差（决策 #2）**：candidate.centroid 相对 anchor.centroid 在主轴方向序正确即匹配；副轴不约束。这与 Playwright `getByText('X').filter({below: ...})` 同语义；alignment 容差（如"y 偏差 ≤ 20pt"）引入二级阈值参数，AI 难写难测。**注意**：单方向 modifier 通常需配 `near` 或 `nth` 才能唯一定位（典型用法 `{role:'cell', below:{text:'Section'}, nth:0}`）
> - **`inside` 用 bounds 几何包含（决策 #3）**：candidate.bounds 完整落入 anchor.bounds（4 边都包）→ 命中。**不**用 DOM 包含（AX tree 形态在 iOS 17/18/26 上差异大，C3 决策日志已记 cell 嵌套 button 不一致；几何包含跨版本稳定）。**等于 self 不算 inside**（candidate !== anchor by reference）
> - **DFS pre-order index for nth/first/last（决策 #4）**：与 C4 collect-all 顺序一致；保持"selector 顺序 = a11y tree 顺序"直觉。bounds 排序（top-to-bottom / left-to-right）虽视觉直觉但与 a11y tree DFS 顺序经常不一致（iOS list cell 可能 a11y 倒序），AI 测试作者不可预测；用户需要视觉排序时显式用 `below`/`above` modifier 组合
> - **多 modifier AND 交集（决策 #5）**：所有 spatial filter 独立施加（candidate 同时满足每个 modifier 才保留）；最后 nth/first/last 在 surviving list 上索引。**不**按顺序应用（避免依赖 modifier 字段在 type 中的顺序）；不允许冲突 modifier（first + last + nth 多个同时给 → 取**最后定义的**那个：first → last → nth 顺序覆盖，最后一个赢；与 Playwright 行为同）
> - **anchor null fail-fast**：spatial / inside modifier 若 anchor selector 无 match → 整体 `resolveSelector` 返 null（**不**抛错；与 base 无 match 同语义；caller / matcher 在 C6 失败时填 visibleElements + suggestions）

  ```typescript
  /**
   * Resolve a Selector against an A11yNode tree.
   *
   * Pure function — no driver / runner / sim calls. Caller (Driver in C6+)
   * is responsible for fetching the tree (via A11yTreeSource.getTree()) and
   * for translating the matched node into a tap target (coord or runner /tap).
   *
   * Pipeline (v0.3 C5):
   *   1. collect-all: DFS pre-order collect every node whose own fields match
   *      the base selector form (text / id / label / role+name).
   *   2. spatial filter: for each relation modifier (near / below / above /
   *      leftOf / rightOf / inside), recursively resolve the anchor selector;
   *      filter candidates by bounds geometry. AND semantics across modifiers.
   *      Anchor selector returning null short-circuits to null overall.
   *   3. index pick: apply nth / first / last on the surviving candidate list.
   *      When several index modifiers are given, last-defined wins
   *      (Modifiers field iteration order: first, last, nth).
   *
   * The returned A11yNode is candidates[0] of the final list (which after
   * index pick has 0 or 1 elements; without index modifier the first DFS
   * pre-order candidate, matching C4 first-match semantics).
   *
   * Matching semantics (locked in design.md §Selector 匹配语义):
   * - bounds unit = logical points @1x (A11yNode wire chapter)
   * - near threshold = 100 logical points (centroid Euclidean distance)
   * - below/above/leftOf/rightOf = centroid axis dominance, no alignment
   *   tolerance
   * - inside = bounds geometric containment (NOT DOM ancestry)
   * - nth/first/last index = DFS pre-order (matches C4 collect order)
   * - anchor null = overall null (no throw)
   */
  export function resolveSelector(tree: A11yNode, selector: Selector): A11yNode | null {
    const candidates = dfsCollect(tree, (n) => matchesBase(n, selector))
    const filtered = applySpatialFilters(tree, candidates, selector)
    if (filtered === null) return null
    const picked = applyIndex(filtered, selector)
    return picked.length === 0 ? null : (picked[0] ?? null)
  }

  function dfsCollect(node: A11yNode, pred: (n: A11yNode) => boolean): A11yNode[] {
    const out: A11yNode[] = []
    walk(node)
    return out
    function walk(n: A11yNode): void {
      if (pred(n)) out.push(n)
      for (const c of n.children) walk(c)
    }
  }

  function matchesBase(node: A11yNode, selector: Selector): boolean {
    if (isTextSelector(selector)) {
      return matchText(node, selector.text)
    }
    if (isIdSelector(selector)) {
      if (selector.id === '') return false
      return node.identifier === selector.id
    }
    if (isLabelSelector(selector)) {
      if (selector.label === '') return false
      return node.label === selector.label
    }
    if (isRoleSelector(selector)) {
      if (node.role !== selector.role) return false
      if (selector.name === undefined) return true
      return matchText(node, selector.name)
    }
    return false
  }

  function matchText(node: A11yNode, pattern: string | RegExp): boolean {
    const candidates: ReadonlyArray<string | undefined> = [node.label, node.value, node.text]
    if (pattern instanceof RegExp) {
      for (const c of candidates) {
        if (c !== undefined && pattern.test(c)) return true
      }
      return false
    }
    if (pattern === '') return false
    for (const c of candidates) {
      if (c === pattern) return true
    }
    return false
  }

  // ---- spatial filters (C5) -----------------------------------------------

  const NEAR_THRESHOLD_PT = 100 // logical points @1x

  type SpatialKey = 'near' | 'below' | 'above' | 'leftOf' | 'rightOf' | 'inside'
  const SPATIAL_KEYS: ReadonlyArray<SpatialKey> = [
    'near', 'below', 'above', 'leftOf', 'rightOf', 'inside',
  ]

  function applySpatialFilters(
    tree: A11yNode,
    candidates: A11yNode[],
    selector: Selector,
  ): A11yNode[] | null {
    let surviving: A11yNode[] = candidates
    const mod = selector as Modifiers
    for (const key of SPATIAL_KEYS) {
      const anchorSel = mod[key]
      if (anchorSel === undefined) continue
      const anchor = resolveSelector(tree, anchorSel)
      if (anchor === null) return null // anchor-not-found = overall null
      surviving = surviving.filter((c) => satisfies(key, c, anchor))
    }
    return surviving
  }

  function satisfies(key: SpatialKey, c: A11yNode, a: A11yNode): boolean {
    if (c === a) return false // self never satisfies own modifier
    const cb = c.bounds
    const ab = a.bounds
    const cc = centroid(cb)
    const ac = centroid(ab)
    switch (key) {
      case 'near':
        return dist(cc, ac) <= NEAR_THRESHOLD_PT
      case 'below':
        return cc.y > ac.y
      case 'above':
        return cc.y < ac.y
      case 'leftOf':
        return cc.x < ac.x
      case 'rightOf':
        return cc.x > ac.x
      case 'inside':
        return contains(ab, cb)
    }
  }

  function centroid(r: Rect): { x: number; y: number } {
    return { x: r.x + r.w / 2, y: r.y + r.h / 2 }
  }

  function dist(p: { x: number; y: number }, q: { x: number; y: number }): number {
    const dx = p.x - q.x
    const dy = p.y - q.y
    return Math.sqrt(dx * dx + dy * dy)
  }

  function contains(outer: Rect, inner: Rect): boolean {
    return (
      inner.x >= outer.x &&
      inner.y >= outer.y &&
      inner.x + inner.w <= outer.x + outer.w &&
      inner.y + inner.h <= outer.y + outer.h
    )
  }

  // ---- index pick (C5) ----------------------------------------------------

  function applyIndex(list: A11yNode[], selector: Selector): A11yNode[] {
    const mod = selector as Modifiers
    // last-defined wins; Modifiers iteration order: first, last, nth
    let picked: A11yNode | undefined
    if (mod.first === true) picked = list[0]
    if (mod.last === true) picked = list[list.length - 1]
    if (mod.nth !== undefined) picked = list[mod.nth]
    if (picked === undefined && mod.first !== true && mod.last !== true && mod.nth === undefined) {
      return list // no index modifier: keep list, caller takes [0]
    }
    return picked === undefined ? [] : [picked]
  }
  ```

  ```markdown
  > C5 起 `resolveSelector` 算法升级为 **collect-all → spatial filter → index pick**

  #### 三段管线

  | 段 | 输入 | 输出 | 行为 |
  |---|---|---|---|
  | base collect-all | `tree, selector` | `candidates: A11yNode[]` | DFS pre-order 收集所有 base 字段命中的节点（顺序与 C4 first-match 收集顺序一致） |

  #### 关系 modifiers（geometry）

  | modifier | 几何 | 阈值 / 算法 |
  |---|---|---|
  | `near` | centroid 欧氏距离 ≤ 100 logical points | 固定 100pt，不自适应；包含等于 |

  | `above` | candidate.centroid.y **严格** < anchor.centroid.y | 同 |
  | `leftOf` | candidate.centroid.x **严格** < anchor.centroid.x | 同 |
  | `rightOf` | candidate.centroid.x **严格** > anchor.centroid.x | 同 |
  | `inside` | candidate.bounds **完整** 落入 anchor.bounds | 4 边闭包含（共边算 inside）；candidate !== anchor by reference（self 排除） |

  - **bounds 单位**：logical points @1x（与 wire 协议章节一致）
  - **centroid**：`{ x: bounds.x + bounds.w/2, y: bounds.y + bounds.h/2 }`
  - **self 排除**：spatial modifier 永不让 candidate === anchor 自匹配（避免单元素树退化）
  - **anchor null fail-fast**：spatial / inside modifier 若 `resolveSelector(tree, anchorSel) === null` → 整体 `resolveSelector` 返 null（**不**抛 ExpectationFailure；与 base 无 match 同语义）

  #### 索引 modifiers

  | modifier | 行为 |
  |---|---|
  | `nth: number` | 取 surviving[nth]；越界 → null |
  | `first: boolean` | 等价 nth=0 |
  | `last: boolean` | 等价 nth=len-1 |

  - **多 index modifier**：first + last + nth 同时给 type 允许但语义冲突，C5 取 **last-defined-wins**（按 `applyIndex` 实现：先 first，再 last，最后 nth 覆盖）；同 Playwright `getByRole(...).first().last()` 行为

  - **`below/above/leftOf/rightOf` 无 alignment 容差**：仅主轴严格序，副轴不约束。Playwright 同语义；想约束副轴对齐用 `inside` 或额外 `near`
  - **`inside` 用 bounds 不用 DOM**：AX tree 在 iOS 17/18/26 上 cell 嵌套形态差异大（C3 决策日志），几何包含跨版本稳定；overlay / popover 场景天然支持
  - **DFS index 不用 bounds 排序**：a11y DFS 顺序与视觉顺序经常不一致（iOS list cell 可能倒序）；用户要视觉顺序用 spatial modifier 组合显式表达
  - **anchor null silent**：与 base 无 match 同语义返 null；C6 matcher 失败时由 driver 层填 `visibleElements` + edit-distance suggestions
  ```

## 关键技术决策

### #1 `near` 阈值 = 固定 100 logical points（centroid 欧氏距离 ≤ 100pt）

| 候选 | 描述 | 影响 | 决策 |
|---|---|---|---|
| **(A) 固定 100pt 阈值** | `dist(centroid_c, centroid_a) <= 100` | 行为可预测；AI 测试作者从 type 签名直接知道 "near = 100pt 内"；iOS Settings cell 高 44pt / 按钮组距 60-80pt / 屏宽 390-440pt 完美覆盖 | **✅ 选** |
| (B) 自适应阈值（基于元素 size） | `max(c.bounds.w + c.bounds.h, a.bounds.w + a.bounds.h)` 或 `0.5 * (c.w + a.w)` 等 | 行为漂移：同一对 (anchor, candidate) 在不同 layout 下 near 阈值变；AI 难写难调；test fixture 必须含 size 才能验 | ❌ |
| (C) 接受 user-tunable 阈值 (Selector.near.threshold?) | `{ near: {selector, threshold: 50} }` | API surface 膨胀（type 改）；冷计划 8 modifier 字面无 threshold 字段；AI 训练语料无 | ❌ |
| (D) bounds 边距 (rect-to-rect) 距离而非 centroid 距离 | 计算两矩形最近边距 | 大 element vs 小 element 不对称（大元素 bounds 触及多）；边距 = 0 还是 "重叠 vs 邻接" 语义模糊 | ❌ |

**理由**：(A) 工程最简 + 行为可预测 + 与 Playwright `near` 同语义（Playwright 也是固定阈值）。100pt 是经验值，源自 iOS Settings 实测（cell 高 44pt × 2 + 间距 = ~100pt）。包含等于（`<= 100`）便于边界值测试。

### #2 `below` / `above` / `leftOf` / `rightOf` = centroid 主轴严格序，副轴无 alignment 容差

| 候选 | 描述 | 决策 |
|---|---|---|
| **(a) centroid 主轴严格序，副轴不约束** | `below`: `c.cy > a.cy` 严格 | **✅ 选** |
| (b) bounds 边比较（`c.top > a.bottom`） | candidate 顶边在 anchor 底边下方 | 同 bounds 大元素场景反直觉：大 anchor 自身高，candidate 必须远离才算 below；centroid 同 row 内部 element 间也能区分 | ❌ |
| (c) centroid + alignment 容差（`|c.cx - a.cx| < 20`） | 主轴序 + 副轴对齐 | 引入二级阈值参数；AI 难写难测；想约束副轴对齐用 `inside` 显式 | ❌ |
| (d) centroid + alignment 容差按 anchor 宽度自适应 | 副轴容差 = `0.5 * anchor.w` | 同 #1.B 漂移 | ❌ |

**理由**：(a) 与 Playwright getByText().filter({below}) 同语义；副轴不约束让 modifier 组合（`below + leftOf`）天然表达"左下方"区域；严格 `>`（含等于不命中）便于边界测试。

### #3 `inside` = bounds 几何包含（**不**用 DOM 包含）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(α) bounds 几何完整包含（4 边闭包含）** | `inner.x >= outer.x && inner.x+inner.w <= outer.x+outer.w && (y 同)` | **✅ 选** |
| (β) DOM 包含（candidate 是 anchor 的子孙节点） | walk tree 找 ancestor === anchor | iOS 17/18/26 cell 嵌套 button 形态差异大（C3 决策日志）；几何方式跨版本稳定；overlay/popover 场景天然支持 | ❌ |
| (γ) 部分相交（intersection 非空） | `c.bounds ∩ a.bounds !== empty` | 太宽松：candidate 横跨 anchor 边缘也算 inside；与"包含"直觉不符 | ❌ |
| (δ) bounds 包含 OR DOM 包含 | 两条 OR | 双语义混乱；C5 严格选一 | ❌ |

**理由**：(α) 跨 iOS 版本稳定 + overlay/popover 天然支持 + AI 测试作者从 type 签名直接知道"inside = bounds 包含"。等于边算 inside（闭包含），便于边界测试。`candidate === anchor by reference` 短路（self 不算 inside 自己）。

### #4 `nth` / `first` / `last` 排序 = DFS pre-order index（与 base collect 顺序一致）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(I) DFS pre-order index** | base collect 时已 DFS 排好；nth=k 取 surviving[k] | **✅ 选** |
| (II) bounds 视觉排序（top-to-bottom, left-to-right） | sort by (y, x) | iOS list cell a11y 顺序经常与视觉顺序不一致（实测 Settings list ascending；某些 List view 倒序）；AI 不可预测 | ❌ |
| (III) 用户给排序 callback | `selector.sortBy?: (a,b) => number` | API 膨胀；不在 type | ❌ |
| (IV) DFS pre-order index after spatial filter | 同 (I) 但在 surviving 上重排 | 与 (I) 等价（surviving 是 candidates 的 filter，filter 保顺序） | (I) 已隐含 |

**理由**：(I) 与 C4 first-match 一致 + 与 base collect 顺序一致 + 可预测；想视觉排序用 `below`/`above`/`leftOf`/`rightOf` modifier 组合显式表达。

### #5 多 modifier 组合 = AND 交集，spatial 按固定 SPATIAL_KEYS 序，index 末位

| 候选 | 描述 | 决策 |
|---|---|---|
| **(P) AND 交集，spatial 固定序施加，index 末位** | candidates → near filter → below filter → ... → inside filter → nth/first/last | **✅ 选** |
| (Q) 按 modifier 在 selector object 中的 key 顺序应用 | 依赖 JS object key 序 | JS object key 序不稳（虽 ES2015+ 大多稳定，但依赖 polyfill / engine 实现）；AI 写时不知道字段顺序影响行为 | ❌ |
| (R) OR 并集 | candidate 满足任一 modifier 即通过 | 与 "modifier = filter" 直觉相反；AI 训练语料里 selector modifier 永远是 AND（Playwright / CSS selector / XPath 同） | ❌ |
| (S) 用户给组合策略 (Selector.combinator?: 'and' \| 'or') | API 膨胀 | YAGNI；型不在 | ❌ |

**理由**：(P) 与 Playwright modifier chain 同语义；spatial 固定序保结果确定（同一 selector 在不同 engine 上行为一致）；first + last + nth 多 index modifier 同给取 last-defined-wins（first → last → nth 覆盖序）。

### #6 base + modifier 关系 = collect-all → spatial filter → index pick → 取 [0]

| 候选 | 描述 | 决策 |
|---|---|---|
| **(W) 先 collect-all base → 用 spatial filter → 再用 nth/first/last 选最终** | C5 三段管线；返 picked[0] ?? candidates[0] ?? null | **✅ 选** |
| (X) 先 first-match base（C4 行为）→ 再判 modifier 是否满足 → 不满足返 null | C4 first-match 扩展 | nth/first/last 无 list 可索引（first-match 只有 1 candidate）；spatial 多个 anchor 时无法 AND | ❌ |
| (Y) base + modifier 同时 collect，不分段 | 单遍 DFS 内同时验 base + modifier | 效率好但代码复杂；anchor selector 递归在每个 candidate 处都得解析（vs C5 一次解析 anchor 多次过滤） | ❌ |
| (Z) collect-all base，spatial 与 index 混合任意序 | spatial 在 index 后施加 | 在 nth=k 后再做 spatial filter 可能让 surviving 为空（k 已过滤后再 filter 空了）；语义混乱 | ❌ |

**理由**：(W) 与 (P) 协同；nth/first/last 在 surviving 上做索引才有意义；anchor selector 一次解析复用多次过滤效率好；base-only 时 candidates[0] === C4 DFS first（C4 行为兼容）。
