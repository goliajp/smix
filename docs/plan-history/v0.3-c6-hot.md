### S1. 核心实现 — `resolveSelectorAll` + `SimctlDriver` 4 stub 真实现 + `tap` 路径 B + 注入 host-hid spawner

> **决策依据（见末尾"关键技术决策"表 #1-#6）**：
> - **双路径 tap 决策（#1）**：plain text-only selector 数量在真测试中占多数（v0.2 C6 e2e + acceptance `tap_text_selector_e2e:ok` 是 v0.2 出口证据），保留 runner /tap 路径 A 避免 regression；其他 selector 形态走 resolveSelector + host-hid 路径 B。单一判断点 `isPlainTextSelector(s)` 复用 v0.2 C6 既有 helper（已在 `simctl-driver.ts` 实现）
> - **host-hid spawn 决策（#2）**：每 tap fresh `execFile` `simx-host-hid` binary，cold start ~50ms（C4 实测 100ms tap hold ≈ total 150ms 端到端），可接受；pool / persistent 会引 SimDeviceLegacyHIDClient lifecycle 管理（rebind on sim restart），与 v0.4-v0.6 Cell 改造耦合；C6 简单方案先通
> - **bounds 归一化决策（#3）**：tree root 是 `XCUIApplication.snapshot()` 的根节点，其 `bounds.{w,h}` = `app.frame.size`（C1 决策 + TreeRoute.swift `appFrame` 在场即 `app.frame`）；host-hid 既有接口接受 0-1 normalized x/y（`SimxHostHIDArgs.swift` 实测），无需 device screen size 查询；若 candidate.bounds 全 0（屏幕外或空 frame），归一化得 nx/ny = 0 — 这种 candidate 在 resolveSelector 视角上仍是有效 match（matchesBase 与 bounds 无关），但 host-hid 0/0 落地点是屏幕左上角，可能误触；C6 加 pre-tap guard：归一化 (nx, ny) ∈ (0,1) 之外 / candidate.bounds.w·h == 0 → 抛 ELEMENT_NOT_FOUND with hint "matched node is offscreen / has empty frame"（这是真 sim 下大概率不发生的边界，C6 单测 mock 验路径 B 行为，e2e 验典型路径）
> - **waitFor 策略决策（#4）**：poll 200ms（与冷计划字面同）/ 默认 5000ms total（v1.md §4 "[3] 冷启动 < 5s" 隐含 single tap waitFor budget 不应超 5s）；超时抛 `TIMEOUT`，hint 指向 `app.describe()`；不可重写 timeout=0（"single-shot" — FindOptions.timeout=0 退化为 1 次 findOne 不 poll，与 v0 FindOptions 注释一致）
> - **findAll 决策（#5）**：复用 dfsCollect + applySpatialFilters，不施加 index pick；index modifier 给 findAll 时**忽略**（不抛错；type 允许，driver 取舍 — 与 Playwright `locator(...).all()` 行为同：index modifier 在 multi 上无意义）
> - **依赖注入决策**：driver ctor `deps?: { runnerClient?, hostHidSpawner? }` 加新字段（与 v0.2 C6 既有 `runnerClient` 同形态）；默认走 `node:child_process.execFile` 包 wrapper 调 `swift-bridge/.build/debug/simx-host-hid`；测试时 mock；与 SimctlClient 既有 spawnBinary 同 type（`BinarySpawner`），避免引第二种 wire

  private async tapViaResolver(selector: Selector): Promise<void> {

    const node = resolveSelector(tree, selector)
    if (node === null) {
      throw new ExpectationFailure({
        code: 'ELEMENT_NOT_FOUND',
        message: `element not found: ${describeSelector(selector)}`,

        code: 'ELEMENT_NOT_FOUND',
        message: `matched node has empty / offscreen frame: ${describeSelector(selector)}`,

        message: `matched node centroid out of app frame: ${describeSelector(selector)}`,
        selector,

      })

  async waitFor(selector: Selector, timeoutMs?: number): Promise<A11yNode> {
    const total = timeoutMs ?? 5000
    const interval = 200
    const deadline = Date.now() + total
    // single-shot path
    if (total <= 0) {
      const node = await this.findOne(selector)
      if (node !== null) return node
      throw new ExpectationFailure({
        code: 'TIMEOUT',
        message: `waitFor(${describeSelector(selector)}) timed out after ${total}ms`,
        selector,
        hint: 'call app.describe() to inspect the current screen; selector may be wrong',
      })
    }
    while (true) {
      const node = await this.findOne(selector)
      if (node !== null) return node

          code: 'TIMEOUT',
          message: `waitFor(${describeSelector(selector)}) timed out after ${total}ms`,
          selector,
          hint: 'call app.describe() to inspect the current screen; selector may be wrong',
        })
      }
      await new Promise((resolve) => setTimeout(resolve, interval))
    }

## 关键技术决策

### #1 non-text selector tap transport = **双路径**（plain text-only 走 runner /tap；其他走 host-hid by coord）

| 候选 | 描述 | 影响 | 决策 |
|---|---|---|---|
| **(A) plain text-only → runner /tap；其他 → resolveSelector → host-hid by coord** | 路径 A 保 v0.2 C6 既有 runner /tap 路径（NSPredicate label==% OR identifier==%）；路径 B 是 C6 新增 host-hid 路径。`isPlainTextSelector` 单一判断点（v0.2 C6 既有 helper） | 保 v0.2 C6 e2e + acceptance `tap_text_selector_e2e:ok` 不破（runner /tap 是已 prove 的快路径）；新 selector 形态走 host-hid 真打通 selector resolver → coord 通路 | **✅ 选** |
| (B) 全部 selector → resolveSelector → runner /tap by label | resolveSelector 命中后取 node.label 走 runner /tap | id selector 无 label 时退化失败；role selector 不一定 label 等值；舍弃 selector → coord 通路 = 浪费 C5 几何 modifier | ❌ |
| (C) 全部 selector → resolveSelector → host-hid by coord（含 plain text-only） | 路径 B 一统天下 | v0.2 C6 既有 runner /tap 路径退化为冗余；acceptance `tap_text_selector_e2e:ok` 行为变（runner /tap 不再被生产路径调用，只剩 health probe）；regression 风险高 | ❌ |
| (D) selector type 加 `transport?: 'runner' \| 'hid'` 字段 | API 表面 | selector 是用户写的 / AI 写的，transport 不应外露 | ❌ |

**理由**：(A) 保 v0.2 C6 既有 e2e 行为不破 + 新 selector 形态走真"selector → coord"端到端通路 + 不污染 selector type 表面。C7 / v0.4 决策反转时可在 plan 内决策日志单行说明（如统一为 host-hid，会破 acceptance 字段需要新 acceptance 字段一起改）。

### #2 host-hid spawn = 每 tap fresh `execFile`（无 pool / 不 persistent）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(α) 每 tap fresh `execFile` `simx-host-hid tap ...`** | 同 v0.2 C4 既有 host-hid smoke 模式 | **✅ 选** |
| (β) Long-lived host-hid child process + stdin JSON request / stdout JSON response | spawn 一次，N tap 复用；省 ~50ms × N | host-hid 当前 binary 是单次 tap-then-exit 设计；改 long-lived 要 swift-bridge 改 stdin loop + line-delimited JSON wire（与 C6 "0 swift 改动" 约束冲突）；推 v0.7+ HID 优化 | ❌ |
| (γ) Pre-spawn pool（N idle child 处理 next request） | 同上 (β) 改造 + pool 调度 | 更复杂；YAGNI | ❌ |
| (δ) Driver 持有 host-hid 进程 ref，drop 时 kill | 同 (β) + lifecycle | 与 Cell allocator (v0.4-v0.6) 耦合，C6 先简单 | ❌ |

**理由**：(α) 简单 + 与 v0.2 C4 / acceptance `hostid_digitizer_smoke:ok` 同模式 + 0 swift 改动 + cold start ~50ms 可接受（典型 v1.md §4 [4] iOS 26 单 tap < 50ms 是 indigo9 直路径预算，digitizer 路径实测 100ms hold + 几十 ms IOHIDEvent 序列；fresh execFile 加 50ms cold start 仍在 200ms 以内一档，可接受）。

### #3 bounds 归一化 = **tree root.bounds**（= XCUIApplication.snapshot 根 frame = app.frame）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(I) `nx = (b.x + b.w/2) / root.w`, `ny = (b.y + b.h/2) / root.h`** | 用 tree 根节点 bounds 做分母；root.bounds = XCUIApplication.snapshot().frame = app.frame（C1 决策 + TreeRoute.swift 在场） | **✅ 选** |
| (II) 用 device screen size（`xcrun simctl io <udid> screenshot --type=pixmap` 取 dim） | 引 1 个额外 simctl 调用 + 通常 device pixel ≠ logical points（@2x / @3x scale）；归一化分母不对 | ❌ |
| (III) host-hid CLI 加 `--width / --height` 参数让 binary 自己查 device frame | 改 swift / 违反 0 swift 改动约束 | ❌ |
| (IV) candidate.bounds.centroid 直接传 (无归一化) + host-hid CLI 加 `--absolute` 模式 | 改 swift；与既有 `--x` `--y` 0-1 normalized 接口冲突 | ❌ |

**理由**：(I) 0 新调用 + 0 swift 改动 + 几何上正确（XCUIApplication.snapshot 是 host-side 的 app frame，与 host-hid digitizer 路径的 normalized coord 同 frame 系）。candidate bounds 全 0 / 越界时加 ELEMENT_NOT_FOUND guard（offscreen / empty frame，hint 明确指 "element offscreen"），避免 0/0 误触屏幕左上角。

### #4 waitFor 策略 = poll 200ms / 默认 5000ms total

| 候选 | 描述 | 决策 |
|---|---|---|
| **(P) poll 200ms / total = timeoutMs ?? 5000ms** | 与冷计划字面 "waitFor / 自动 poll 真生效" + v1.md §4 [3] 5s 冷启动预算一致 | **✅ 选** |
| (Q) exponential backoff (50ms → 100 → 200 → ...) | 第 1 次极快，后期慢；适合长 wait 但短 wait 几乎无差；C6 简单方案先通 | ❌ |
| (R) timeoutMs ?? 30000 / 长 default | 测试套件总耗时长；与 v1.md §4 [3] 5s 预算冲突 | ❌ |
| (S) 同步 busy-loop（无 sleep） | CPU 烧；不可接受 | ❌ |

**理由**：(P) 与 v1.md §4 [3] "冷启动延迟：simx run 到首 tap 完成 < 5s" 对齐 + Playwright 同语义（default timeout 5s）+ poll 200ms 是经验值（够细让测试快 fail，够粗不烧 CPU / 不烧 RunnerClient 负载）。**timeoutMs=0 是 single-shot**（FindOptions.timeout=0 注释合规 + 与 findOne 退化等价）。**timeoutMs 不抛 ELEMENT_NOT_FOUND 而抛 TIMEOUT**（语义区分：findOne 即时查 = ELEMENT_NOT_FOUND，waitFor 等不到 = TIMEOUT；FailureCode 已有 'TIMEOUT'）。

### #5 findAll = **dfsCollect + applySpatialFilters，不施加 index pick**

| 候选 | 描述 | 决策 |
|---|---|---|
| **(W) 复用 dfsCollect + applySpatialFilters；index modifier (nth/first/last) silent ignore** | sibling export `resolveSelectorAll`；与 resolveSelector 共享前两段管线 | **✅ 选** |
| (X) `findAll` 严格不接 index modifier（type 不允许 / 接到抛错） | type 已 allow（Modifiers 在 Selector 上），driver 层抛错破 SDK 表面 | ❌ |
| (Y) `findAll` 真施加 index modifier (nth=k 时返 length=1 数组) | "find all" + index pick 语义自相矛盾；Playwright `.all()` 不应用 index | ❌ |
| (Z) 全文 deep clone 后 mutate 取消 index 字段 | 复杂；浪费 | ❌ |

**理由**：(W) 与 Playwright `locator(...).all()` 同语义 + 与 resolveSelector 共享 80% logic + selector type 表面不改（用户写 `{text:'X', first:true}` 在 findOne 上取 first，在 findAll 上忽略 first 是用户预期）。

### #6 examples/_v03-pending/login.test.ts 推 C7（C6 不挑回）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(α) examples/login.test.ts 推 C7** | C6 出口仅 e2e smoke + driver 单测；C7 时把 examples 挑回 + fill 字段合理化为 tap-only 子集（HID 键盘 fill v0.7+） | **✅ 选** |
| (β) C6 即挑回 login.test.ts | 但 fill 字段需 HID 键盘（v0.7+），等于挑回后 skip 一半 case；散乱 | ❌ |
| (γ) login.test.ts 改写为纯 tap selector 测试 | C6 不动 examples（保 v0 既有形态完整给 C7 处理） | ❌ |

**理由**：(α) 冷计划 §C7 字面 "examples/login.test.ts 完整跑通含 selector + tap + fill" — C7 是 examples 收尾 checkpoint，C6 维持 4 stub + tap 升级 1-3 step 范围。fill 字段在 v0.7 HID 键盘前都是无效（Driver.fill 仍 stub），强行挑回 examples 会让 example test 半途 throw（违反 examples 黄金路径原则）。
