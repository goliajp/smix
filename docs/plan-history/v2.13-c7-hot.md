# plan-hot — v2.13 到 C7：把循环装进会话,并让 app 死掉成为一件事件

## 目标 checkpoint

C7：`skills/drive` `skills/author` `skills/diagnose` 三个 skill 随 plugin 装上,
Claude Code 按上下文自动调起;`monitors/monitors.json` 让 runner 掉线或 app 崩溃
变成一条通知,而不是等到下一次 tool 调用才以「元素找不到」的面目出现。
**贯穿不变量机器化**:skill 里教的每一条 smix 命令,人在终端都能原样敲。

## 前置条件

```bash
python3 scripts/dev/plugin-structure.test.py     # C5/C6 的结构闸门在
./target/release/smix --help | head -1
ls plugin/skills 2>/dev/null || echo "(还没有 skill)"
```

## 步骤（线性,3 步）

### S1. 不变量的机器判据先立起来

**红（写测试）**
- 文件：`scripts/dev/plugin-capability-parity.test.py`
- 断言：
  - 扫 `plugin/skills/**/SKILL.md` 里出现的每一条 `smix <子命令>`，
    与 `smix --help` 真实子命令表比对，**不存在的即失败**
  - 扫每一个 `smix_<tool>`，与 MCP server 的 `tools/list` 比对
  - skill 里若出现 `xcrun simctl` / `adb` 的可变动词 → 失败
    （plugin 不该教用户绕过自己的护栏）

**绿（实现）**
- 先写检查，此时无 skill 目录 → 应报「没有 skill 可检查」并失败，
  这样它不会在空目录上假绿

**重构**
- 无

### S2. 三个 skill

**红（写测试）**
- 扩充 `plugin-structure.test.py`：三个目录各有 `SKILL.md`，各有 frontmatter `description`
- S1 的 parity 检查此时必须真跑到内容（断言扫到的命令数 > 0）

**绿（实现）**
- `drive`：从零到能操作（`smix_devices` → `smix_use` → 感知 → 操作）；先看后动
- `author`：把手工驱动变成可重跑的 flow（`smix authoring record --app-id` → `smix run`）
- `diagnose`：一步失败了怎么读（visibleElements / suggestions / 截图 / tree）
- 关键点：**只教 core 已有的动词**；每条都能在终端原样敲

**重构**
- 无

### S3. monitor：掉线是事件

**红（写测试）**
- 文件：`scripts/dev/plugin-monitor.test.sh`
- 断言（无设备，靠一个本地假 health 端点）：
  - 端点在 → 不输出（stdout 每行都是通知，安静是默认）
  - 端点从在到不在 → 输出一行且含端口号
  - 端点始终不在 → 输出**至多一行**（不刷屏）

**绿（实现）**
- `plugin/scripts/watch-runner.sh` + `plugin/monitors/monitors.json`
  （`when: on-skill-invoke:drive`，不驱动时不watch）

**重构**
- 无
