## 7 决策答案（含拒绝路径，每条必答）

### 决策 1：schema 字段集

**答**：每行 JSON 字段 = `{ts, seq, type, args, ok, duration_ms[, err]}`。

- `ts: number` — `Date.now()` ms epoch（写入 record 那一瞬间）
- `seq: number` — 1-based 整数，每 case 重置（与 PNG `<NNNN>-screenshot.png` 序列 **独立**——决策 5）
- `type: string` — Driver 方法名（决策 2 锁定 24 集合）
- `args: object` — 经决策 6 清洗后的参数对象（永远 object，无 args 时 `{}`）
- `ok: boolean` — true 当 base.method 正常 resolve；false 当 base.method throw
- `duration_ms: number` — `Date.now() - start`（含 throw 时也记，让 AI 看到 timeout 类失败的实际等待时间）
- `err?: string` — 仅 `ok=false` 时存在；值 = `err instanceof Error ? err.message : String(err)`

**不**含字段：
- 拒绝（A）`screenshot_seq` 字段（C5 才有 per-step PNG，C4 加是预测——AI 看到无对应文件反误导；决策 5 选拆开 PNG/jsonl seq 后此字段失意义）
- 拒绝（B）`stack` (Error stack)：stack 长 + machine-noisy，AI 喂不友好；`err.message` 足够定位
- 拒绝（C）`return: <value>` 字段：mutating return 多数 `void`；`pasteboardGet` return string 也不记（隐私 + AI 用不上）
- 拒绝（D）`selector` 顶层字段：selector 已在 `args` 子对象内，顶层是冗余
- 拒绝（E）`pid` / `bundleId` 顶层：同 D

理由：最小可消费集 + 与 v0.6 `failure.json` 字段名规约一致（`ts` / `ok` / `err`）让 AI 跨 trace 双形态识别。

### 决策 2：哪些 Driver 方法记入 steps.jsonl

**答**：候选 A — **仅 mutating actions**。共 24 个 method 名（F5 已列）。**不**记：`tree` / `findOne` / `findAll` / `describe` / `waitFor`（5 read-only）。

理由（F5/F6）：
- 拒绝（B）"A + read-only 全部"：matcher 内 pollFor 每 50→500ms 调一次 `findOne`，1 个 toBeVisible 在 5s 窗口产生 ~30-50 个 findOne 行；100 case 跑下来 jsonl 文件 5MB+，AI 上下文吃不下。
- 拒绝（C）"A + 失败时的 describe"：matcher.ts `safeDescribe` 已封装 describe 调用，状态机由 matcher 拥有；TracingDriver 不知 "这是 matcher 失败 path 的 describe" vs "用户手动 app.describe()"，无法选择性记。C6 才会把 `describe() snapshot` 通过 `failure.json` 落盘。
- 拒绝（D）"A + screenshot 排除"：screenshot 是 mutating-ish（sim IO + 已落 PNG），记入让 AI 看到时序对齐 PNG 文件名；不记反破 C5 future PNG-vs-step 一对一假设。
- **`pasteboardGet` 算 mutating**：判定准则 = "用户直接调它代表显式操作意图" → 是 = 记。`pasteboardGet` 不改 state 但需要 sim IO，归 mutating 以记录用户行为时序（用户在测试里写 `await app.pasteboardGet()` 是显式操作，应记）。

### 决策 3：写入层 = 扩 `trace-sink.ts` vs 新文件 `step-sink.ts`

**答**：**扩 `trace-sink.ts`**，加 `appendStep(sink, record)` + `StepRecord` type。

理由：
- `trace-sink.ts` 已是"matcher / driver / cli 三方共消费的写盘单点"（C2 决策日志，v1.md line 147）；C6 也将复用同文件加 `writeFailureJson`。一个文件管 `.simx/trace/<case>/` 下 3 类产物（`failure-NNNN.png` / `steps.jsonl` / `failure.json`）符合"单一事实源"原则。
- 拒绝（A）"新文件 `step-sink.ts`"：两套 module-private singleton（`activeSink` vs `activeStepSink`）+ 两套 `set/clear/get` API + 两套 seq map = 重复抽象；run.ts onCaseStart 要调两次 set。
- 拒绝（B）"`TracingDriver` 自己持 jsonl path 写盘，不走 trace-sink"：那 sink lifecycle 由 TracingDriver 拥有，但 sink 真生命周期在 case（beginCase / clearTraceSink）—— 与 matcher 同源处理更对。
- 拒绝（C）"AsyncLocalStorage"：单 process 串行下与 module singleton 等价，引入 ALS = 多余复杂度（C2 决策日志已拒此路径）；v1.1 并行 Cell 时再考虑。

### 决策 4：写入时机 + crash flush

**答**：**每 action 同步 `fs.appendFile` + 不需要显式 flush**。

- 每行调用：`await appendFile(path, JSON.stringify(record) + '\n')`（`node:fs/promises`，append mode，单线程 process 内顺序保证）
- 不缓冲：avoid batch flush 因 1 个 action 1 行的成本 ~10KB/s 写入，磁盘 IO 不是瓶颈
- crash 处理：appendFile 每次写盘 = process kill / OOM 时已落盘的行不丢；正在 await 的 promise 内容可能丢一行（无对策——这是 stdlib appendFile 的天然语义，与 C2 PNG 同处理）
- AsyncLocalStorage：决策 3 已拒，不引入

理由：
- 拒绝（A）batch flush 每 N 行：N 行未落盘时 process exit → 丢；增量代码 + 失败窗口反而扩大
- 拒绝（B）显式 `fd.sync()`：appendFile 已隐含；过度优化无证据
- 拒绝（C）写 tmp + rename：jsonl 是 append-only 文件，不需原子替换；rename 形态适合 failure.json (C6) 整体 write

### 决策 5：seq counter 与 PNG counter 关系

**答**：**完全独立**。`steps.jsonl` 的 `seq` 字段在 `trace-sink.ts` 内由新 `stepSeqByCase: Map<string, number>` 维护（与 failure PNG 的 `seqByCase` 同形态独立 map）；`TracingDriver.screenshot()` 的 `this.seq` 仍管 `<NNNN>-screenshot.png` 文件名计数（v0.2 C6 起的语义不动）。

理由：
- C5 计划在每个 mutating action **之后** 自动截屏 → 那时一个 step 对应一个 PNG，但**这是 C5 范围**；C4 阶段 PNG 仅来自显式 `app.screenshot()` 调用，PNG 计数与 step 计数语义不同。
- 拒绝（A）"复用 TracingDriver.seq 同时记 PNG + step"：当前 `screenshot()` 增 seq 后写 `0001-screenshot.png`；其他 action 也增 seq 会改 PNG 文件名意义（不再是"第 N 次截图"），破 v0.2 C6 既有 acceptance（`0001-screenshot.png` 一对一）。
- 拒绝（B）"step seq 在 TracingDriver 内维护"：state 在两处（trace-sink 管 sink + TracingDriver 管 stepSeq）违反"单一事实源"；放 trace-sink 统一管 lifecycle（setTraceSink 重置 stepSeq + failureSeq 两个 map）。
- C5 接 PNG-step 一对一时再决定（可能：C5 让 `step-<NNNN>.png` 使用 step seq；现有 `<NNNN>-screenshot.png` 名义保留用户显式 `screenshot()` 调用）—— C4 不预判。

### 决策 6：args 清洗与 RegExp / Function 处理

**答**：所有 args 调用一个 `sanitizeArgs(value)` 浅递归清洗函数后 JSON.stringify：

```ts
function sanitizeArgs(v: unknown): unknown {
  if (v instanceof RegExp) return { __regex: v.source, flags: v.flags }
  if (Array.isArray(v)) return v.map(sanitizeArgs)
  if (v !== null && typeof v === 'object') {
    const out: Record<string, unknown> = {}
    for (const [k, val] of Object.entries(v as Record<string, unknown>)) {
      out[k] = sanitizeArgs(val)
    }
    return out
  }
  return v
}
```

应用于 args 的所有顶层字段。

理由（F7）：
- selector 可能含 `text: /Sign in/i`（RegExp），原生 `JSON.stringify(/x/) === '{}'`；清洗为 `{__regex: 'Sign in', flags: 'i'}` 让 AI 看出意图。
- 拒绝（A）"toString RegExp"：`/Sign/i.toString() === "/Sign/i"` 是字符串形态可读但 AI 难再解析为对象/regex；object 形态结构化更好。
- 拒绝（B）"深拷贝 + 过滤所有非 plain"：增量代码 ~30 行未必必要；浅递归 (RegExp + Array + Plain Object 三档) 覆盖 v0.4 所有 Driver 入参形态。
- 拒绝（C）"args.fill 的 text 字段截断长度"：长 text (fill 1000 字符) 偶发但不在 v0.4 e2e 路径；C5/C6 时再加阈值。

### 决策 7：错误处理 + 抛错 rethrow 时机

**答**：TracingDriver 内每个 mutating wrap 严格序列：

```ts
async tap(s: Selector): Promise<void> {
  const start = Date.now()
  let err: string | undefined
  try {
    await this.base.tap(s)
  } catch (e) {
    err = e instanceof Error ? e.message : String(e)
    throw e
  } finally {
    await this.recordStep('tap', { selector: s }, err === undefined, start, err)
  }
}
```

要点：
- `await this.recordStep(...)` 放 `finally` 块——保证不论 throw / resolve 都记一行
- `recordStep` 内自己读 `getTraceSink()`，sink 缺失 silent no-op（与 matchers.ts 同语义）
- recordStep 内部 fs 错也 catch 后 silent（**不**掩盖 action throw；与 C2 `writeFailurePng` 路径一致）
- `throw e` 在 catch 内的语义：finally 先完整执行（含 await recordStep），然后再让 throw 自然冒泡

拒绝路径：
- 拒绝（A）"action throw 时不记 step"：丢失"测试卡在第 N 步"信息，与 cold plan "AI-readable" 矛盾
- 拒绝（B）"appendStep 失败时 wrap 成 ExpectationFailure rethrow"：trace 写失败不应破测试；silent + 可选 console.warn（C4 选不加）
- 拒绝（C）"在 catch 前 append (start time 已记，end time 在 throw 前抢一份)"：finally 写法等价且代码更短
- 拒绝（D）"通过 Proxy 自动 wrap 所有 mutating method"：Proxy 难以与 TS 严格类型 + Driver interface 双向一致；显式 wrap 24 method 各 +6 行 ≈ 150 行的代价但可读 + 静态可检
- **`screenshot()` 的特殊处理**：既有写 `<NNNN>-screenshot.png` 逻辑保留；C4 在 `screenshot()` finally 内 append step `type:'screenshot'`，args=`{}`。错误处理同上。

```ts
/**
 * A single Driver action record written to steps.jsonl.
 * Schema is wire-stable; see docs/design.md §steps.jsonl wire schema (added C4).
 */
export type StepRecord = {
  readonly type: string
  readonly args: unknown
  readonly ok: boolean
  readonly durationMs: number
  readonly err?: string
}

// Shallow recursive sanitization: RegExp → {__regex, flags}; arrays / plain
// objects recurse one level. Primitives untouched. Functions / non-plain
// instances fall through to JSON.stringify's default behavior.
function sanitizeArgs(v: unknown): unknown {
  if (v instanceof RegExp) return { __regex: v.source, flags: v.flags }
  if (Array.isArray(v)) return v.map(sanitizeArgs)
  if (v !== null && typeof v === 'object') {
    const out: Record<string, unknown> = {}
    for (const [k, val] of Object.entries(v as Record<string, unknown>)) {
      out[k] = sanitizeArgs(val)
    }
    return out
  }
  return v
}

/**
 * Append one JSON line to `<traceRoot>/<caseSlug>/steps.jsonl`.
 * Callers (TracingDriver) silence fs errors so trace-write failures
 * never mask the underlying action's throw.
 */
export async function appendStep(
  sink: MatcherTraceSink,
  record: StepRecord,
): Promise<void> {
  const next = (stepSeqByCase.get(sink.caseSlug) ?? 0) + 1
  stepSeqByCase.set(sink.caseSlug, next)
  const line = {
    ts: Date.now(),
    seq: next,
    type: record.type,
    args: sanitizeArgs(record.args),
    ok: record.ok,
    duration_ms: record.durationMs,
    ...(record.err !== undefined ? { err: record.err } : {}),
  }
  const dir = join(sink.traceRoot, sink.caseSlug)
  const out = join(dir, 'steps.jsonl')
  await mkdir(dir, { recursive: true })
  await appendFile(out, JSON.stringify(line) + '\n')
}
```
