### S2. v0.2 整体出口验收脚本 + README + roadmap（红→绿）

> **决策依据（见末尾"关键技术决策"表 #1 #2 #5）**：v0.2 closure 需要单一证据；C7 acceptance 脚本串 9 个 endpoint，是**唯一** v0.2-level 真验收脚手架。前 8 个 endpoint 已存在；新增的工作是**编排 + 单行 JSON 汇总**。脚本不重复实现（不并行启 2 个 xcodebuild test runner），按以下顺序串行：
>
> 1. swift test（包 path）—— 不依赖 sim runner，最快
> 2. bun run typecheck —— 不依赖 sim runner，~3s
> 3. bun run test —— 不依赖 sim runner，~1s
> 4. bun src/cli/index.ts doctor —— 不依赖 sim runner，~3s（含 simx-host-hid probe 子调用）
> 5. simx-host-hid probe —— 独立 binary，不需要 runner
> 6. `scripts/simx-c6-tap-e2e.sh` —— **它**内部启 runner + 跑 tap-text-selector + 双面 probe（已含 runner health / runner tap / 真 UI 跳页 = 等价 endpoint 5/6/7 在脚本内合并；为避免后台 runner race，C7 acceptance 选**只跑 c6-e2e**，覆盖原 8 个 endpoint 中的 health + runner tap smoke + hostid digitizer smoke + tap_text_selector_e2e 4 项的功能子集；前 3 个独立 script 不再单独串——它们是 c6-e2e Phase 内的子集，重复跑 = 3 个 xcodebuild test 启动 = 3 × 90s = 4 min cold start，CI 不友好）
> 7. `scripts/simx-hostid-digitizer-smoke.sh` —— **跳过单独跑**，理由同上（host-hid digitizer smoke 与 c6-e2e 是不同 transport，但都依赖同一个 runner — 串行跑会触发 runner 重启）。**改在 acceptance 末尾追加一句 hostid digitizer smoke**：c6-e2e 跑完后 runner 已起，**复用同一 runner port** 跑 hostid digitizer tap → 这是真验证两条 transport 都工作的最便宜方式
>
> 综上：脚本结构（4 Phase，单一 xcodebuild test 启动，多 endpoint 复用）：
> - Phase 1 — 离线检验：swift test / typecheck / bun test / doctor / host-hid probe（5 endpoint）
> - Phase 2 — 启 runner 并 wait health（200）
> - Phase 3 — 跑 `bun src/cli/index.ts run examples/tap-text-selector.test.ts`（驱动 SDK → real UI tap），完后双面 probe 验真跳页
