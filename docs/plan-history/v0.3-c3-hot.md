### S1. TS 侧 — `elementTypeNameToRole` + `A11yTreeSource` interface + `RunnerClient.getTree()` batch fill `role`

> **决策依据（见末尾"关键技术决策"表 #1-#3）**：
> - **桥接选 (a) TS 侧加函数，不改 Swift wire**（决策 #1）：Swift wire 已稳定（C1 19 swift tests + smoke 通），改 wire schema 会破 C1 baseline；TS 侧加 `elementTypeNameToRole` 是 1 个 5-行函数复用既有 `XCUIElementType` 表反查，**0 编译时双侧维护成本**。
> - **eager batch fill，不 lazy**（决策 #2）：调用方期望 `A11yNode.role` 就在，每节点 1 次 O(1) 查表（`XCUIElementType` 表 ~60 个 entry，反查 O(60)），整棵树 167 node × 60 = ~10k 次比较 < 1ms；lazy（每次访问翻 = N 次同样 cost + 状态机复杂度）= 负债。post-processor 形态：递归 walk，原地覆盖 role 字段，类型从 `A11yNode`（role: Role | undefined）保持。
> - **`A11yTreeSource` 单方法 v0.3，多设备推 v0.4+**（决策 #3）：v0.3 单 dev sim 单 runner；Cell allocator 在 v0.4-v0.6 retrofit，那时 `getTree()` 形态变 `getTree(cellId?)` 或 `A11yTreeSource` 由 Cell 持有；C3 加多余参数 = YAGNI。
> - **结构等价 implements，不显式声明**（决策 #4）：TS structural typing 让 `RunnerClient` 自动满足 `A11yTreeSource`（已有 `getTree(): Promise<A11yNode>`）；显式 `class RunnerClient implements A11yTreeSource` = 强耦合 + 改 RunnerClient 签名时 cascade error 不便。
> - **`role` 在 `A11yNode` type 已是 optional**（决策 #5）：`screen.ts` line 16 `role?: Role`——C3 只需写入即可，**不**改 type 定义；isA11yNode 守卫**不**强制 role 在场（C1 已注 "Optional fields (identifier/label/value/text/role) are not required at this layer"）。

  ```typescript
  /**
   * String variant of elementTypeToRole — accepts the raw element-type name
   * (e.g. "button", "staticText") emitted on the wire by SimxRunner's
   * /tree route (v0.3 C1 TreeRoute.elementTypeName).
   *
   * Returns the same Role | undefined contract as elementTypeToRole(value:number):
   * - In XCUIElementType table AND in KNOWN_ROLES → Role
   * - In table but not KNOWN_ROLES (e.g. 'other', 'group', 'window') → undefined
   * - Not in table (typo or new iOS type) → undefined
   *
   * Why string variant: the wire emits string (TreeRoute.swift:160) — keeping
   * a string accessor avoids name→number→name round-trip and double-maintains
   * one table on TS side.
   */
  export function elementTypeNameToRole(rawType: string): Role | undefined {
    if (!(rawType in XCUIElementType)) return undefined
    const candidate = rawType as Role
    return KNOWN_ROLES.has(candidate) ? candidate : undefined
  }
  ```

     * Walk the tree once and assign `role` from `rawType`. In-place to avoid
     * a full deep clone (trees can be ~200 nodes; clone would be O(N) extra).
     * Overwrites any pre-existing role on the wire — role is always derived

## 关键技术决策

### #1 桥接策略：TS 侧加 `elementTypeNameToRole(rawType: string)` —— 选 (a)，**拒** (b)/(c)

| 候选 | 描述 | 影响 | 决策 |
|---|---|---|---|
| **(a) TS 侧加 string→Role 函数** | `elementTypeNameToRole(rawType:string)` 复用既有 `XCUIElementType` 表 + `KNOWN_ROLES` 反查 | 0 Swift 改动；Swift wire schema 0 变化；C1 19 swift tests + smoke 0 退化；TS 加 ~5 行函数 + ~5 行 batch fill | **✅ 选** |
| (b) Swift 改 wire 加 raw value number | TreeRoute.serialize 改 `out["rawType"] = elementTypeName(d.elementTypeRawValue)` → 加 `out["rawTypeValue"] = Int(d.elementTypeRawValue)` 或全替；TS 侧用既有 `elementTypeToRole(value:number)` | 破 C1 wire schema；smoke jq 'rawType=="application"' 字符串断言要改；C1 19 swift tests TreeRouteTests 验 string name 要改 → 退化风险高 | ❌ |
| (c) Swift 改 wire 加 role 字段 | TreeRoute 内维护 elementTypeRawValue → Role 字符串第二张表，wire 出 `out["role"] = "button"` | 双侧维护两份翻译表（Swift 一张 + TS 既有一张）；KNOWN_ROLES 在 TS 侧的 fine-grained 控制要在 Swift 复制；冷计划 prompt 模板 "Role 翻译表已经在 src/core/role.ts，直接复用（不要重写）" 直接违反 | ❌ |

**理由**：(a) 工程量最小 + 0 wire 破坏 + 0 双侧维护 + 严格遵守冷计划 prompt 模板"复用 src/core/role.ts"。

### #2 role fill 时机：`RunnerClient.getTree()` 内 eager batch，**不** lazy

| 候选 | 描述 | 决策 |
|---|---|---|
| **(a) eager batch fill** | `getTree()` 内 isA11yNode 守卫通过后调 `fillRolesInPlace(root)`，递归 O(N) 覆盖 role | **✅ 选** |
| (b) lazy（getter / proxy） | `A11yNode` 成员 `get role()` 按需算 | 改 type 形态；运行时 cost 相同但状态机复杂；C4+ resolver 用时还得拷贝 | ❌ |
| (c) 推到 C4+ resolver 内做 | C4 selector resolver 用前才 fill | C4 内单测无法验单纯 wire 协议；smoke 也验不到 role；违反冷计划"C3 协议固化 + Role 翻译" | ❌ |

**性能**：树 ~167 node × `XCUIElementType` 表 ~60 entry = ~10k 次比较 = sub-millisecond（vs P50 < 20ms target）。

### #3 `A11yTreeSource` 形态：单方法 `getTree(): Promise<A11yNode>`

| 候选 | 描述 | 决策 |
|---|---|---|
| **(a) 单方法** | `interface A11yTreeSource { getTree(): Promise<A11yNode> }` | **✅ 选**（v0.3 单 dev sim 单 runner；多设备推 v0.4-v0.6 Cell allocator） |
| (b) 多方法 `getTree(udid?)` | 加 cellId / udid 参数 | YAGNI；Cell allocator 在 v0.4-v0.6 落地，那时 source 由 Cell 持有 / 由 Driver 注入；C3 加参数 = 早期抽象浪费 | ❌ |
| (c) `getTreeAt(point)` / `screenshot()` 加入 interface | tree source + 截图 + selector resolve 全在一个 interface | 过度耦合；C6 SDK 接通时 Driver 已有 `screenshot()` / `tree()` 各自接口；A11yTreeSource 只管"出一棵树" | ❌ |

### #4 design.md 章节内容锁定（决策 #4）

字段表：12 个字段（rawType / role / identifier / label / value / text / bounds / enabled / selected / hasFocus / visible / children）+ 必填 / nullable + 单位 + 数据源 + role 翻译算法 + 60 层截断 + 占位字段 + A11yTreeSource interface 形态 + 已知偏差。

**关键锁定项**：
- **bounds 单位 = logical points @1x**（非 device pixel / 非 host pixel / 非归一化）—— C5 几何阈值 modifiers 全用此单位
- **role 算法**：rawType ∈ XCUIElementType 表 ∧ ∈ KNOWN_ROLES → Role；否则 undefined
- **截断行为**：silent + stderr warn；wire **不**加 `_truncated` flag（保字段稳定）
- **占位字段**：hasFocus 永 false / text 永空（v0.3 阶段）；v0.7+ AXP 路径补
- **value 类型偏差**：snapshot.value 是 Any?；仅 String 时收录

### #5 `A11yNode.role` 类型保持 `Role | undefined`（**不**改 type）

- C1 已有 `role?: Role`（screen.ts:16）
- exactOptionalPropertyTypes 不变量："role 字段存在 ⇔ KNOWN_ROLES 内"
- 实现路径：`delete node.role`（rawType 未知时）/ 赋值 `node.role = r`（KNOWN_ROLES 内时）
- **不**改成 `role: Role | null` 或 `role: Role`（破 C1 type / 强非空都不合规）

### #6 batch fill 永远覆盖 wire 上游 role（即使 wire 不出）

- 不变量："role 来自 rawType"
- 当前 wire 决策 #1 选 (a)：Swift 0 出 role，不存在 wire 上游冲突
- 防御性测试：mock fetch 返带 `role: "wrongValue"` 的 wire → fill 覆盖为正确值（避免未来调用方误传）
