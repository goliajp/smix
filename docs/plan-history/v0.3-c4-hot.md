**已锁定的 7 个匹配决策**（详 §关键决策 #1-#7；prompt §决策 1-7 一一对应）：

1. **C4 范围 = 纯函数**（A），**不**接通 driver；C6 接通时由 driver 调用
2. **first match strategy = DFS pre-order**（self → children 左到右）
3. **text selector 匹配字段 = `label` OR `value` OR `text`**（三选一命中即可；**不**匹配 `identifier`）
4. **role+name selector**：`role` 严格等于 `node.role`；`name` 若给 → 匹配 `label` OR `value` OR `text`（与 text selector 一致）；`name` 未给 → 不约束 name
5. **id selector** = `node.identifier` 严格相等（**case-sensitive**，**不** contains）
6. **label selector** = `node.label` 严格相等（**case-sensitive**，**不** contains）
7. **regex 适用范围**：`Selector.text` + `BaseRole.name` 接受 `string | RegExp`（已是 type 定义）；其他字段（`BaseId.id` / `BaseLabel.label`）只接 `string`（与 type 定义一致）。`string` 比对 case-sensitive 严格相等；`RegExp` 用 `.test(value)` 部分匹配（不锚定）。空字符串 `""` 视为不匹配（避免 false positive）

**不**做（推 C5+ / 后续 minor）：

- 8 modifiers（near / below / above / leftOf / rightOf / inside / nth / first / last） → **C5**（含几何阈值）
- driver / SDK 接通（`Driver.findOne` / `findAll` / `waitFor` / `ElementHandle.resolve` 真实现） → **C6**
- SimctlDriver.tap 改路径（id/role/label selector 当前抛 DRIVER_ERROR，C4 后**继续抛**；C6 时由 driver 改用 resolveSelector → coord（host-hid digitizer）或 → text fallback runner /tap） → **C6**

- HostAxpTreeSource 真实现 → v0.7+
- `Driver.tree()` 真实现（当前是 stub 抛 AX bridge not supported） → C6/C7
- Selector 匹配 `identifier` 字段以外的 fuzzy / contains / edit-distance fallback → **永不做**（matcher suggestions 在 C6 失败时填 visibleElements，C4 严格匹配）

### S1. 纯 TS 实现 — `resolveSelector` + 最小红绿

> **决策依据（见末尾"关键技术决策"表 #1-#7）**：
> - **C4 范围 = 纯函数（决策 #1）**：用户 prompt 显式选 (A) TS 侧 client 端 resolver，但 C4 仅做 selector → A11yNode 匹配（**不**做 → 坐标 → tap transport，那是 C6）。pure function = 0 e2e 风险 / 大量 unit test 高速反馈 / 与 driver / runner / cell / SDK 解耦
> - **DFS pre-order first-match（决策 #2）**：模仿 Playwright / DOM `querySelector` 行为；BFS 偏 "广度优先返浅层节点" 不符合 a11y tree "容器嵌套" 直觉（cell > button，DFS 会先返 cell 而非 button — 但 cell 是 container，selector text="OK" 命中应该返 button —— 因此 **DFS + first match on the actual node whose own fields match**，不通过递归 children 的命中冒泡到父）
> - **text 匹配三字段 label/value/text（决策 #3）**：iOS 26 cell 嵌套 button 时，cell 自身 label 通常为空、button 有 label；iOS 17/18 cell 自身可能 label 已填。三字段任一命中 → 跨 iOS 版本健壮；**不**匹配 identifier（identifier 是开发者 ID，不是 user-visible 文本，text selector 应当是 user-facing）
> - **role+name name 与 text 同语义（决策 #4）**：`{ role: 'button', name: 'OK' }` 与 `{ text: 'OK' }` 在 button 节点上语义重叠，差异在 role 收窄到 button——name 也匹配三字段；若 name 是 string → strict equal；RegExp → .test
> - **id / label strict equal**（决策 #5, #6）：a11y identifier 和 label 是开发者写死的稳定字段，AI 测试作者期望 strict equal（"ContinueButton" ≠ "continueButton"）；contains / fuzzy 留给 C6 matcher 失败时的 suggestions（edit-distance），不污染主路径
> - **regex 适用范围**（决策 #7）：`Selector` type 已锁定 text/name 接 `string | RegExp`，id/label 仅 `string`——C4 严格按 type 走；`string` strict equal / `RegExp` partial .test
> - **modifier 护栏**：C4 input 是 `Selector` 类型，可能包含 modifier 字段。C4 必须 fail-fast 抛 `ExpectationFailure(DRIVER_ERROR)` 含 modifier name + hint "推 C5"，避免 silent ignore

- 文件 1（新建）：`src/core/resolve-selector.ts`：
  ```typescript
  import type { Selector } from './selector.js'
  import type { A11yNode } from './screen.js'
  import { ExpectationFailure } from './error.js'
  import { isTextSelector, isIdSelector, isLabelSelector, isRoleSelector, describeSelector } from './selector.js'

  /**
   * Resolve a Selector against an A11yNode tree.
   *
   * Pure function — no driver / runner / sim calls. Caller (Driver in C6+)
   * is responsible for fetching the tree (via A11yTreeSource.getTree()) and
   * for translating the matched node into a tap target (coord or runner /tap).
   *
   * Search order: DFS pre-order (self first, then children left-to-right).
   * First match wins.
   *
   * Modifiers (near / below / above / leftOf / rightOf / inside / nth / first
   * / last) are NOT supported in v0.3 C4 — they land in C5 with geometry
   * thresholds. Encountering any modifier throws an ExpectationFailure with
   * code DRIVER_ERROR.
   *
   * Matching semantics (locked in design.md §Selector 匹配语义 v0.3 C4):
   * - text:  node.label || node.value || node.text matches; string = strict
   *          case-sensitive equal; RegExp = .test() partial. Empty string =
   *          never matches.
   * - id:    node.identifier strict case-sensitive equal.
   * - label: node.label strict case-sensitive equal.
   * - role:  node.role strict equal; if name present, match name like text.
   *
   * The matched field set deliberately excludes identifier from text/name
   * matching — text selectors are user-facing text; identifier is a developer
   * key.
   */
  export function resolveSelector(tree: A11yNode, selector: Selector): A11yNode | null {
    rejectModifiers(selector)
    return dfsFind(tree, (n) => matches(n, selector))
  }

  function rejectModifiers(selector: Selector): void {
    const MOD_KEYS = ['near', 'below', 'above', 'leftOf', 'rightOf', 'inside', 'nth', 'first', 'last'] as const
    for (const k of MOD_KEYS) {
      if ((selector as Record<string, unknown>)[k] !== undefined) {
        throw new ExpectationFailure({
          code: 'DRIVER_ERROR',
          message: `Selector modifier '${k}' not supported until v0.3 C5: ${describeSelector(selector)}`,
          selector,
          hint: `modifiers (near/below/above/leftOf/rightOf/inside/nth/first/last) land in v0.3 C5 with geometry thresholds; use a more specific base selector for now`,
        })
      }
    }
  }

  function dfsFind(node: A11yNode, pred: (n: A11yNode) => boolean): A11yNode | null {
    if (pred(node)) return node
    for (const child of node.children) {
      const found = dfsFind(child, pred)
      if (found !== null) return found
    }
    return null
  }

  function matches(node: A11yNode, selector: Selector): boolean {
    if (isTextSelector(selector)) {
      return matchText(node, selector.text)
    }
    if (isIdSelector(selector)) {
      return node.identifier === selector.id && selector.id !== ''
    }
    if (isLabelSelector(selector)) {
      return node.label === selector.label && selector.label !== ''
    }
    if (isRoleSelector(selector)) {
      if (node.role !== selector.role) return false
      if (selector.name === undefined) return true
      return matchText(node, selector.name)
    }
    return false
  }

  function matchText(node: A11yNode, pattern: string | RegExp): boolean {
    const candidates: ReadonlyArray<string | undefined> = [node.label, node.value, node.text]
    if (pattern instanceof RegExp) {
      for (const c of candidates) {
        if (c !== undefined && pattern.test(c)) return true
      }
      return false
    }
    if (pattern === '') return false
    for (const c of candidates) {
      if (c === pattern) return true
    }
    return false
  }
  ```

## 关键技术决策

### #1 C4 范围 = 纯函数（A），**拒** (B)/(C)；driver 接通推 C6

| 候选 | 描述 | 影响 | 决策 |
|---|---|---|---|
| **(A) C4 = 纯函数 resolveSelector(tree, selector)，driver 不动** | C4 落孤立模块 + unit test；C6 SimctlDriver 改成 `getTree()→resolveSelector→tap` 时调用 | 0 e2e 风险；大量 unit test 高速反馈；与 driver / runner / cell / SDK 解耦；用户 prompt 显式选 | **✅ 选** |
| (B) C4 = 纯函数 + 同时接通 SimctlDriver.tap 走 runner /tap by text | C4 同时改 driver 把 id/role/label selector 通过 resolver → label → POST /tap | 多一层耦合 driver-runner；C4 测试要含 mock runner；id/role 匹配后转 text 再走 NSPredicate 是双重匹配（resolver 命中 cell.label="" → fallback button.label="General" 后再 NSPredicate 二次匹配，可能匹配错节点） | ❌ |
| (C) runner Swift 内 resolver | 扩 SimxRunnerCore TapRoute 接受 id/role/label selector，Swift 内构造 NSPredicate | 不接 HID；selector logic 散在 swift（违反 §3 "selector 是 TS 类型"）；冷计划 prompt 模板 "Role 翻译表在 TS 侧 src/core/role.ts" 同理选择 selector 也在 TS 侧 | ❌ |

**理由**：(A) 工程量最小 + 0 e2e + 0 driver 耦合 + 严格遵守冷计划 "selector resolver 是 TS 侧主语义"（决策日志 v0.3 C1+C2+C3 同 trend）；C6 决定 transport 时再调用 C4 这个 pure function。

### #2 First match strategy = DFS pre-order

| 候选 | 描述 | 决策 |
|---|---|---|
| **(a) DFS pre-order（self → children L→R）** | 模仿 Playwright querySelector / DOM TreeWalker；嵌套 cell > button 时 cell.label='' 跳过，DFS 继续到 button | **✅ 选** |
| (b) BFS（广度优先） | 浅层节点优先返回；嵌套 cell > button 时若 cell.label='General' iOS 17 会先返 cell（容器）而非 button（可点对象） | ❌ |
| (c) Hit-test 优先（按 bounds 计算 z-order） | iOS 26 视觉层级；需要 zPosition / overlapping logic | C5 几何 modifiers 一起做更连贯；C4 推 ❌ |

**理由**：DFS 与 a11y tree 结构契合（DOM-like），AI 测试作者从 Playwright/Selenium 训练语料对 DFS 有强先验；BFS 在嵌套容器场景反直觉。

### #3 text selector 匹配字段 = label ∨ value ∨ text（**不** identifier）

| 候选 | 描述 | 决策 |
|---|---|---|
| **(a) label ∨ value ∨ text 任一命中** | iOS 17/18 cell.label='General' 命中 cell；iOS 26 cell.label='' 跳过，命中 cell > button.label='General' | **✅ 选** |
| (b) 仅 label | iOS 26 cell 嵌套 button 时 cell.label='' → root cell 不命中；DFS 走到 button.label='General' 命中（行为相同），但 staticText.value='42' 场景失效 | ❌ |
| (c) label ∨ value ∨ text ∨ identifier | text selector 与 id selector 语义模糊；AI 写 `{text:'okBtn'}`（识别错把 id 当 text）反而误命中 | ❌ |

**理由**：(a) 吸收 iOS 17/18/26 cell vs cell>button label 形态差异（C3 决策日志已记 iOS 26 实测）；value 字段命中 staticText 数字 / textField 输入 / progress 数值；text 字段是 v0.7+ AXP 路径预留（C3 wire 章节锁定占位）；identifier 是开发者键，与 text selector 语义分离。

### #4 role+name 的 name 与 text selector 同语义

- `{role:'button', name:'OK'}` 解析路径：role 严格 `===` + name 走 `matchText`（label ∨ value ∨ text 三字段任一）
- `name?` 未给 → 不约束 name，仅 role 命中即可
- name 是 RegExp → 用 `.test()` partial
- name 是 string='' → 永不匹配（与 text selector 同语义防 false positive）
- 模拟 Playwright `getByRole('button', { name: 'OK' })` 行为

### #5 id selector = node.identifier 严格 case-sensitive 相等

- AI 测试作者期望 identifier 精确匹配（`"ContinueButton"` ≠ `"continueButton"`）
- 空字符串 `id:''` 永不匹配（防 identifier 也空时 false positive；wire 协议章节已记 identifier='' 时省略字段，但 DSL 表面给定 id='' 仍 fail-fast）
- fuzzy / contains 推 C6 matcher 失败时 suggestions（edit-distance），不污染主路径

### #6 label selector = node.label 严格 case-sensitive 相等

- 同 #5 理由
- 模糊匹配走 `{text: /sub.*string/}` selector + RegExp 显式声明
- 空字符串 `label:''` 永不匹配

### #7 regex 适用 = text + name；适用算法 = `.test()` partial（不自动 anchor）

- Selector type 已定义 `BaseText.text: string | RegExp` 和 `BaseRole.name?: string | RegExp`（src/core/selector.ts:18,21）—— C4 严格按 type 走
- `BaseId.id: string` / `BaseLabel.label: string` 仅 string；RegExp 在该字段上 type 不允许
- `RegExp.test(value)` 是 partial 匹配（不锚定 `^...$`）；调用方需 anchor 时显式 `/^OK$/`
- 模拟 Playwright `getByText(/pattern/)` 同语义
