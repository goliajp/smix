# plan-hot — v2.9 到 C2：`smix-runner-client` 驱动 wire 方法全面经 napi 边界暴露（loopback，复用 C1 范式）

## 目标 checkpoint

C2：**`crates/smix-node` 的 `SmixNodeDriver` 在 C1 的 `tapAtCoord` 之外，再经同一 napi 范式暴露 `smix-runner-client` 的驱动/感知 wire 动词全集，且 `SmixNodeDriver.openSession(bundleId)` 产出一个 `SmixNodeSession` napi 对象承载 app 生命周期动词——全部对 loopback fake wire（`node:http` mock，镜像 C1 `tap.test.mjs`）单测覆盖、Promise 真 resolve、无真设备、无 panic。** 具体绑成的 napi 面（← `smix-runner-client` 方法 ← `App.ts` 桩）：

| napi 方法 | 载体 | ← smix-runner-client | ← App.ts 桩 |
|---|---|---|---|
| `tapById(id)` → `bool` | `SmixNodeDriver` | `tap_by_id(&str)` | `App.tap`（selector 在 TS SDK 侧 resolve→id，见下决策） |

| `swipe(direction)` → `void` | `SmixNodeDriver` | `swipe_once(SwipeDirection)` | `App.swipe` |

| `systemPopups()` → `String`(JSON) | `SmixNodeDriver` | `system_popups(None)` | `App.systemPopups` |

## 已经查清、不必重查的事实

- **跨边界 marshaling 决策（本段核心，无分叉）：Selector / TapMode 一律不过 napi 边界。** napi 面绑 **`tap_by_id` / `input_text`** 这类「已解析原子动词」，**不**绑 client 的 selector 版 `tap(&Selector, TapMode, …)` / `fill(&Selector, …)`。依据（读源码核实）：
  - **parity 参照 `smix-ffi/src/driving.rs` 就是这么做的**——`SmixSession::tap_by_id(id)` + `input_text(text)`，无 selector 版；注释原文「they resolve a selector to an id and pass it here, so no coordinate crosses the boundary」。Swift/Kotlin SDK 在自己那层 resolve selector→id（走 resolver stone），再调 `tap_by_id`。TS SDK 同构：`App.ts` 已有 `resolver` / `labelsResolver` seam（对 runner 的 `/select/resolve*` 路由），C3 退桩时 `App.tap` = `snapshotTree` → resolve → `tapById(id)`；`App.fill` = resolve → `tapById(focus)` → `inputText(text)`。
  - 因此 **C2 无需引入 `smix-selector` 依赖，`Cargo.toml` 不加任何新 dep**——这正面回答冷计划风险表里「若需新类型 crate（如 smix-selector）在此评估」：**不需要**。绑的动词只吃 `&str` / `f64` / camelCase 枚举名，全是原生可跨的标量。
  - 这是**首选正统**（prefer-orthodox）+ 与 UniFFI 面 1:1 parity，非分叉。"selector 过边界"那条路被此决策关死。
- **枚举 marshaling：`key` / `direction` 以 camelCase 字符串入参，在边界用 serde 解析**——镜像 `driving.rs::parse_wire_enum`：`serde_json::from_value(Value::String(name))` → `KeyName` / `SwipeDirection`，失败即 `napi::Error::from_reason`。这样枚举名映射只有 serde 一份、不复制。核实 wire 串（`crates/smix-input/src/lib.rs`，两枚举皆 `#[serde(rename_all="camelCase")]`）：`KeyName` = `return/delete/tab/space/escape/arrowUp/arrowDown/arrowLeft/arrowRight/home/lock/volumeUp/volumeDown`；`SwipeDirection` = `up/down/left/right`。
- **要绑的 client 动词签名 + 返回（读 `crates/smix-runner-client/src/lib.rs` 核实）**：
  - `tap_by_id(&self, id: &str) -> Result<bool, RunnerTransportError>`（`:1436`，`POST /tap-by-id`，返回 `{ok:bool}` 里的 `ok`）→ napi 返回 `bool`。
  - `input_text(&self, text: &str) -> Result<(), _>`（`:1418`，`POST /input-text`，OkEnvelope）→ napi 返回 `()`。
  - `press_key(&self, key: KeyName) -> Result<RunnerKeyboardResult, _>`（`:1767`，`POST /press-key`）→ napi 丢弃诊断 payload 返回 `()`（同 `driving.rs::press_key` 的「fire-and-return，丢 tree/timings」约定）。
  - `swipe_once(&self, direction: SwipeDirection) -> Result<(), _>`（`:1825`，`POST /swipe-once`，OkEnvelope）→ napi 返回 `()`。
  - `get_tree(&self, include: Option<IncludeScope>) -> Result<A11yNode, _>`（`:1198`，`GET /tree`，deser 后 `derive_roles_recursive`）→ napi 传 `None`（同 `driving.rs::tree`），`serde_json::to_string` 返回 JSON `String`。
  - `system_popups(&self, include: Option<IncludeScope>) -> Result<Vec<SystemPopup>, _>`（`:1208`，`GET /system-popups`，`{popups:[…]}` 信封）→ napi 传 `None`，`serde_json::to_string(&Vec<SystemPopup>)` 返回 JSON `String`。
  - session 生命周期（req 类型由 `smix-runner-client` re-export，`driving.rs` 已 import 同名）：`open_session(&SessionOpenRequest{bundle_id, activate:false}) -> SessionOpenResponse`（`:1091`，`.session_id`）；`launch_session_app` / `terminate_session_app(&SessionAppLifecycleRequest{session_id, ..Default})`（`:1170`/`:1160`）；`relaunch_session_app(&SessionRelaunchAppRequest{session_id})`（`:1135`）。全部 `Result<_, RunnerTransportError>`。
- **wire 类型 serde（`crates/smix-runner-wire`/`smix-screen` 核实，都是 `#[derive(Serialize,Deserialize)]`，多为 camelCase）**，供 loopback mock 回体：
  - `A11yNode`（`smix-screen:398`）：唯一无默认必填 = `rawType`（camelCase）；`elementTypeRaw` 有 `default`，`identifier/label/children` 皆 `default`/optional。最小可反序列化体 = `{"rawType":"application","identifier":"root"}`。
  - `SystemPopup`（wire:370）：必填 `id` / `type`(`kind`) / `source`；其余 `default`。信封 `{"popups":[{"id":"p1","type":"alert","source":"SpringBoard"}]}`。
  - `RunnerKeyboardResult`（wire:303）：`tree` / `stages` 皆 optional → 最小体 `{}`。
- **C1 已定、本段沿用的范式**（`crates/smix-node/src/lib.rs`）：每个 `#[napi] pub async fn` 先 `let client = Arc::clone(&self.client);` 再 await（future 自持 client，不跨 napi runtime 借 `&self`）；`RunnerTransportError` → `napi::Error::from_reason(e.to_string())`（跨语言契约上报，非防御）；结构化结果走 `serde_json::to_string` 出 JSON `String`。napi 默认自带 tokio runtime（`Cargo.toml` 已 `features=["napi9","tokio_rt"]`），async fn 自动导出为 JS Promise——无需手挂 runtime。
- **`SmixNodeSession` 返回形**：`#[napi] pub struct SmixNodeSession { client: Arc<HttpRunnerClient>, session_id: String }`；`open_session` 复用同一 `Arc<HttpRunnerClient>`（`Arc::clone`，共享连接池，同 `driving.rs::open_session`）。napi-rs 3.x 支持 async fn 返回 `#[napi]` 类实例。
- **loopback fake wire = `node:http` mock，零设备**：镜像 C1 `crates/smix-node/__test__/tap.test.mjs`——`http.createServer` + `server.listen(0)` 取随机端口，按 `req.method + req.url` 路由回预置 JSON，`new SmixNodeDriver(port)` 指向它。POST 路由回上列信封，GET `/tree`、GET `/system-popups` 回上列 body。
- **两个 App.ts 桩在 client 侧无对应 wire 方法 → 明确排除出 C2**（本机 grep 核实 `crates/**/*.rs` 无 `/screenshot`、无 `/open-url`/`open_url` 的 `json_post`/`json_get` 路由；CLI 的 `sim screenshot` 走 host 侧 simctl，非 runner wire）：
  - `App.screenshot()` → **无 wire 方法**（缺口，非 C2 可绑）。
  - `App.openUrl(url)` → **无 wire 方法**（缺口，非 C2 可绑）。
  这两条要么补 `smix-runner-client` 新 wire 路由、要么走 host 侧——属 C2 之外的 wire 缺口，本段不绑、如实上报。
- **与 UniFFI `driving.rs` parity 差异（组织层，非能力层）**：`driving.rs` 把无状态动词（`tap_by_id`/`input_text`/`press_key`/`swipe_once`/`system_popups`）也挂在 `SmixSession` 下（纯组织，其 client 方法并不需要 `session_id`）。C2 沿用 **C1 已定的「无状态动词挂 `SmixNodeDriver`、仅生命周期动词挂 `SmixNodeSession`」** 布局（C1 的 `tapAtCoord` 就挂在 driver）——动词归位随其真实 state 依赖，正交、无 fork。`CancelToken` 参数 `driving.rs` 全线程有、C1/C2 **不绑**（cancel 是横切 FFI 人机工程、非驱动动词；C1 已定无 cancel 基线，JS 侧 abort 属另一机制）——此差异如实记于此，留后续单独决策，不在 C2 静默塞入。

## 步骤（线性，3 个，按方法分组）

### S1. `SmixNodeDriver` 无状态 act 动词组：`tapById` / `inputText` / `pressKey` / `swipe`

**红（写测试，先失败一次）**
- 文件：`crates/smix-node/__test__/act.test.mjs`（`node:test` + `node:http`，镜像 `tap.test.mjs`）
- 断言（一个 loopback server 按 `req.url` 路由，四 case）：
  1. `POST /tap-by-id` 回 `200` `{"ok":true}`；`const ok = await d.tapById('btn-ok')`；断言 `ok === true`，且 server 收到的 body `.id === 'btn-ok'`。
  2. `POST /input-text` 回 `200` `{"ok":true}`；`await d.inputText('hello')` 真 resolve（不抛），server 收到 body `.text === 'hello'`。
  3. `POST /press-key` 回 `200` `{}`；`await d.pressKey('return')` 真 resolve，server 收到 body `.key === 'return'`。
  4. `POST /swipe-once` 回 `200` `{"ok":true}`；`await d.swipe('up')` 真 resolve，server 收到 body `.direction === 'up'`。
- 跑：`cd crates/smix-node && node --test __test__/act.test.mjs` → 期望**红**（四方法未绑，TypeError）。

**绿（实现，最少代码转绿）**
- 文件：`crates/smix-node/src/lib.rs`，`impl SmixNodeDriver` 内加（复用 C1 的 `Arc::clone`-before-await + `from_reason` 范式）：
  - 顶部加解析 helper：`fn parse_wire_enum<T: serde::de::DeserializeOwned>(name: &str, what: &str) -> napi::Result<T>`，体 = `serde_json::from_value(serde_json::Value::String(name.into())).map_err(|_| napi::Error::from_reason(format!("unknown {what}: {name:?}")))`。
  - `#[napi] pub async fn tap_by_id(&self, id: String) -> napi::Result<bool>` → `Arc::clone` → `client.tap_by_id(&id).await.map_err(|e| napi::Error::from_reason(e.to_string()))`。
  - `#[napi] pub async fn input_text(&self, text: String) -> napi::Result<()>` → `client.input_text(&text).await.map_err(from_reason)?; Ok(())`。
  - `#[napi] pub async fn press_key(&self, key: String) -> napi::Result<()>` → `let key: KeyName = parse_wire_enum(&key, "key")?;` → `client.press_key(key).await.map_err(from_reason)?; Ok(())`（丢弃 `RunnerKeyboardResult`）。
  - `#[napi] pub async fn swipe(&self, direction: String) -> napi::Result<()>` → `let direction: SwipeDirection = parse_wire_enum(&direction, "direction")?;` → `client.swipe_once(direction).await.map_err(from_reason)?; Ok(())`。
  - 加 `use smix_input::{KeyName, SwipeDirection};`（`smix-runner-client` 已 re-export 或经其依赖可达；若不可达则在 `Cargo.toml` 加 `smix-input = { path=…, version="2.0.0" }`——按编译实际，属既有 workspace crate 非新第三方 dep）。
- 关键点：① 无 selector 过边界（见决策）；② 枚举字符串边界解析，映射只 serde 一份；③ 返回类型贴 `driving.rs` 语义（`tap_by_id`→bool，其余→`()`）。
- 跑：`cd crates/smix-node && bun run build && node --test __test__/act.test.mjs` → 期望**绿**。

**重构（可选）**
- 若 `from_reason` 闭包在各方法重复，抽一个 `fn transport_err(e: RunnerTransportError) -> napi::Error`；不改行为。
