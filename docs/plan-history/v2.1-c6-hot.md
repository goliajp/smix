# plan-hot — v2.1 到 C6:postgres 的 stream_sessions

## 目标 checkpoint

C6:smix-server 不再连接 postgres。`stream_sessions`(一张表、按 udid upsert)
成为 store 里的一个命名空间;`sqlx` 依赖、`db.rs`、`migrations/` 与 CI 的
postgres service 容器一并移除。**集成测试从此不需要任何外部服务** —— 今天它
在 `DATABASE_URL` 缺失时整套跳过。

## 前置条件

```bash
cargo test -p smix-server   # C5 后 44 测绿
```

## 步骤(线性)

### S1. sessions 迁到 store

**红**
- 文件:`crates/smix-server/src/sessions.rs` 内测试
- 断言:
  - `register` 后 `list` 含它;同一 udid `register` 两次仍只有一行
    (upsert 语义,不是追加)
  - 第二次 register **刷新** device_name / runtime / stream_path 与 started_at
    (原 SQL 的 `ON CONFLICT DO UPDATE` 就是这么做的)
  - `list` 按 `started_at` **降序**(原 SQL 的 `ORDER BY started_at DESC`;
    KV 无序,排序必须在 Rust 里显式做,不能依赖 store 的返回顺序)
  - 空 store `list` 返回空 `Vec`,不是错误
  - 损坏的记录 → 具名错误

**绿**
- 文件:`crates/smix-server/src/sessions.rs`,`stream.rs` 改为调用它
- 关键点:
  - 命名空间 `session:<udid>`,值是 `SimEntry` 的 JSON
  - `started_at` 从 SQL 的 `now()` 变为 `Utc::now()` —— 语义相同,
    但时钟从数据库移到进程,值得在注释里写明
  - `SimEntry` 去掉 `sqlx::FromRow` 与 `#[sqlx(default)]`

### S2. 拆掉 postgres

**红**
- 无新测试;由 S1 的测试与既有 wiring 套件保证

**绿**
- 文件:`Cargo.toml`、`crates/smix-server/{Cargo.toml,src/main.rs,src/state.rs,
  src/error.rs,src/db.rs,migrations/}`、`tests/wiring.rs`、`.github/workflows/ci.yml`
- 关键点:
  - `DATABASE_URL` 仍被设置时**明说已失效**(与 C5 的 `REDIS_URL` 同处理)
  - wiring 套件去掉 `DATABASE_URL` 门禁 —— 它现在可以无条件运行,
    这正是这次迁移买到的东西,必须体现在测试能不能跑上
  - `migrations/` 整目录删除;`db.rs` 删除
