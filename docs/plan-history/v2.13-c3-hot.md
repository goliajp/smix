# plan-hot — v2.13 到 C3：独立闭环走通一次，全程没有 Claude Code

## 目标 checkpoint

C3：一条脚本从**装 app** 开始，走到**跑一条自己录出来的 flow**，中间不出现 Claude Code、
不手工补任何一步：装 app → `smix init` → `capsule up` → 驱动 → 录制生成 flow → `smix run` → 收摊。
机器判据全程可判，收尾无孤儿。

## 前置条件

```bash
./target/release/smix init --help          # C2 已落地
find selftest-fixture -type f | wc -l      # 期望 0 —— 仓内没有可跑的示例 app
xcrun --sdk iphonesimulator --show-sdk-path
bash scripts/dev/pick-dev-sim.sh           # 有一台本仓自有 sim 可用
```

## 步骤（线性，3 步）

### S1. 一个被测 app（测试夹具，不是对外示例）

**红（写测试）**
- 文件：`scripts/dev/build-fixture-app.sh`；先跑一次，断言它**尚不存在**产物
- 断言：脚本产出 `.app` 后，`plutil -extract CFBundleIdentifier raw <app>/Info.plist`
  等于 `jp.golia.smix.fixture`，且 `file <app>/<exe>` 报 arm64 simulator Mach-O

**绿（实现）**
- 单个 Swift 文件 + 手写 `Info.plist`，用
  `xcrun --sdk iphonesimulator swiftc -target arm64-apple-ios<ver>-simulator` 直接编出可执行文件，
  **不建 xcodeproj**（xcodeproj 是维护负担，且这里只需要一个能装能驱动的 bundle）
- 界面提供**稳定的 accessibilityIdentifier**：一个 `fixture-input`、一个 `fixture-submit`、
  一个 `fixture-result`；点了 submit 后 result 变成输入的内容 —— 三件套刚好覆盖 sense / act / assert
- 关键点：夹具归 `test-fixtures/`，README 一句话说明它是测试资产**不是**对外示例
  （仓内不承诺可跑的示例 app 这条现状是有意的，见决策日志 2026-07-19）

**重构**
- 无

### S2. 独立闭环 e2e

**红（写测试）**
- 文件：`scripts/dev/v2.13-c3-standalone-loop-e2e.sh`；未实现前跑它应失败
- 断言（每步机器可判）：
  1. 在一个**空的临时工作目录**里(不是 smix 仓)`smix init --device <UDID>` → `.smix` 写出、exit 0
  2. `smix sim install <fixture.app>` → exit 0；`smix doctor --json` 的 `next` 变成 `capsule up`
  3. `smix capsule up dev --bundle jp.golia.smix.fixture` → exit 0，`doctor --json` 的 `ready` 为 true
  4. 驱动：`smix fill`/`smix tap`/`smix find` 打在夹具的三个 id 上，`find` 报 `exists=true`
  5. 录制 → `smix authoring generate` → 产出的 yaml **非空且能被 `smix run` 消费**
  6. `smix run <生成的 flow> --device dev` → exit 0
  7. `smix down` → 无残留 runner、sim 回收
- **禁令断言**：脚本自身不得出现 `claude`（`grep -c claude` 为 0），
  独立闭环必须靠自己成立，不许靠协同那条兜底

**绿（实现）**
- 按上述顺序实现；每步失败即停并打印该步的机器判据实测值

**重构**
- 无

### S3. 接进闸门

**绿（实现）**
- 名字符合 `scripts/dev/*-e2e.sh`，preflight 的 `SMIX_DEVICE_E2E` 集自动收编（workflow-scan 视为已跑）
- 夹具构建脚本被 e2e 调用，故不算孤儿
