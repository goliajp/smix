## Root cause

v1.0.3 session lifecycle correctly stopped the `.activate()` storm (fix A). Two remaining pressure sources unchanged:

- **`simctl io screenshot` cadence** — perf gate + visual gate + `takeScreenshot` yaml verbs, no rate control. iOS 26.5.2 SimRenderServer 1051.55 hits `brk 1` under sustained load on its `com.apple.display.captureservice` queue.
- **`/system-popups` poll cadence** — 1.7 QPS × 6 XCUIQuery, unbounded even when app is dead. Same arbitration pressure that produces `** TEST INTERRUPTED **` in feedback §E.

Both are **core capability gaps** in smix, not driver bugs. §12 three-layer architecture calls for sense + act at core layer, decide at driver.

## Decisions

### D1 — sense layer: SimHealthMonitor (new stone `smix-sim-health`)

New crate. Watches:
- SimRenderServer pid (`pgrep -f SimRenderServer.*<UDID>`), alive/dead state
- `xcodebuild` test-host pid, alive/dead + last exit code
- Last `/health` response age (from `HttpRunnerClient`)
- Rolling window of screenshot wall times

State machine:
- `Healthy` — all watched procs alive, `/health` < 5s ago, screenshot p95 < 800ms
- `Degraded` — one signal degraded (screenshot p95 > 800ms, or `/health` > 5s but < 15s)
- `Dead` — SimRenderServer or xcodebuild gone, or `/health` > 15s

Transitions broadcast on `tokio::sync::broadcast::Receiver<SimHealthState>`. Additive: any consumer that doesn't subscribe is unaffected.

Sense-only. Does not act. Actions live in driver + smix-simctl + smix-adapter-maestro.

### D2 — sense layer: app-alive cache

On first observation of "Application X is not running" XCTIssue (runner-side, in `SmixRunnerUITests.resolveApp` and query handlers), record `bundleId → deadUntil = now + 20s` in a shared cache on the runner. During `deadUntil` window:
- `GET /tree` returns `{ "tree": null, "reason": "app_not_running" }` immediately, no XCUIQuery
- `GET /system-popups` returns `{ "nodes": [] }` immediately, no XCUIQuery
- Cache invalidated by any subsequent `POST /sim/launch` or `POST /session/open` for that bundle-id

Cuts the swallowed-error firehose we saw in the runner log. This is a runner-side change; SDK sees a normal empty result and can still make its own retry decisions.

### D3 — act layer: adaptive `simctl io screenshot` throttle

In `smix-simctl::SimctlClient::screenshot`:
- Measure wall time of last call
- Baseline: last < 300 ms → allow immediately, 1 QPS floor if caller loops
- Slowdown: 300-1500 ms → soft-cap to 0.3 QPS via internal `tokio::time::sleep`
- Failure: > 1500 ms wall OR non-zero simctl exit → circuit-breaker 3 s, return `Err(SimctlError::CaptureBackpressure { retry_after })`, downgrade SimHealthState to `Degraded`

Not user-facing config. Auto-tuned. Consumers that care can subscribe to `SimHealthState` and back off explicitly.

### D4 — act layer: `/system-popups` minimum interval + wait-context gating

Runner side: reject `GET /system-popups` requests arriving < 500 ms after previous return from same session, with `429 Too Many Requests`, `Retry-After: 500ms`.

SDK side (yaml runtime in `smix-adapter-maestro`): the `waitForVisible` / `assertVisible` verbs currently trigger a popup poll on every tick of their internal wait loop. Change to only poll popups when the wait-condition explicitly asks for popup awareness (e.g., `expect: visible: <text>` on SpringBoard permission alert waits). Regular `assertVisible` waits use `/tree` diff only.

### D5 — act layer: `smix runner cycle` core verb

New CLI subcommand `smix runner cycle` (and Rust SDK `RunnerHandle::cycle()`):
1. Read runner state from `.smix/runner/state.json`
2. Send `POST /session/close-all` (if v1.0.3+ runner)
3. Kill xcodebuild subprocess, keep `derived-data-<UDID>/`
4. Re-invoke `xcodebuild test-without-building` with existing derived data
5. Wait for `/health` 200
6. Return to caller when session-ready

Target ~3 s cold path vs current ~15 s. Feedback §E ask 3.

### D6 — act layer: XCTest test-host auto-restart

Runner-side supervisor thread:
- Tails its own log for `** TEST INTERRUPTED **` and `SchemeActionResultOperation started unexpectedly`
- On detection: mark all open sessions as `Cycling`, invoke internal cycle equivalent to D5
- After cycle success, sessions are reopened by SDKs when they observe `SimHealthState::Cycling → Healthy` transition (D1 broadcast)
- Emit `RunnerCycled { reason, at_ms }` event on health channel

Feedback §E ask 1. Transparent for a resilient client; overt for a client that subscribes.

### D7 — SDK surface: Session-aware Degraded state (all 4)

Additive. v1.0.3 clients continue to work unchanged.

- **Rust**: `Session::state() -> SessionState { Healthy, Degraded, Cycling, Dead }`, `Session::state_stream() -> impl Stream<Item = SessionState>`
- **TypeScript**: `session.on('state', (state) => ...)`, `session.state` getter
- **Swift**: `session.state: SessionState`, `session.stateStream: AsyncStream<SessionState>`
- **Kotlin**: `session.state: StateFlow<SessionState>`

Consumers wire like:
```ts
session.on('state', (state) => {
  if (state === 'degraded') pauseGate()
  if (state === 'dead') abortGate()
  if (state === 'cycling') waitFor('healthy')
})
```

## Wire additions (additive-only)

- `POST /session/close-all` → `200 {ok, closed: N}` (D5 support)
- `GET /health` response gains `simRenderServer: { alive, pid }`, `xcodebuildTestHost: { alive, pid, restartCount }` (extends v1.0.2 added fields; still a superset — legacy jq `.ok` still works)
- `429 Too Many Requests` from `/system-popups` when D4 throttle trips
- New response header `X-Sim-Health: healthy|degraded|dead|cycling` on every response — SDK reads it to update local `SessionState` without polling

v1.0.4 clients work against v1.0.3 runners (missing endpoints return 404 → fall through to legacy behavior).
v1.0.3 clients work against v1.0.4 runners (extra fields ignored, header ignored, session-close-all not used).

### D8 — feedback §A: `smix runner up` bundle validation

Add explicit validation on `smix runner up`:

1. If `--bundle` is passed, log `[runner] target bundle-id: <id>` at boot.
2. If `--bundle` is not passed, probe the currently-foreground app on
   the target device. If found, log `[runner] target bundle-id: <id>
   (auto-detected foreground; pass --bundle to pin)`. If nothing is in
   the foreground, exit non-zero with:
   ```
   error: no foreground app to attach to; pass --bundle <bundle-id>
     example: smix runner up sim-<name> --bundle com.example.app
   ```

Rationale: current default `com.apple.Preferences` silently latches
Preferences as the target, causing hours of "empty tree" ghost-chase.
Explicit-or-auto is strictly better; consumers get either an obvious
error or an accurate log.

### D9 — feedback §B: `--gate-signal <regex>` on `smix run`

Add flag `smix run --gate-signal <regex>` which:

1. Requires `--metro-log-url <file:// | ws:// | ->` also set.
2. Before running the FIRST yaml step, tails the metro log source and
   blocks until a line matches the regex (or `--gate-signal-timeout`
   elapses, default 60 s → exit non-zero).
3. Symmetric to the existing `--await-signal` which fires at the END
   of the flow.

Replaces insight's `wait-metro-signal.ts` node-side helper.

### D10 — feedback §D: `--activate` cost — DOCUMENTATION

No code change. v1.0.3 session lifecycle already resolves this: when
a session is open, `App-Activate: true` is silently dropped on the
runner side (short-circuits to the session's cached binding). CHANGELOG
adds a note pointing consumers to sessions.

### D11 — feedback §I: `--debug-output <dir>/step-<n>.tree.json`

For every step in a flow with `--debug-output <dir>` set:

- Existing: `<flow>/step-<n>.png` (fail-annotated)
- New: `<flow>/step-<n>.tree.json` — snapshot of `runner.tree()` at
  the moment the step executed. Compressed pretty-JSON (~10-100 KB).
- Also expand `<flow>/run-summary.json` to record per-step:
  `{ n, verb, verdict, wall_ms, tree_path?, png_path? }`.

Consumer flow: when `assertVisible` fails, `step-<n>.tree.json` shows
the exact a11y hierarchy the runner saw when it evaluated the assertion
— avoiding the "screenshot shows the text but assertion fails" mystery
that feedback §I named.

### D12 — feedback §F + §H: `launchApp: clearState: true` rewrite

**Current implementation** (buggy on iOS 26.5): `simctl uninstall
com.<bundle>` + `simctl install <path>.app` + `simctl launch com.<bundle>`.

**Effects on iOS 26.5 sim**:
- **§F**: XCUITest test-host loses a11y binding — every subsequent
  `/tree` query returns `unknown name="<App>" id="com.<bundle>"` root
  with all children labelled `unknown`.
- **§H**: `com.apple.ReportCrash` interprets the uninstall as "the
  previously-running app is now missing an install receipt" ⇒ posts
  "Insight quit unexpectedly" system dialog on top of every flow. Not
  a real app crash — no `.ips` file written — but the operator sees
  it repeatedly and asks "why does Insight keep crashing?"

**Fix**: rewrite `launchApp: clearState: true` to:
1. `XCUIApplication.terminate()` on the target — clean SIGTERM, no
   crash-report daemon interpretation.
2. In-place sandbox clear: `simctl privacy <bundle> reset all` +
   `NSFileManager.removeItem` under the app's sandbox root
   (`~/Library/Developer/CoreSimulator/Devices/<udid>/data/
   Containers/Data/Application/<data-uuid>/{Documents,Library,tmp}`
   in the runner process). Never uninstall + install.
3. `XCUIApplication.launch()` inside the SAME test-host process. Reuses
   the XCUITest binding — no unknown-tree regression.

If sandbox clear via NSFileManager is refused by iOS 26.5 sandbox rules
(some Documents/ directories are protected), fall back to the existing
uninstall/install path but ONLY when the caller explicitly opts in via
new yaml verb `clearAppData: { mode: force-reinstall }`. The default
`launchApp: clearState: true` shape uses the safe in-place clear.

### D13 — feedback §G: openLink URL query-param verification

`openLink` verb passes the full URL (including query-params) to iOS.
If smix is dropping `?url=...` in the transport, fix by properly
percent-encoding + preserving full URL bytes end to end.

Repro shape: `openLink: 'exp+focus-ai-app://expo-development-client/
?url=http%3A%2F%2Flocalhost%3A8081'` should auto-connect the dev

expo-dev-client 57.0.5 broke auto-connect.

Deliverable: unit test in smix-adapter-maestro asserting exact URL
bytes reach the invoked simctl argv, and an integration test using a
loopback `simctl openurl <UDID> file://...&param=value` observed via
its captured argv.

### D14 — app lifecycle primitive: `Session::relaunch_app()`

New SDK API across all four SDKs, additive to the v1.0.3 Session:

- Rust: `Session::relaunch_app(&mut self) -> Result<()>`
- TS: `session.relaunchApp(): Promise<void>`
- Swift: `session.relaunchApp() async throws`
- Kotlin: `session.relaunchApp()`

Semantics: `terminate() + launch()` on the session's cached
`XCUIApplication` binding in the SAME test-host process, preserving the
session id and the XCUITest binding. Wire: `POST /session/relaunch-app
{sessionId}` → `200 {ok}`.

Consumers wire this after observing an app crash (via C2 app-alive cache
transition or Session state change to `Dead` where the runner is
Healthy) to auto-recover without cycling the whole runner.

### D15 — safe exit cascade for `smix run`

`smix run` currently exits on ctrl-C by dropping the tokio runtime, which
drops open sessions and connections, but the runner-side session table
is only cleaned up when the runner's HTTP timeout fires (~60 s). If the
CLI is invoked in a wrapper (bash script, CI), the wrapper may see a
"session id in use" error on the next invocation.

Fix: install a `tokio::signal::ctrl_c()` handler in `smix run` that:
1. If a session is open, send `POST /session/close` (best-effort, 2 s
   timeout).
2. If a maestro-adapter flow is mid-step, log the last-attempted step
   before exit.
3. Print `interrupted after step N (Ns elapsed)` on stderr.
4. Exit 130 (POSIX SIGINT convention).

Symmetric handler for `SIGTERM` (kill / CI cancellation) — same
cascade, exit 143. No signal handler for `SIGKILL` (can't; runner-side
session dangles until the runner's own liveness reap fires).

Runner-side complement: the runner already handles idle sessions via a
120 s idle-close sweep, but v1.0.4 tightens this to 60 s so a
SIGKILL-orphaned session doesn't linger a full 2 minutes.
