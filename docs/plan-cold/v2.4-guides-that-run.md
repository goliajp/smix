# plan-cold/v2.4-guides-that-run.md — 指南里印出来的东西必须是能跑的

## 为什么要做

2026-07-22 一天之内撞到两次同型,**两次都不是闸门发现的,是真跑一次才知道的**:

- `docs/ai-guide/04-actions.md` 印着 `tapOn: {id: …, dispatch: daemonProxy}`,
  而 `require_plain_text_selector` 每次都拒 —— 那个 escape hatch 存在的理由正是 RN 的 `testID`,
  它偏偏用不了 `id`。**指南教了一条必然失败的 yaml。**
- `smix authoring suggest` 的帮助印着 `'Sign In'` 这种裸字符串,而裸形态只查 `text`/`value`/`title`。
  实测一棵真 Settings 树:`label` 33 个非空,`text` 与 `title` **各 0 个** ——
  **这个例子在 iOS 上结构性地永远返回空。**

已知还有三条同族**未修**:
`smix tap`/`find`/`describe` 等单点 verb 只认 `--port` 与 env,而 `05-cli.md` 写着
"flag → env → registry → default";`launchApp` 硬编码 `-n <pkg>/.MainActivity`,
对启动 Activity 不叫这个名字的应用(含所有 AOSP 应用)一律无效而指南未提;
yaml **触不到** `/tap-by-id`(路由被 `v2-modal-*` / `v2-tab-*` 命名空间挡着),
于是 Android 上 view-id 直取只有 SDK 调用方够得到。

**缺口是系统性的,不是零星 bug。** 三道现有文档闸门各守一层,没有一道守"示例能不能跑通":

| 闸门 | 守什么 | 那条 daemonProxy 示例 |
|---|---|---|
| `documented_flags_exist` | 指南里的 flag / 子命令**存在** | 通过 ✓ |
| `guide_yaml_parses` | 指南里的 yaml **解析得过** | 通过 ✓ |
| `hygiene-scan` | 死链、开发噪音 | 通过 ✓ |
| **执行会怎样** | **无人守** | **必然失败** |

v2.0.0 是第一个对外正式发布,而**用户第一次接触 smix 就是读这几份指南**。
这一族是发布时唯一会直接伤到新用户的缺陷类型。

## 已知风险

- **闸门可能只能覆盖一部分示例**。很多指南示例要真设备才能判"跑得通"。对策:闸门**明写它覆盖到哪一层**
  (与 `audit-ledger-scan` / `scope-promise-scan` 同一惯例:说不出自己不查什么的闸门会被读成全知),
  覆盖不到的靠人拆
- **判据可能被写成"能让现状过"的形状**。对策:**闸门必须先于修复**,并且建成时
  **当场抓出已知未修的那三条**(负对照),同时**对已修的两条通过**(正对照)。
  两向都对上才算闸门写对了 —— 这是 v2.3 反复验证有效的范式
- **修 `launchApp` 的 Activity 约定牵动 Android runner**,体量未知。对策:C1 产出的清单要带
  "修它要动哪几层",让后续 checkpoint 按体量排而不是按发现顺序
- **扫全指南会发现新的**,清单只会变长。对策:C1 只求"把这一族列全并给出状态",不在 C1 里修

## TDD 要点

C1 是闸门 + 清单,走红绿:先让闸门对着现状变红(点名已知三条),再让它对已修的两条绿。
C2 / C3 每修一条,对应的闸门断言从红转绿;**每条都要能在装回缺陷时重新变红**。

**贯穿全段**:凡"这条示例能跑"的判定,必须给出**它会走的那条代码路径**作为依据 ——
不接受"看起来对"。今天两条都是"看起来对"了很久。

## Checkpoint 概要列表

- C1:闸门 `scripts/dev/guide-executability-scan.py`(或等价形态)+ 全指南这一族的清单。
  闸门把指南里的示例喂给**它们真正会走的纯函数与约束**(选择器 guard、端口优先级链、
  verb→路由可达性),而不是只看它解析得过。建成时必须**抓出已知三条、放行已修两条**
- C2:CLI 层 —— 单点 verb 的端口优先级链与 `05-cli.md` 对齐(改实现还是改文档,C1 给依据后定)
- C3:yaml / verb 层 —— `launchApp` 的 Activity 约定、`/tap-by-id` 的 yaml 可达性
- C4:C1 清单里剩余各条逐条闭合,闸门覆盖到的全绿
