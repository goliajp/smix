# plan-cold/v2.6-shape-for-the-consumer.md — 按消费者塑形,承诺机制不承诺结果

## 为什么要做

`docs/scope-decisions-pending.md` 挂着的三项,拍板结果是**两做一撤**,但三项的重新设计
指向同一件事:**它们当初都是按「别的表面有这个名词」写进 in-scope 的,没问过消费者需要什么。**

- `--stable` 抄自一份 `🔬 explored` 的探索笔记
- `diagnostic-dump` 抄自 CLI 的动词名
- `session` 抄自 SDK 的概念

而三个表面的消费者完全不同:CLI 面向人 + Claude Code,SDK 面向写代码的人,
**MCP 面向一个上下文有限、拿到什么就信什么的外部 agent**。照搬名词就是把消费者搞错。

三项重设计的共同方向:**按消费者塑形,并且承诺机制而不是承诺结果** ——
结果验证不了,机制可以。这是前几段一直在拆的那类缺陷的正面版本。

## 已知风险

- **iOS 拿不到「动画关」,只拿得到 Reduce Motion**。XCUITest 跑在独立进程,
  `UIView.setAnimationsEnabled(false)` 够不到被测 app;`simctl spawn defaults write
  com.apple.UIKit UIAccessibilityReduceMotionEnabled` 是 smix 单方面能给的最强杠杆。
  对策:**分平台如实写**,Android = 三个 scale 归零(真关),iOS = Reduce Motion(减弱)。
  绝不笼统写「动画已关」—— 那就是新造一条承诺了结果的开关
- **改默认会动 `assertScreenshot` 的既有 baseline**。对策:这是破坏性变更,进表进 CHANGELOG;
  若确认有重度视觉回归用户,退回到「默认关 + 视觉回归 verb 自动开」的更细设计
- **`waitForAnimationToEnd` 在 iOS 上仍然有用**(Reduce Motion 不等于零时长),
  在 Android 上才近似空操作。对策:17 处文档改的时候分平台讲,不要写成「这个 verb 没用了」
- **`simctl ui appearance` 名义 per-sim 实际全局**(memory 有记录)。
  `simctl spawn <udid> defaults write` 是另一条机制,写进该 sim 的容器。
  对策:C1 必须**回读校验**,不靠推理

## TDD 要点

两个 checkpoint 都走红绿。C1 的绿必须包含**回读校验**:设完再读一次,读不到就报错,
不静默。C2 的红是「MCP 表面缺一个诊断工具 / session 错误不说恢复动作」。

## Checkpoint 概要列表

- C1:动画默认关(分平台如实),`--animations` 反向开关,回读校验,破坏性变更 #10 进表进 CHANGELOG,
  17 处文档分平台改写,`--stable` 这个名字废掉
- C2:MCP `smix_diagnose`(答案在前、raw dump 嵌在 `details`)+ 撤回 `session` 工具 +
  session 类错误必须点名恢复动作的契约与闸门
