### 系统性的发现:act 层没有返回类型

不是「tap 缺一个命中检查」。**整个 act 面返回 `Result<(), ExpectationFailure>` ——
成功即「没有报错」**。后果有三层,一层比一层难看:

1. `/tap-at-norm-coord`(**默认路径**)的响应是空信封 —— 从没问过那一点上是谁
2. `POST /tap`(只有 `dispatch:` 显式进入)**早就返回 `TapResult`**
   (`crates/smix-runner-wire/src/lib.rs:175`:matchedLabel / frame / appFrame / 分阶段耗时)——
   **能力存在于没人走的那条路由上**
3. 而 driver 拿到它之后,`crates/smix-driver/src/lib.rs:487` / `:521` / `:557` 三处
   `Ok(_result) => return Ok(())` —— **把已经在手里的信息扔掉**

所以 #4 修不成一个特例:它需要那个类型。

## 已知风险

- **命中判据误报会打断今天能跑的流**。缓解:`Unconfirmable` 不判失败;
  `SMIX_TAP_HIT_MISMATCH=warn` 给存量流过渡窗口;判据是纯函数、单测钉住、能装回缺陷验红
- **v2.6-C1 的动画默认压低正好降低这个风险** —— 元素在取树与点击之间移动的窗口变小了
- **4 个 SDK 的签名改动体量大**。缓解:`sdk_failure_code_parity` 与 `route-conformance`
  两道既有闸门会把漏改的地方顶出来
- **私有 API 依赖加深**(`XCPointerEventPath` 的 offset 时间线)。它已经是 swipe 的基础,
  不是新引入的依赖;但 C2 要在 docstring 写明 Apple 改了它会怎样
- **#3 的 428ms 是他们测的,不是我们测的**。C2 起手先自己量一次
