# plan-cold/v2.10-cross-platform-recorder.md — 一个 IR，三平台录制:iOS · Android · web

## 为什么要做

录制现在只有一条腿：iOS。`swift-bridge` 的 `EventRecorder` 捕获原生事件 →
`RecordedEvent`（wire）→ `/record/*` → `smix-authoring-ir::IRAction` →
`smix-recorder` 的 generator（maestro YAML / Rust）。**IR + generator 是平台无关
stone/steel，已就位**；缺的是另外两条采集腿：Android（UIAutomator）与 web
（Playwright bridge）。不做，「录一遍生成 flow」只对 iOS 成立，四生态承诺（v8 SDK
四生态 LIVE）在 authoring 面是空的。这是折入 v2 的 in-scope item 13（authoring/编排
的第一件）。**§9#1**：web 轴是 **Playwright bridge**（driver 层录 web 交互），**不是
物理设备**，不破真机永不做。

## 入口条件

```bash
git log --oneline | grep -q 'v2.9 napi phase complete'     # v2.9 闭合
grep -q 'pub enum IRAction' crates/smix-authoring-ir/src/lib.rs  # 平台无关 IR stone 在
grep -q 'generate_maestro_yaml' crates/smix-recorder/src/generator_maestro_yaml.rs  # generator 在
grep -q 'EventRecorder' swift-bridge/SmixRunnerUITests/EventRecorder.swift  # iOS 采集腿在（参照实现）
grep -rq 'RecordHandlers\|/record/start' swift-bridge/Sources/SmixRunnerCore/  # iOS /record wire 在
node --version                                              # web 轴 Playwright 宿主
```

## 资源依赖

- **平台无关地基（已有，复用不重造）**：`smix-authoring-ir::IRAction`（Tap/Fill/Clear/…）
  + `smix-recorder`（RecordSession + maestro/rust generator）+ `/record/*` wire 契约。
- **Android**：UIAutomator/AccessibilityService 的事件采集面（对等 iOS `EventRecorder`
  的原生事件流）；android-runner 已有 instrumentation runner（v2.8-C6 基础）。
- **web**：Playwright（Node），录 web 交互 → IRAction；smix-node/bun workspace 已建
  （v2.9-C4），web 腿可挂这条 Node 侧。
- 外部文档：UIAutomator event / AccessibilityEvent API；Playwright codegen/tracing API。

## 已知风险

- **Android 事件采集能力未知**：UIAutomator 是否像 iOS `EventRecorder` 那样能捕获
  tap/input 事件流？对策 = C1 起手先**调研 Android 采集面**（AccessibilityService 事件
  vs UIAutomator watcher vs instrumentation hook），拿不到对等能力则诚实 re-tier（决策
  日志），不硬凑。
- **三平台 → 一 IR 的语义对齐**：iOS 的 RecordedEvent、Android event、Playwright action
  各自表达力不同；映射到同一 `IRAction` 会有平台特有动作落不进 IR。对策 = IR 以「最小
  可移植动作集」为准，平台特有的记为 gap 单列，不扩 IR 迁就单平台。
- **web 是 driver-bridge 非设备**（§9#1 守）：Playwright 录的是浏览器交互，桥成 IRAction；
  不引入任何物理设备/真机路径。
- **§9 不变量**：录制不得埋 sense/act 能力进 driver（§9#8 三层）；采集腿是 sense 的一种，
  落 core/runner 平铺，generator 是 steel。

## TDD 要点

- IR + generator 已有纯逻辑单测（stone/steel）；新采集腿各自：平台事件 → IRAction 的
  纯映射单测（fixture 事件流 → 期望 IRAction[]，无设备）+ 设备 e2e（真录一段 → 生成 →
  可 replay）。跨平台 parity：同一操作在三平台录出**等价 IRAction**（generator 输出对齐）。

## Checkpoint 概要列表

- C1：Android 采集腿 —— 调研 Android 事件采集能力（拿不到诚实 re-tier），UIAutomator/
  AccessibilityService 事件 → `IRAction`，纯映射单测绿。
- C2：Android 录制 wire + 设备 e2e —— android-runner 补 `/record/*` 对等路由，真 emulator
  录一段 → generator 出 maestro/rust，replay 绿。
- C3：web Playwright bridge —— Playwright 录 web 交互 → `IRAction`（挂 Node/bun workspace），
  纯映射单测 + 一段真 web 录制 → 生成绿。
- C4：三平台 parity 闭合 —— 同一操作 iOS/Android/web 录出等价 IRAction；一条「record → generate
  → replay」跨平台机械 gate；authoring 面四生态录制承诺兑现。

## 出口验收

三平台各能 record → `IRAction` → generator（maestro/rust）→ replay 绿；跨平台同操作
IRAction 等价（parity gate）；`smix record` 面覆盖 iOS/Android/web；§9#1 web=Playwright
bridge 非真机、§9#8 三层不破。零 publish（顺延）。
