# plan-cold/v2.12-federation.md — N 机 N runner 的分布式 run federation,结果合并进 CI

## 为什么要做

单机 `smix run --parallel N`(v2.8-C4)把 flow 分片到本机 M 台 sim,吞吐上限 = 一台机器能同时
开几台 sim/emulator。v2.12 把同一编排推广到跨机:中央 scheduler 把 flow 分片到 N 台机器的 smix
(各跑**自己的 sim/emulator**,§9#1 不碰真机),结果合并为单一 CI 报告 + 单一聚合退出码
(roadmap「Distributed run federation」)。不做,CI 规模化只剩「买更大的单机」。这是折入 v2 的
**最后一个** minor;v2.12 出口 = v2.8–v2.12 折入阶段全完成。

## 已知风险

- **scheduler 形未决**(CLI 编排推广 `--parallel` / 常驻 daemon / 脚本层 SSH 扇出):选错废多
  commit。对策 = **C1 研究先行**,枚举候选逐个判,verdict 定形后才动手。
- **远端二进制/源新鲜度**:v2.8-C4 e2e 实证 stale binary(mini 陈旧二进制 EXIT=2)。对策 =
  节点准备度做**显式机器 gate**(诚实形 C1 定),不隐式假设远端是新的。
- **registry 严格 per-machine**:resolution 只读本机 registry 文件、从不查活 sim 集(确定性寻址
  不变量)。跨机设备清单不得偷改此语义;中央清单 vs 引用远端 alias 的取舍归 C1。
- **SSH 网络抖动**:v2.8-C4 过程实证(连上几秒即断、detached 进程被杀)。对策 = C1 把「退出码/
  stdout 经 SSH 无损回传」列为轴内判据,抖动应对策略据证据定,不臆造重试层。
- **flow 文件与 artifact 都在两端盘上**:分发(scheduler→节点)与回收(节点→scheduler)机制
  都不存在。对策 = C1 定诚实形(rsync/scp/stdin 候选),C3/C4 分头机械 gate。

## TDD 要点

C1 = read-only 研究,产 verdict 文档(rubric 先于证据,同 v2.10-C1 / v2.11-C1 范式)。C2+ 各腿:
调度核心(节点×flow 分配、聚合)= 纯逻辑单测,无网络无设备(同 `parallel.rs` 被单测钉死的先例);
远程执行腿 = 传输层对 stub 单测 + 真 mini e2e 分层;合并报告 = fixture 单测(N 份真 shape 的
run-summary → merged schema)+ 双节点 e2e。e2e 全程显式 UDID + 用完回收(sim-guard / sweep 纪律)。

- C1:**研究先行** — 跨机 federation 回路可得性 + 诚实形(节点契约 / 调度形 / 跨机设备清单 /
