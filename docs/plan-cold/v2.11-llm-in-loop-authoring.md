# plan-cold/v2.11-llm-in-loop-authoring.md — smix runtime 观察 flow 执行 → 本机 claude 提议改进

## 为什么要做

录制（v2.10）能把交互变 flow，但 flow **写完后不会自己变好**：失败步的 selector 漂了、
缺 `waitFor`、断言写脆了，只能人肉改。v2.11 让 smix runtime **观察一次 flow 执行的结构化
记录**（`--debug-output` bundle + 失败时的 `ExpectationFailure`）→ 经**本机 `claude` CLI**
产出**可机械校验的改进提议**（改 selector / 插 waitFor / 调断言 …）→ 机械验证提议有效。
不做，authoring 面只有「录一遍」没有「改一版」，flow 维护仍是纯人力。这是折入 v2 的
authoring/编排第二件（roadmap「LLM-in-the-loop authoring」）。**§9#2**:走**本机 `claude`
CLI**（单 provider、无网络 key 管理），复用 v2.0 已落的 `smix-ai-tier` fenced 范式。

## 已知风险

- **§9#2 网络路径决策点（留给用户拍板,本冷计划不偷改不变量）**:roadmap 原文
  「backed by the Claude API」的**网络 API 路径**属独立 §9#2 修订 —— **本冷计划全部默认本机
  `claude` CLI,不把网络路径写进 scope**;是否放开直连 Claude API 由用户单独决定,进决策日志。
- **proposal 形未定**:selector swap / waitFor 插入 / step reorder / 断言改 / verb 改 —— 具体
  产什么结构未知。对策 = **C1 研究先行**定诚实形（拿不到就 re-tier,不臆造 schema）。
- **验证无人读图未定**:well-formedness（device-free:proposal 反解为合法 flow,parser 接受）
  vs effectiveness（device replay:amended flow 从 fail→pass）。对策 = C1 定分层策,C3/C4 分头机械 gate。
- **非确定性**:LLM proposal 不可复现 → 同 ai-tier fenced 定位（deletable test / opt-in /
  标 non-deterministic）,**不进 resolver/sense 路径**（§9#8 三层:这是 authoring aid,非 sense/act core）。
- **别造虚构 wire**（v2.9-C5 教训）:propose 只消费**真** `--debug-output` 产物 + **真** claude CLI,不新造 route。

## TDD 要点

C1 = read-only 研究,产 verdict 文档（rubric 先于证据,同 v2.8-C7 / v2.10-C1 范式）。C2+ 各腿:
proposal 生成走 fixture bundle → 结构化 proposal 的**纯逻辑单测**（无 claude,mock 回复）+ claude
调用单测（对 stub 二进制,不真调 API）;良构 gate = proposal → 合法 Step/Selector 的反解单测;有效性
= 真 sim/emulator「fail flow → propose → apply → re-run → pass」e2e。ai-tier 同源 deletability test 守 fence。

## Checkpoint 概要列表

- C1:**研究先行** — observation→local-claude→actionable-proposal 回路可得性 + 诚实形,产
  `docs/research/c1-llm-authoring-loop.md`（三轴 rubric + 证据 + `VERDICT`）。verdict 出后 C2+ 据其热化或 re-tier。
- C2:proposal schema + 生成核心（device-free）— `--debug-output` bundle → local claude → 结构化
  machine-checkable proposal,fixture bundle → proposal 纯逻辑单测 + claude 调用范式单测。
- C3:proposal 良构 gate（device-free）— proposal 反解为合法 flow 编辑（落合法 Step / Selector,parser 接受）,well-formedness 单测绿。
- C4:proposal 有效性 e2e（device replay）— fail flow → propose → apply → 重跑 amended flow → fail→pass,真 sim/emulator。
- C5:fenced 归位 + CLI/四生态闭合 — `smix authoring propose` 挂 CLI,ai-tier 同源防火墙（deletable / opt-in / non-deterministic）,出口 e2e。

> C2–C5 是 C1 verdict = OBTAINABLE / PARTIAL 时的**预期建造路径**;若 C1 = NOT-OBTAINABLE 或 PARTIAL 缩了改进类,据 verdict re-tier 概要列表并进 `docs/v2.md` 决策日志,不硬凑。
