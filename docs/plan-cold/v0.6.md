# plan-cold/v0.6 — MCP Server（含 explain_screen via claude CLI）

## 为什么要做
v0.5 后人 / AI 可通过 CLI 用 simx，但 AI 接入的"一等公民"路径——MCP——还没有。v0.6 把 v0 设计文档里 18 个 tool 全部实现，含核心差异化 `screen_describe`（AI 的眼睛）和 `explain_screen`（VLM 兜底）。`explain_screen` 走本机 `claude` CLI，复用 Claude Code 订阅，无 API key 管理。

## 入口条件
```bash
test -f docs/plan-history/v0.5-c6-hot.md
which claude && claude --version          # 期望：claude CLI 在 PATH
claude -p "hello" --output-format text | head -1  # 期望：能拿到响应（已登录）
```

## 资源依赖
- 环境：与 v0.5 同
- MCP SDK：`@modelcontextprotocol/sdk`（npm 上的官方 TS SDK）
- 协议参考：[Model Context Protocol spec](https://modelcontextprotocol.io/)
- Claude CLI：本机已安装 + 已登录
- 人 / agent：主对话

## 已知风险
- **MCP SDK 升级 break**：pin 版本，定期 review
- **`claude` 子进程冷启动 ~500ms-1s**：`explain_screen` 不是高频路径可接受；但要给 timeout 30s 兜底
- **`claude -p --image` 参数稳定性**：如果 cli 改了 flag 名，simx 要能给清晰错误。读 `claude --help` 探测可用 flag 一次
- **stdio MCP 与日志冲突**：stdio 通道不能写 log 到 stdout（会破坏 JSON-RPC）。日志一律到 stderr

## TDD 要点
- Tool handler 全 TS 单测：mock driver，断言每个 tool 的 args/result schema
- MCP 协议层：用官方 SDK 自带的 test harness 跑 initialize / tools/list / tools/call
- `explain_screen` 单测：mock `spawn('claude', ...)`，断言参数 + 错误处理
- 端到端：起 `simx mcp`，用一个 MCP 客户端（写一个小 node 脚本）跑完整流程

## Checkpoint 概要列表
- **C1** MCP 协议层（stdio JSON-RPC，initialize / tools/list / tools/call）跑通
- **C2** 4 个 simulator/app 生命周期 tool（simulator_list/boot/shutdown, app_launch/terminate/install/uninstall）
- **C3** 4 个观察 tool（screen_describe, screen_screenshot, screen_hierarchy, element_inspect）
- **C4** 7 个交互 tool（tap, double_tap, long_press, fill, swipe, scroll_to, key_press）+ 默认返回新屏幕 summary
- **C5** 3 个复合 tool（find_and_tap, wait_for, flow_run）+ 3 个系统 tool（open_url, pasteboard_set/get, permissions_grant）
  > **C5 落地修正**（v0.6 C5 close 2026-05-16）：cold plan slash 表达"3 + 3"实际落地 **3 复合 + 4 系统 = 7 tool**：`pasteboard_set` / `pasteboard_get` 字面拆 2 tool（决策 1.A——单一职责、MCP 表面更扁，拒 1 tool `{mode:'set'|'get'}` 复合形态）；`permissions_grant` MCP wire 是单 `permission` enum 非数组（决策 7.A——driver `grantPermission(permission, bundleId?)` 签名字面镜像；多权限走 `flow_run` 链或多次 call）；`bundleId` 强制 required，不 fallback driver `lastLaunchedBundleId`（决策 7.C 字面——MCP 表面 stateless）；`Permission` zod enum 12 字面镜像 `src/driver/types.ts` line 16-28（决策 7.B）。
- **C6** `explain_screen` 走 `claude -p ... --image ...` 子进程；含 timeout / 未安装错误
- **C7** ScreenDescription / SerializedFailure 序列化 schema 固化（MCP tool 与 SDK 共用）
- **C8** 端到端：写一个 MCP 客户端脚本（或用 Claude Code），跑 `examples/login.test.ts` 等价流程，全部通过
