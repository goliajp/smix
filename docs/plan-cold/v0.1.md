# plan-cold/v0.1 — simctl wrapper 通电

## 为什么要做
v0 是 types-only，调任何 SDK 方法都抛 `DRIVER_ERROR`。v0.1 让最简单的端到端（`launch → screenshot → terminate`）真跑通，建立 driver / CLI / 测试三条技术线的最小可用形态。后续阶段都在这基座上加。

## 入口条件
```bash
xcodebuild -version | head -1            # 期望：Xcode 26.x
xcrun simctl list runtimes -j | jq '.runtimes | length'  # 期望：≥1
bun -v                                   # 期望：1.1.0+
test -f tsconfig.json && test -f src/sdk/index.ts        # 期望：v0 骨架在
```

## 资源依赖
- 环境：macOS 15+、Xcode 26+、iOS runtime 至少 1 个（17.5 / 18.x / 26.x 任一）
- 工具：node 20+、`xcrun simctl`
- 外部 API / 文档：[simctl manpage](https://www.iosdev.recipes/simctl/)、`xcrun simctl help`
- 人 / agent：无特殊，主对话即可

## 已知风险
- **simctl 输出 schema 偶发变动**：用 `simctl list -j` JSON 而非文本解析；解析失败时报清晰错误带原始输出片段
- **boot 是异步**：`simctl boot` 返回后实际 boot 未必完成；用 `simctl bootstatus -b` 轮询
- **CI 上 simctl 慢**：单测全 mock 子进程；集成测试标 `@integration`，本机跑

## TDD 要点
- 单测全 mock `node:child_process`，依赖注入 `runSimctl(args)` 函数
- 集成测试目录 `src/sim/__tests__/integration/`，开 vitest tag `@integration`
- 自家 SDK runner (`src/sdk/test.ts`) 不在 v0.1 自测路径上；examples/ 通过 CLI 跑作 e2e

## Checkpoint 概要列表
- **C1** vitest 基础设施 + 一个 sanity test 跑过（exit 0）
- **C2** `simctl list runtimes/devices` 包装 + 单测全过
- **C3** `simctl boot/shutdown/install/launch/terminate/screenshot/openUrl/pasteboard/permissions/appearance` 包装 + 单测全过
- **C4** `SimSession` 抽象（acquire/release/auto-boot）+ 单测全过
- **C5** `SimctlDriver` 实现 Driver 接口可做的方法；不能做的显式抛 `DRIVER_ERROR with hint`
- **C6** CLI 雏形 `simx list` / `simx run`；`examples/screenshot-only.test.ts` 端到端跑通
- **C7** `simx doctor` 极简版（探测 Xcode、可用 runtime、claude CLI 占位）

## 出口验收
```bash
bun run typecheck                                            # exit 0
bun run test                                                 # exit 0，全部 pass
bun src/cli/index.ts list | head -3                      # 列出真实 device
bun src/cli/index.ts run examples/screenshot-only.test.ts # exit 0
ls .simx/trace/screenshot-only/0001-screenshot.png           # 文件存在 且 size > 1000
```
