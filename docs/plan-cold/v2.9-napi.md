# plan-cold/v2.9-napi.md — TS SDK 经 napi 真驱动，闭合四 SDK parity

## 为什么要做

四个 SDK 里 TS 是唯一不能驱动的：`npm/smix-rn/src/App.ts` 的 13 个驱动方法全部
`throw SmixNotImplementedError('napi', …)`（tap/fill/pressKey/swipe/screenshot/
tapAtCoord/terminate/relaunch/launchFresh/snapshotTree/systemPopups/openUrl）。v2 的
「一份 wire client 经 FFI」架构里，Swift/Kotlin 已经过 `smix-ffi`（UniFFI）到达 Rust；
TS 还差一根 N-API 桥。不做，四 SDK parity 不闭合，TS 消费者只有类型 + Selector +
resolver seam，没有 live driving/sense。这是折入 v2 的 in-scope item 12。

## 入口条件

```bash
git log --oneline | grep -q 'v2.8 phase (C1-C8) complete'    # v2.8 折入阶段闭合
python3 scripts/dev/route-conformance.py                     # rc=0：零 unserved 路由（parity 基线）
grep -q 'SmixNotImplementedError' npm/smix-rn/src/App.ts      # 13 桩仍在（本阶段要退的对象）
grep -c 'pub fn resolve_selector' crates/smix-ffi/src/lib.rs  # 现 FFI 只暴露 resolver stone（driving 未暴露）
node --version                                                # Node LTS 在（napi 宿主）
```

## 资源依赖

- **napi-rs**（`@napi-rs/cli` + `napi` crate）：Rust→N-API 的正统绑定 + prebuild 工具链。
- **跨 triple `.node` 构建宿主**：mini/studio = darwin-arm64（见 [[build_hosts_mini_lx64]]），
  lx64 = linux-x64；darwin-x64 经 cross/CI；win32-x64 默认 **out-of-scope**（RN/Expo 开发面
  以 mac/linux 为主，热化 C1 前若要纳入需显式扩边界）。
- **现成 FFI 边界**：`smix-ffi`（UniFFI 0.29，`crate-type=["staticlib","cdylib","rlib"]`），
  当前只 wrap `smix-selector-resolver + smix-screen`（stone）。驱动 wire client 在
  `smix-runner-client`（tokio-async）。
- 外部文档：napi-rs prebuild/CI matrix、N-API 版本矩阵。

## 已知风险

- **FFI 现只暴露 resolver stone，不暴露 driving**：napi 层要把驱动面（`smix-runner-client`
  的 wire 方法）经边界暴露给 Node —— 比「加语言绑定」大。对策：先决定架构（napi 直绑
  `smix-runner-client` 的新 `smix-node` crate，vs 扩 `smix-ffi` UniFFI 面）——**这是 C1 前的
  架构决策，进决策日志，不在冷计划拍死**。
- **async 桥**：wire client 是 tokio-async，N-API 要 async 化（napi-rs `#[napi] async fn` +
  tokio runtime 寄宿）。对策：napi-rs 的 tokio 集成，C1 单方法端到端先验。
- **不能破坏现有 UniFFI Swift/Kotlin 消费者**：动 smix-ffi 面要 semver 谨慎。对策：若走新
  `smix-node` crate 则零触碰 UniFFI 面（首选正统，隔离）。
- **跨 triple prebuild + CI matrix**：prebuild 分发 `.node` 二进制（napi-rs `npm/` 目录范式）。
  对策：先 darwin-arm64 单 triple 端到端（C1），矩阵 later（C4）。
- **§9#6 私有符号不变量不涉**：napi 绑的是 smix 自家 Rust wire client，非 Apple 私有符号。

## TDD 要点

  退桩后 TS 的驱动路由必须真的有 runner 服务，rc 保持 0。
- 出口设备 e2e：TS 驱动一条真 flow（对真 sim），与 Swift/Kotlin driving parity。
