# plan-cold/v2.8-faster-and-wider.md — 折入 v2:runtime 更快、覆盖更广、退化被 CI 抓住

## 为什么要做

这是 2026-07-23「roadmap 全量折入 v2」后的第一个折入阶段(决策见 `docs/v2.md` 决策日志)。
v2.0.0 pre-fold 把能力面做齐了,但没为**速度、规模、退化检测**优化过:
`runner cycle` 每次 spawn 一个 `xcodebuild`(~3s 热 / ~15s 冷)、截图管线未 hoist、
单 sim 单流是唯一形态、perf 只有一次性 gate 没有回归线。本阶段把「能做」变成
「做得快、做得多、退化了 CI 会挂」。**全程 additive-wire + additive-ABI**——
任何会破坏 pre-fold v2.0 面的都是 bug,`cargo-semver-checks` 每 checkpoint 守。

## TDD 要点

- **测量 checkpoint(C1)**:红 = 一条断言「同一 flow 两次跑的耗时差被 `smix bench` 检出且超阈值判失败」;绿 = corpus + baseline + 5% 判据落地,自身有单测钉 baseline 比对逻辑。
- **perf checkpoint(C2/C3)**:红 = bench 断言当前 raw time vs 参考目标的 gap;绿 = decomposition + attack 后 bench 累计过 variance band。**先 decomposition(read-only)后 attack(worktree),两 phase 不跳跃**。
- **能力 checkpoint(C4–C8)**:红 = 新形态失败测试(mock 优先,设备核实进决策日志不进 gate);绿 = 最小实现 + `cargo-semver-checks` 确认 additive。
- 每个 checkpoint 过既有全部 gate(route-conformance / workflow-scan / tarball 新鲜度 / fence-check / …)。

## Checkpoint 概要列表

- C1:bench 回归检测 —— `smix bench` 跑 perf-gate corpus 对比上次 committed 基线,超 5% CI 判失败。**先做,它是 C2/C3 的测量前置**。
- C2:进程内 runner cycle —— 同 test-host 内 bounce FlyingFox + rebind XCUIApplication,免 `xcodebuild` spawn,目标 ~500ms(decomposition-first)。
- C3:截图管线 hoist —— sRGB splice + 自适应 pacer 下沉,`simctl io screenshot` p95 < 100ms(decomposition-first)。
- C4:多 sim 编排 —— `smix run --parallel N` 分片 N 流到 M 台 sim,各自 runner+supervisor,N=1 保持现契约。
- C5:real-sim 压测台 —— 20 流 bootstrap corpus 夜间 CI 跑 sim-smoke,取代 ad-hoc smoke 为分级 stress+smoke。
- C6:Android 运行时 parity —— UiAutomator 补 iOS-specific 的 rate-limit pacer + app-alive cache。
- C7:遮挡感知命中判定 —— 先调研 z 序可得性,回答 EXT1 #4 defer 的问题,拿得到才做,拿不到诚实 re-tier。
- C8:面向 AI 的文档 —— `docs/ai-guide/authoring.md`(从 LLM 写 Locator 流)+ SessionState → 消费者响应 playbook。
