# plan-cold/v2.1.md — 让已发布的 v2.0 表面更快、更广,一个字节都不破坏

## 为什么要做

v2.0.0 是第一个对外正式版,把能力面做齐了,但**没为规模和速度优化过**:
`runner cycle` 每次重启一个 `xcodebuild`(~3s 热 / ~15s 冷)、截图管线未 hoist、
单 sim 单流是唯一形态、perf 只有一次性 gate 没有回归检测。v2.1 是发布后第一个 minor:
**纯 additive-wire + additive-ABI**(任何会破坏 v2.0.x 消费者的都滑到 v3),
把「能做」变成「做得快、做得多、退化了会被 CI 抓住」。

## 入口条件

```bash
cargo search smix-cli | head -1          # 期望:2.0.0 已发布(v2.0 cycle 闭合)
git tag -l 'swift-v2.0.0'                # 期望:有
grep '^version' Cargo.toml | head -1     # 发布后应已 bump 到 2.1.0-dev 或仍 2.0.0 待 bump
```

- v2.0.0 必须**已发布四生态**(crates.io + npm + Maven + swift tag)—— v2.1 是它的增量,
  不是它的补丁。未发布则先闭 v2 的 C14。

## 资源依赖

- 环境:Xcode + iOS 26.5 runtime、Android SDK + emulator(C6 parity)、
  多台 booted sim(C3 multi-sim,注意 sim-guard 显式 UDID 纪律)。
- 设备核实走 **mini**(与 studio 同构,memory `build_hosts_mini_lx64`),不占 studio。
- perf checkpoint(C1/C2)需要能看 5μs 级 delta 的 bench infra —— n≥1000、多 run、CPU pin。
- 工具:`cargo-semver-checks`(每 checkpoint 验 additive)、samply/perf(C1/C2 decomposition)。

## 已知风险

- **C1/C2 是 perf,必然诱发「polish 到天花板」自欺**:对策 = 强制走
  `~/.claude-shared/global/methodology/perf-decomposition-vs-polish.md`——
  连续 2 轮 polish 没动针即停,做 decomposition(拆 18+ stage 对照参考实现),不 declare ceiling。
- **additive 破功**:任何 checkpoint 手滑改了 v2.0 wire/ABI 语义即 major break。
  对策 = `cargo-semver-checks` 每 checkpoint 跑,红即回退;wire 只加 route/字段不改旧的。
- **C3 multi-sim 抢设备**:N 个 runner + supervisor 对占 N 台 sim,与 in-house batch 冲突。
  对策 = C3 e2e 让位活动 batch(`pgrep -fl "runner.ts|smix run|supervise"`),先做纯逻辑 + 单元。
- **C7 遮挡检测是 v2.0 明确 defer 过的**(EXT1 #4:snapshot 无 z 序,isHittable 刻意拒过两次)。
  对策 = 先回答「z 序到底拿不拿得到」这个纯调研问题,拿不到就诚实 re-tier,不硬塞 isHittable。

## TDD 要点

- perf checkpoint(C1/C2):红 = 一条 bench 断言当前 raw time vs 参考目标的 gap;
  绿 = decomposition + attack 后 bench 累计过 variance band。**先 decomposition 后 attack,两 phase 不跳跃**。
- 能力 checkpoint(C3-C7):红 = 新形态的失败测试(mock 优先,设备核实进决策日志不进 gate);
  绿 = 最小实现 + `cargo-semver-checks` 确认 additive。
- 每个 checkpoint 都要过既有全部 gate(route-conformance / workflow-scan / tarball 新鲜度 / …)。

## Checkpoint 概要列表

- C1:进程内 runner cycle —— 不再 spawn `xcodebuild`,同 test-host 内 bounce FlyingFox + rebind XCUIApplication,目标 ~500ms(decomposition-first)。
- C2:截图管线 hoist —— sRGB splice + 自适应 pacer 下沉,`simctl io screenshot` p95 < 100ms(decomposition-first)。
- C3:多 sim 编排 —— `smix run --parallel N` 把 N 流分片到 M 台 sim,各自 runner+supervisor,N=1 保持现契约。
- C4:bench 回归检测 —— `smix bench` 跑 perf-gate corpus 对比上次基线,超 5% CI 判失败。
- C5:real-sim 压测台 —— 20 流 bootstrap corpus 夜间 CI 跑 sim-smoke,取代 ad-hoc smoke 为分级 stress+smoke。
- C6:Android 运行时 parity —— UiAutomator 补 iOS-specific 的 rate-limit pacer + app-alive cache(sense/act 契约可移植)。
- C7:遮挡感知的命中判定 —— 先调研 z 序可得性,回答 EXT1 #4 defer 的那个问题,拿得到才做,拿不到诚实 re-tier。
- C8:面向 AI 的文档 —— `docs/ai-guide/authoring.md`(从 LLM 写 Locator 流)+ SessionState → 消费者响应 playbook。

## 出口验收

所有 Cn 通过 + `cargo-semver-checks` 确认整个 v2.1 相对 v2.0 是 minor(无 break)+
e2e smoke:一条流在 `--parallel 2` 下跑两台 sim 各自过,cycle 用进程内路径实测 < 1s。
四生态同窗发布 v2.1.0。

标准模板见 CLAUDE.md §6。本版本特殊 context 追加:
