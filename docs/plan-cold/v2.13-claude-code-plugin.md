# plan-cold/v2.13-claude-code-plugin.md — 两个闭环：smix 独立可用，smix + Claude Code 顺手

## 为什么要做

两件事各自没闭：

**独立闭环**没闭在开场。拿到二进制只有 `cargo install smix-cli --locked` 一条路 —— 27 个 crate
现编，还要求一个 app 开发者机器上有 Rust。之后从零到能驱动要 5 步、要自己找 UDID、要知道 bundle id、
要先写一个 flow 文件。`doctor` 只数设备，不告诉人下一步该干什么。

**协同闭环**根本没有。`smix-mcp` 一个进程绑一台设备，绑定发生在 MCP client 启动时
（`main.rs:560-575` 读 `SMIX_UDID`）——会话中途换设备不可能，首次调用必撞「runner 没起」。
面向消费方的 plugin / skill / hook 资产为零。**真正的 AI runner 是 Claude Code**，
人是在那个会话里开发 app 的。

## 贯穿两个闭环的不变量（新增，进 §9）

**plugin 不得拥有 smix 独立时没有的能力。** 它加的是主动性（什么时候做、替谁记着），不是能力。
卸掉 plugin，用户失去的是顺手，不是本事。这是 §12.1「不把能力埋进 driver」换了个消费方
—— plugin 同样不许成为能力藏身处。每条 skill 教的动词，人在终端里都能原样敲。

## 入口条件

- v2.0.0 已发布并复核（crates.io 27 / npm 5 / Maven Central / Swift tag，2026-07-25）
- CI 已有跨 triple 原生构建矩阵（`napi-prebuild`，3 个 triple）—— CLI 二进制沿用同一套机器
- `smix sim install` / `capsule up` / `authoring generate` 等独立闭环所需动词均已存在（已核）
- 面向消费方的 plugin 资产为零（find 核实）

## 资源依赖

- Claude Code（`claude plugin validate` / `--plugin-dir` / `/reload-plugins`）
- 规格真源：`code.claude.com/docs/en/plugins` + `/plugins-reference`（已取）
- 设备：`sim-smix-*` + emulator-5554；物理机在场，护栏必须成立
- **一个 smix 仓之外的 app 仓**做两个闭环的出口验收；npm / Homebrew tap 的发布位

## 已知风险

- **分发是这件事最大的门槛，也最容易被当成杂活**。对策：C1 就做，不放到最后。
- **两个闭环会长出两套实现**。对策：上面那条不变量 + C7 出口 e2e 逐条比对「skill 教的动词 == 人能敲的动词」。
- **plugin 与 smix 二进制各自演进 → 版本错配**。对策：SessionStart 读 `smix --version` 对表，不匹配时给可执行话术。
- **`.mcp.json` 只能给 `command`**：`smix-mcp` 不在 PATH 时用户看到的是空 tool 列表。对策：同上 hook 先探测。
- **hook 装在用户机器上，误伤面远大于仓内自用**。对策：只拦有歧义 / 全局 / 命名寻址，拒绝话术必须给出 smix 等价物。
- **skill 里的例子会腐烂**。对策：接既有 guide-executability 闸门。

## TDD 要点

分发与 `init` 的**纯逻辑**（平台判定、注册表写入、下一步话术）走单元测试；取二进制与设备走 e2e。
hook 按「命令行 → 放行 / 阻断」表驱动，device-free。plugin 结构由 `claude plugin validate` 判。
两个闭环各自的出口 e2e 都必须机器判据，且**独立闭环那条不许出现任何 Claude Code**，
**协同闭环那条不许手工 `capsule up` 兜底**。

## Checkpoint 概要列表

- C1：分发 —— 预构建 CLI 二进制（npm + Homebrew tap + GitHub Release），`cargo install` 降为其中一条而非唯一
- C2：开场 —— `smix init`（选设备 / 写注册表 / 记住 app）+ `doctor` 从「数设备」变成「说下一步」
- C3：**独立闭环出口 e2e** —— 装 → init → 装 app → capsule up → 驱动 → 录制成 flow → 跑 → 收摊，全程无 Claude Code
- C4：smix-mcp 会话内设备绑定 —— `smix_devices` / `smix_use` / `smix_release`，env 降为默认值
- C5：plugin 骨架 + `.mcp.json` + marketplace + SessionStart 就绪 hook（探测 smix 在不在、版本对不对）
- C6：护栏 hook —— iOS sim-guard 移植 + Android 序列号护栏，拒绝话术给出 smix 等价物
- C7：skill 三件（drive / author / diagnose）+ 示例进 guide 闸门 + monitor（app 死了是事件）
- C8：**协同闭环出口 e2e** —— 独立 app 仓里只经 plugin 走完全程；并逐条核对不变量（plugin 无独占能力）
- C9：§9#2 改写落地 —— `ask` 签名显式带附件，判定层不再靠 `--tools Read` 读本地文件；默认满足方仍是本机 `claude`

## 出口验收

两条都过：**独立** —— 一台只有 Xcode 和一个 .app 的机器，不碰 Rust、不开 Claude Code，
按 README 走到能驱动并生成一个可重跑的 flow。**协同** —— 一个 app 仓里装上 plugin，
不手工起任何 smix 进程，完成选设备 → 起 runner → 启动 → 感知 → 操作 → 失败诊断 → 录制 → 收摊。
